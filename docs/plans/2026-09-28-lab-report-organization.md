# 检验报告整理与来源关联实施计划

> 执行方式：功能 worktree 内逐项实施；每项先写失败测试，再完成最小实现和回归。

当前状态：步骤 1～5 已完成。独立审查提出的整份确认范围、报告详情、过期提交和冲突提示问题已用失败测试复现并修复。本地 `submit` 完整门禁通过，[PR #121](https://github.com/skuyd/emr/pull/121) 已 Squash 合并，源代码随 [v2.3.0](../releases/v2.3.0.md) 发布；证据见[验证记录](../verification/lab-report-organization.md)。

**目标：** 在健康档案的检验报告详情提供独立的“整理报告”入口，完整展示和调整同患者现有报告单元的来源关系。

**架构：** 继续使用 `LabReportUnit`、`ReportAssociation` 和现有关系事件。读取层按报告单元计算与对比、输出相同的完整互认分组；写入层在患者锁内校验双方当前版本、关系快照和权限，一次只改变选定关系。页面只处理来源归属，原图通过现有查看器读取。

**技术：** Django、pytest、Playwright；不新增表或外部依赖。

**规格：** [检验报告整理与来源关联](../specs/2026-09-28-lab-report-organization.md)。逐份内容确认由其[独立规格](../specs/2026-09-28-lab-report-review-workspace.md)负责。

## 验收范围与前提

- 一份上传资料可以有多个报告单元；一页也可以有多个区域。页面按单元显示来源，包含零指标续页。
- 自动归并仍由既有 MG-01～MG-06 决定；整理只写人工判断，不改原件、原始识别或人工修订。
- 来源分组保持现有完整互认规则。一次操作只改变一条关系，保存后展示真实分组和剩余关系。
- 查看和提交都按当前患者及有效解析版本校验；旧关系写入地址不得成为旁路。
- 整理不确认指标或报告内容。对比、趋势、输出继续从同一关系投影读取。

## 容易遗漏的情形

1. 同一原图有多个报告区域时，选择来源不能把整页视为同一报告。
2. 一个来源没有指标时，仍须在来源清单和分组内出现。
3. 仅撤销三来源中的一条关系时，页面须显示实际剩余关系和分组。
4. 候选预览后另一窗口修改任一相关关系或解析版本，提交须拒绝。
5. 同一操作标识重试只能返回原决定；换了请求内容须冲突。
