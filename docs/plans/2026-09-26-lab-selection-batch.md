# 检验对比选择与报告批量确认实施计划

> 执行方式：按已确认规格实施；独立任务并行，完成后统一回归及独立审查。使用 test-driven-development 和 dispatching-parallel-agents 工作流。

**目标：** 完成[需求规格](../specs/2026-09-26-lab-comparison-selection-and-batch-confirmation.md)的 R1～R3 与 AC-01～AC-10。

**方案：** 对比页使用现有目录顺序与指标身份构造树形选择器，GET 参数区分首次默认全选和显式清空。批量确认使用现有完整报告分组与逐项修订服务，在事务中复核权限、报告组成及结果版本；不依据展示列或数值折叠扩大范围。

**技术：** Django、原生 JavaScript、pytest、Playwright。基线为远端 `origin/main` 的 `cdecda3`；开发工作区 `.worktrees/lab-selection-batch`，分支 `feat/lab-selection-batch`。

## 全局约束

- 排序来源为已导入的 `apps/labs/dictionaries/indicator-catalog.json`；运行时不依赖本地 Excel。
- 保留既有别名、身份、单位、参考范围、报告归并、权限和审计规则；仅对比页取消个性化排序。
- 首次全选，显式清空后为空；折叠不改变选择；详情返回保留筛选。
- 单来源隐藏独立入口，数值链接及核对、错误、冲突提示保留。
- 批量操作只确认选中完整报告内的合格待确认结果，逐项审计，不修改数值或报告信息。
- 版本未知，保持 `releases: []`；不修改自动版本字段，不操作本地云部署资料。

## 审查重点

1. 跨分类同名与同义指标必须维持一个历史身份；选择键不能只取显示名称。
2. 清空、非法选择键和组合筛选不得意外恢复全部；选项范围不随日期过滤丢失。
3. 单来源冲突提示不能随来源折叠入口一起消失。
4. 报告续页、重复来源、同日同院独立报告的确认边界必须精确。
5. 确认不能使报告归并失效；重复提交、重解析、撤权及版本变化必须在写入前复核。
