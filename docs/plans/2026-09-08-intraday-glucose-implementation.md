# 日内血糖实施计划

依据[日内血糖规格](../specs/2026-09-08-intraday-glucose.md)完成 B5-02。
本分支从最新 `origin/main` 的 `af06c658cb8cc449c85ad19232f6ed0e078daa60` 创建独立
worktree，保留日常记录、治疗周期和临床字段任务。日常记录公共接口以合入 main 的实际
版本为依赖，同期导出表也在主分支合流后集成。

## 1. 冻结来源范围与纯数据契约

- 独立原件审计固定 source/OCR 身份，核对实际血清结果、采样/报告时刻、明示空腹、
  尿糖/HbA1c、输液与非逐次护理摘要；保留未判断范围，不先读新预测修改标注。
- 新建 `apps/glucose/payloads.py` 和 `tests/glucose/test_payloads.py`，先用失败用例固定
  单位规则、精度、原始字符串、非单值、全部时段、时区/秒/DST 与表示能力边界。
- 换算源为规格中的 CDC 页面；合成测试使用明确数学值，不引入医疗阈值。

## 2. 独立记录、历史和生命周期

- 注册独立应用、GlucoseRecord、GlucoseRevision 和源关联迁移；实际作者为必需参数。
- 先测再实现幂等创建、来源重复导入、乐观修订、删除/撤销、账号与患者清理。
- 迁移检查保留既有文档、临床字段、日常记录与旧导出/分享；历史迁移图显式包含新应用
  当时不存在的状态。新增记录绝不写假 Document。

## 3. 来源导入与核对

- `apps/glucose/sources.py`/`services.py` 基于当前有效观察项，独立核验血液葡萄糖语义。
  从同报告原页抓取有明确标签的采样时刻和时段，保留字段对应的原文位置；冲突或缺失
  保留精度不详，标题/编码不能跨报告借用。
- 预览来源与确认导入分开；POST 重新计算来源身份，拒绝已更正、重解析或撤权后的旧选择。
- 护理原件核对录入保留用户抄录来源与原页；没有逐次时间的摘要不自动拆点。
- 真实固定输入重放保留首次结果、字段/来源分母及限制；原有检验抽取不因本导入器而
  被静默重写。需要修复源解析时另留失败、修复与同一基准复测证据。

## 4. 实际页面与图表

- 表单、来源候选选择、当前/原始/历史详情与补时；旧标签页固定患者，错误输入不丢失。
- 日内多点、时间不详区域、多天时段热力表与多值展开；单位和来源分组、未注明时段、
  无记录、日期筛选与手机/键盘路径明确。
- 实际 HTTP 与 Chromium 验证跨季/切换时区、新重复时刻、保留原秒值以及历史来源链接。

## 5. 选定速查、导出与分享

- 只从实际 main 合流日常记录及同期已交付格式，增加血糖表和独立来源绑定。
- 记录单独 PDF、CSV/JSON/ZIP、兼容读取器及限定分享；选定血糖与其他记录范围分别验证。
- 时间/原单位/换算/作者/修订/来源持久保留，分享按现有投影边界裁剪。
- 以实际较大导出和原件下载验证生成、提交、分块消费与撤权/来源变化竞争，不替换生产
  校验函数来模拟通过。

## 6. 并发、审查与源码交付

- 专用 PostgreSQL 库跑真实锁等待：双重修订/导入、来源更正与重解析、成员撤权、作者
  注销、生成与分享响应发出前变更。保留真实迁移验证。
- 冻结应用提交后运行相邻检查、必要完整测试、JavaScript、必跑浏览器和仓库契约。
  原件评测、普通测试、PG、浏览器与独审结果分别记录，不将重叠数量相加。
- 独立复审真实 diff、来源范围和反例；修复确认缺陷后定向复核，结果绑定实际提交。
- 更新文档登记与验证证据，检查暂存区和新增提交历史，校验实际中文 Conventional PR
  标题/正文。四项确切 head CI 通过后按授权 Squash；Release Please 实际发布后补版本
  清单，五批整体验收由后续 Task 10 逐条处理。
