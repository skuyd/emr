## 0. 文档目的

本 PRD 将上位方案中的第一阶段范围展开为可执行需求，用于回答：

- 用户进入产品后会看到什么、如何完成任务；
- 第一版必须开发哪些页面和功能；
- 上传、解析、搜索、查看原件和趋势分别遵循什么规则；
- 识别失败、网络失败和重复上传如何处理；
- 设计、研发和测试以什么标准判断第一版完成；
- 如何保持首版简单，同时确保未来可以继续完善。

本 PRD 不定义具体技术框架、云厂商、模型厂商、数据库选型或项目排期。

## 1. 产品定义

### 1.1 产品定位

面向肿瘤患者及家属照护者的自动病案整理工具。用户上传图片或 PDF 后，系统自动保存原件、识别文档信息和检验指标，并提供按时间浏览、关键词搜索和原件回看能力。

### 1.2 第一版核心假设

**只要用户上传资料，系统就能自动产生足够的整理价值，使用户以后愿意继续上传。**

第一版验证流程是否成立，不以医疗级解析准确率作为发布前置条件。

### 1.3 用户结果

用户完成一次上传后，应获得以下结果：

1. 原件被安全保存；
2. 文件有清晰处理状态；
3. 系统尽可能识别日期、机构、文档类型和检验指标；
4. 用户可以按时间找到资料；
5. 用户可以搜索 OCR 原文或指标；
6. 用户可以从任何识别结果回到原件；
7. 识别失败时仍能查看原件，不需要手工补录。

### 1.4 产品边界

第一版不提供：

- 诊断、疗效、病情进展或风险判断；
- 治疗、用药或就医建议；
- 当前诊断、分期、治疗方案、影像和病理的自动摘要；
- 正式就诊速查卡；
- 多患者切换和家庭协作；
- 分享、PDF、离线包和结构化导出；
- 回收站和删除恢复；
- 人工审核工作台和逐字段用户校对；
- 跨医院复杂可比性和单位换算；
- 面向公众的大规模开放。

### 1.5 第一版设计原则

1. 除患者姓名或昵称外，不设置必填医疗信息；
2. 上传是首要动作，任何辅助功能不得阻塞上传；
3. 原件优先，自动结果只做整理和索引；
4. 失败自动降级，不把工作转交给用户；
5. 指标尽量宽覆盖，但不承诺同等准确率；
6. 不自动生成医学判断性文案；
7. 页面数量、状态数量和用户选择保持最少；
8. 原件、OCR 和解析版本必须支持未来重新处理。

## 2. 用户与使用场景

### 2.1 主用户

实际整理患者资料、陪同就诊的家属照护者。

典型特征：

- 手里已有大量相册照片、截图和 PDF；
- 医疗知识有限；
- 整理时间碎片化；
- 不愿逐项录入检验结果；
- 需要在医院或家庭沟通中快速找到原件。

### 2.2 次用户

能够自主使用智能手机的患者本人。

第一版不针对医生提供账号。医生可能查看用户手机上的原始报告，但不是产品内角色。

### 2.3 核心场景

| 场景 | 用户目标 | 第一版结果 |
|---|---|---|
| 首次归档 | 把相册和 PDF 集中保存 | 一次批量上传并看到整理结果 |
| 后续补档 | 检查后快速补充资料 | 再次进入即可直接上传 |
| 查找资料 | 找到某次检查或某个指标 | 搜索结果可直接打开原件 |
| 查看变化 | 粗略查看同一指标的历史值 | 从指标详情进入实验趋势 |
| 识别不准 | 告知系统结果有问题 | 一键反馈，不要求填写正确答案 |
| 停止使用 | 删除单份资料或全部数据 | 明确确认后删除，不提供首版恢复 |

## 3. 第一版范围和优先级

### 3.1 必须交付（MUST）

- 单账号、单患者建档；
- 手机号验证码登录；
- 图片和 PDF 批量上传；
- 原件保存、处理进度、失败重试；
- 文档类型、日期、机构候选识别；
- 至少 125 项检验指标字典和宽覆盖抽取；
- OCR 全文搜索；
- 按日期组织的文档级病案列表；
- 文档详情、原件查看和字段证据定位；
- 完全相同文件去重；
- 单份资料删除和账号全量删除；
- 账号数据隔离和必要同意；
- 核心产品埋点和运行监控。

### 3.2 建议交付（SHOULD）

- 相似文件“可能重复”提示；
- 一键“识别不准确”反馈；
- 实验性指标趋势；
- 站内任务提醒和可选浏览器通知。

SHOULD 功能可以通过配置关闭，但数据模型和入口不得影响 MUST 主流程。

### 3.3 范围裁剪顺序

若项目资源不足，按以下顺序裁剪：

1. 实验性趋势；
2. 相似文件提示；
3. 一键识别反馈；
4. 可选浏览器通知。

不得裁剪上传、原件保存、病案列表、搜索、原件查看、账号隔离和删除能力。

### 3.4 关键方案选择

| 决策 | 可选方案 | 第一版选择 | 原因 |
|---|---|---|---|
| 病案组织 | 自动合并临床事件 / 按文档展示 | 按文档展示 | 降低误合并风险，用户更容易对应原件；数据层预留事件关系 |
| 指标范围 | 少量高准确指标 / 宽覆盖指标 | 至少 125 项宽覆盖 | 先验证真实资料覆盖和用户价值，准确率按指标建立基线 |
| 错误处理 | 强制用户校对 / 自动降级 | 自动降级为仅原件 | 避免把系统工作转交给用户，保证上传闭环 |

## 4. 信息架构

### 4.1 一级导航

桌面端使用固定左侧导航，保持三项：

1. **首页**：上传、任务进度、最近资料；
2. **病案**：搜索、筛选、按日期浏览；
3. **我的**：患者称呼、隐私说明、反馈、删除账号。

趋势不占一级导航，只从指标详情进入。页面顶部右侧固定展示当前患者称呼、任务状态入口和账号菜单。

### 4.2 页面清单

| 页面编号 | 页面名称 | 入口 | 核心任务 |
|---|---|---|---|
| P00 | 登录 | 访问 Web 系统 | 使用手机号验证码进入账号 |
| P01 | 首次进入与建档 | 首次登录 | 同意规则并创建单患者空间 |
| P02 | 首页 | 默认首页 | 上传资料、查看任务和最近资料 |
| P03 | 上传任务 | 首页上传按钮 | 选择文件、上传、查看逐文件进度 |
| P04 | 病案列表 | 左侧“病案” | 浏览、搜索和筛选资料 |
| P05 | 文档详情 | 文档卡片 | 查看自动结果和打开原件 |
| P06 | 原件查看器 | 详情页 | 查看图片/PDF并定位证据 |
| P07 | 实验趋势 | 指标点击 | 查看同指标历史原始值 |
| P08 | 我的 | 左侧“我的” | 查看隐私说明、反馈和删除数据 |

## 5. 核心用户流程

### 5.1 首次使用

1. 用户访问桌面 Web，进入 P00；
2. 使用手机号验证码登录；
3. 首次登录进入 P01；
4. 阅读简短产品说明；
5. 输入患者姓名或昵称；
6. 勾选隐私政策、敏感个人信息处理规则及资料上传授权声明；
7. 点击“开始整理”；
8. 进入 P02 首页；
9. 点击“上传资料”；
10. 进入 P03，拖拽或选择图片/PDF；
11. 确认文件后开始上传；
12. 原件上传成功后，用户可以切换页面或关闭浏览器标签页；
13. 首页持续展示处理任务；
14. 处理完成后展示已整理、仅原件或处理失败结果；
15. 用户打开任一资料查看详情和原件。

### 5.2 再次补档

1. 用户打开首页；
2. 直接点击“上传资料”；
3. 选择新文件并上传；
4. 系统自动追加到同一患者病案；
5. 不再要求填写患者或病史信息。

### 5.3 查找资料

1. 用户进入病案页；
2. 可按日期浏览，也可输入关键词；
3. 搜索同时匹配 OCR、文档类型、机构、日期、指标名称和值；
4. 用户点击结果进入详情；
5. 点击“查看原件”打开对应图片或 PDF。

### 5.4 识别失败

1. 原件已上传成功；
2. 解析任务失败或未识别出结构化内容；
3. 文件状态显示“仅原件”或“处理失败”；
4. 用户仍可查看原件；
5. 处理失败时可点击“一键重试”；
6. 不要求用户输入日期、类型或检验结果。

### 5.5 删除资料

1. 用户在文档详情点击“删除这份资料”；
2. 系统说明第一版删除后不可恢复；
3. 用户二次确认；
4. 该资料立即从用户界面和搜索结果中消失；
5. 后台按隐私政策完成原件、解析结果和索引删除。

## 6. 页面需求

### 6.0 P00 登录

**页面目标**

让用户在桌面浏览器中以最少步骤安全进入自己的病案空间。

**页面元素**

- 手机号输入框；
- 验证码输入框；
- “获取验证码”按钮；
- 主按钮“登录”；
- 隐私政策入口；
- 产品名称和一句话说明。

**登录规则**

- 第一版仅支持中国大陆手机号验证码登录；
- 手机号只作为账号凭证，不作为患者病案字段展示；
- 同一手机号对应一个账号和一个患者空间；
- 验证码有效期、发送频率和错误次数由安全配置控制；
- 登录成功后，首次用户进入 P01，已有用户进入 P02；
- 登录过期后返回 P00，重新登录后回到原访问路径；
- 不支持游客访问、账号密码和第三方扫码登录。

**异常状态**

- 手机号格式错误：“请输入正确的手机号”；
- 验证码错误或失效：“验证码无效，请重新获取”；
- 发送过于频繁：“操作过于频繁，请稍后再试”；
- 网络失败：“暂时无法登录，请检查网络后重试”。

### 6.1 P01 首次进入与建档

**页面目标**

用最少信息创建病案空间并完成必要授权。

**页面元素**

- 产品名称和一句话说明；
- “为谁整理资料？”标题；
- 患者称呼输入框；
- 占位示例：“例如：妈妈、王女士、我自己”；
- 隐私政策入口；
- 敏感个人信息处理规则入口；
- “我确认有权上传并管理相关资料”的授权责任说明；
- 主按钮“开始整理”。

**字段规则**

| 字段 | 是否必填 | 规则 |
|---|---|---|
| 患者称呼 | 是 | 1–20 个可见字符，自动去除首尾空格 |
| 隐私政策同意 | 是 | 未同意不可继续 |
| 敏感个人信息单独同意 | 是 | 未同意不可继续 |
| 资料上传授权确认 | 是 | 统一确认本人有权上传并管理相关资料 |

**交互规则**

- 患者资料中不要求填写性别、年龄、身份证号、手机号、诊断或病史；账号登录手机号与患者资料分开；
- 建档成功后不再重复展示该页；
- 第一版不提供新增第二位患者入口；
- 患者称呼可以在“我的”中修改，修改不影响历史资料。

**异常状态**

- 网络失败：“暂时无法创建病案，请检查网络后重试”；
- 同意版本已更新：再次进入时展示简短变更说明并重新确认。

### 6.2 P02 首页

**页面目标**

让用户一眼看到上传入口、正在处理的任务和最近资料。

**页面结构**

1. 左侧固定导航；
2. 顶部患者称呼和任务状态入口；
3. 主按钮“上传资料”；
4. 处理中任务卡；
5. 最近资料，默认显示最近 5 份；
6. 空状态引导。

宽度不小于 1280 像素时，处理中任务和最近资料采用双栏布局；较窄桌面窗口自动改为单栏，不出现横向滚动。

**空状态文案**

“还没有资料。上传检查单、报告图片或 PDF，系统会自动帮你整理。”

**任务卡信息**

- 上传时间；
- 文件数和总页数；
- 已完成数量；
- 处理中数量；
- 失败数量；
- 主状态；
- “查看详情”入口。

**交互规则**

- 首页不展示医学结论和异常提醒；
- 有多个任务时按最近创建时间倒序；
- 任务全部完成后保留 7 天，之后不再占用首页主要位置；
- 点击最近资料进入 P05。

### 6.3 P03 上传任务

**页面目标**

通过拖拽或文件选择器完成批量上传，并提供逐文件状态反馈。

**默认限额**

- 每批最多 20 个文件；
- 每批总页数最多 60 页；
- 单张图片最大 20 MB；
- 单个 PDF 最大 100 MB；
- 支持 JPEG、JPG、PNG、HEIC 和 PDF；
- 限额由后台配置控制，调整后不改变产品流程。

**选择文件后展示**

- 缩略图或 PDF 图标；
- 文件名；
- 页数；
- 文件大小；
- 删除选择按钮；
- 状态。

**桌面交互**

- 页面中央提供大面积拖拽区域，支持一次拖入多个文件；
- 同时保留“选择文件”按钮；
- 拖入不支持的文件时在文件行内提示，不中断其他文件；
- 支持键盘 Tab 切换和 Enter 触发主要按钮；
- 原件保存成功后，切换站内页面或关闭当前标签页不影响后台解析；
- 用户再次登录后可以继续查看原任务状态。

**上传状态**

| 状态 | 含义 | 用户操作 |
|---|---|---|
| 待上传 | 已选择但未开始 | 可移除 |
| 上传中 | 原件正在传输 | 可继续停留，不能删除 |
| 上传失败 | 原件未完整保存 | 重试或移除 |
| 处理中 | 原件已保存，正在识别 | 可以切换页面或关闭标签页 |
| 已整理 | 已产生可查看结果 | 打开详情 |
| 仅原件 | 未形成可靠结构化结果 | 查看原件 |
| 处理失败 | 原件已保存，解析任务失败 | 重试解析或查看原件 |
| 已存在 | 检测到完全相同文件 | 打开已有资料 |

**关键规则**

- 用户切换页面或关闭标签页前，必须明确区分“上传未完成”和“原件已保存、正在处理”；
- 只有原件成功保存后才允许提示用户可以离开；
- 上传失败不创建病案记录；
- 解析失败必须保留病案记录和原件；
- 完全相同文件不重复保存，展示已有资料入口；
- 相似但不完全相同的文件只提示“可能重复”，默认仍允许上传；
- 不要求用户为文件选择文档类型或日期。

**完成反馈**

“资料已保存，系统正在自动整理。你可以切换页面或关闭标签页，稍后回到首页查看结果。”

### 6.4 P04 病案列表

**页面目标**

让用户在最少操作下按时间或关键词找到资料。

**页面结构**

1. 搜索框；
2. 筛选按钮；
3. 日期分组；
4. 文档卡片；
5. 加载、空结果和错误状态。

**筛选项**

- 全部；
- 检验报告；
- 影像报告；
- 病理报告；
- 出院小结；
- 医嘱/处方；
- 治疗记录；
- 其他；
- 仅原件；
- 处理失败。

筛选默认为单选文档类型，可叠加一个处理状态。不提供多层高级筛选。

**排序规则**

1. 已识别文档日期的资料按日期倒序；
2. 同一天按上传时间倒序；
3. 日期未识别的资料归入“日期未识别”，按上传时间倒序；
4. 不根据异常值或医学重要性排序。

**文档卡片字段**

- 文档日期或“日期未识别”；
- 文档类型；
- 机构候选名称；
- 原件页数；
- 已识别指标数量；
- 处理状态；
- 上传时间仅在日期未识别时显示。

**搜索规则**

搜索范围包括：

- OCR 原文；
- 原始文件名；
- 文档类型；
- 机构名称；
- 文档日期；
- 指标原始名称；
- 指标标准名称；
- 指标原始结果和单位。

搜索结果展示命中片段，但不得把片段改写成医学结论。

**空结果文案**

“没有找到相关资料。可以换个关键词，或直接按日期浏览。”

### 6.5 P05 文档详情

**页面目标**

展示系统整理结果，同时让原件入口始终清晰可见。

**桌面布局**

- 默认采用左右双栏：左侧展示文档信息和识别结果，右侧展示原件预览；
- 点击左侧字段时，右侧原件跳转到对应页面并高亮证据；
- 双栏空间不足时允许收起原件预览，但“查看完整原件”入口始终可见；
- 用户可打开 P06 全屏查看器查看复杂 PDF 或大图。

**顶部信息**

- 文档类型；
- 文档日期；
- 机构；
- 处理状态；
- 页数；
- 主按钮“查看原件”。

**识别结果区**

按原报告顺序展示，不按严重程度排序：

| 展示项 | 规则 |
|---|---|
| 原始指标名 | 尽量保持报告文字 |
| 标准名称 | 有可靠映射时展示为辅助文字 |
| 原始结果 | 不修改原始精度 |
| 原始单位 | 保持报告单位 |
| 参考范围/定性说明 | 有可靠关联时展示 |
| 报告原始标记 | 可展示 H、L、↑、↓ 等，并标注“报告标记” |
| 来源 | 点击后打开 P06 并定位对应页 |

**结构化展示准入**

- 名称、结果和单位关联明确时才生成一条结构化字段；
- 关联不明确时只保留 OCR 原文；
- 不因数值极端而删除字段；
- 未检出、阳性、阴性、溶血、拒收和未报告不得转成数值 0；
- 第一版不计算严重程度、风险或疗效；
- 页面固定展示：“自动识别结果可能不准确，请以原始报告为准。”

**其他区域**

- 折叠的 OCR 原文；
- “识别不准确”反馈按钮；
- “删除这份资料”入口；
- 处理失败时的“重新整理”按钮。

### 6.6 P06 原件查看器

**页面目标**

可靠查看原始图片或 PDF，并支持从字段回到证据位置。

**功能**

- 图片缩放、拖动和旋转查看；
- PDF 翻页和页码显示；
- 缩略页导航；
- 支持全屏查看；
- 支持鼠标滚轮缩放及键盘上一页/下一页；
- 从字段进入时打开对应页面；
- 有可靠坐标时高亮原文区域；
- 无可靠坐标时只定位到页面；
- 返回后保持详情页滚动位置。

**限制**

- 第一版不提供下载、分享和离线保存；
- 不展示永久公开链接；
- 原件加载失败时提供重试；
- 访问权限失效时返回登录页，不暴露文件地址。

### 6.7 P07 实验趋势

**页面目标**

低成本验证用户是否需要纵向查看指标，不把趋势作为正式医学能力。

**入口条件**

- 同一标准指标至少有 2 条可用结果；
- 结果为普通数值；
- 日期明确到日；
- 原始单位相同；
- 方法信息相同，或均来自同一机构且未发现方法冲突；
- 不含待解析、定性、半定量和带大于/小于符号的结果。

不满足入口条件时不展示趋势入口。

**页面内容**

- 指标标准名称和原始名称；
- 时间轴；
- 原始数值和原始单位；
- 每个数据点的日期和机构；
- 点击数据点打开来源原件；
- 固定声明：“实验性整理结果，不用于诊断或疗效判断。”

**展示规则**

- 初期不做单位换算和百分比变化；后续经批准的单位规则及
  [B4-03 多指标与个人变化规格](../specs/2026-09-08-personal-trend-comparison.md)
  扩展可比数值和个人变化展示，保留原值、单位及来源；
- 不生成“持续升高、改善、恶化”等文案；
- 数据不足时不补点、不推测日期；
- 数据发生冲突时分开显示，不强制连线。

### 6.8 P08 我的

**页面目标**

承载最少但必要的账号和隐私管理能力。

**功能**

- 查看并修改患者称呼；
- 查看隐私政策和敏感个人信息处理说明；
- 开启或关闭浏览器任务通知；
- 提交产品意见；
- 查看当前试用配额；
- 删除全部资料并注销账号。

**账号删除流程**

1. 用户点击“删除全部资料并注销”；
2. 页面说明影响及不可恢复；
3. 用户二次确认；
4. 立即停止账号访问；
5. 后台启动全量删除；
6. 按隐私政策完成原件、缩略图、OCR、字段、索引和日志关联信息处理。

第一版不提供账号迁移、患者转交或删除恢复。

- 日期类型候选；

- 来源页；
- 内部置信度。

4. 多个候选冲突且无法确定时显示“日期未识别”；

- 未命中字典的指标仍可作为原始字段或 OCR 文本保存；
- 新增指标不得要求修改文档主结构；
- 指标准确率按指标、医院和版式分层报告；
- 不承诺所有 125 项都可进入趋势。

## 8. 状态与异常处理

### 8.1 状态转换

正常路径：

待上传 → 上传中 → 处理中 → 已整理

降级路径：

- 上传中 → 上传失败；
- 处理中 → 仅原件；
- 处理中 → 处理失败；
- 处理失败 → 处理中；
- 任一已保存状态 → 已删除。

“仅原件”表示流程已完成但没有可靠结构化结果；“处理失败”表示任务异常且允许重新处理。

### 8.2 异常清单

| 异常 | 用户提示 | 系统行为 | 用户操作 |
|---|---|---|---|
| 网络中断 | 上传未完成，请检查网络后重试 | 保留已选文件状态 | 重试 |
| 文件格式不支持 | 暂不支持这种文件格式 | 不上传 | 移除 |
| 文件超限 | 文件过大或页数过多 | 不上传 | 重新选择 |
| 文件损坏 | 文件无法读取 | 不上传 | 更换文件 |
| 完全重复 | 这份资料已经存在 | 不重复保存 | 打开已有资料 |
| 可能重复 | 可能与已有资料重复 | 默认允许继续 | 继续或取消 |
| OCR 失败 | 原件已保存，暂未识别文字 | 状态为仅原件 | 查看原件 |
| 结构化失败 | 原件已保存，暂未整理出指标 | 状态为仅原件 | 查看原件 |
| 解析任务异常 | 原件已保存，整理未完成 | 状态为处理失败 | 重试 |
| 服务繁忙 | 当前任务较多，资料会继续处理 | 保持队列 | 稍后查看 |
| 原件加载失败 | 原件暂时无法打开 | 记录错误 | 重试 |
| 搜索无结果 | 没有找到相关资料 | 保留查询 | 换词或浏览 |
| 删除失败 | 删除未完成，请稍后重试 | 保持原数据可见 | 重试 |
| 登录失效 | 登录已失效，请重新进入 | 禁止访问文件 | 重新登录 |

### 8.3 用户文案禁区

自动内容不得出现：

- 进展、复发、恶化、改善；
- 危险、严重、轻度、中度；
- 疗效好、疗效差；
- 建议就医、建议用药；
- 骨髓抑制、粒细胞缺乏等系统推断；
- 其他诊断、预后和处置结论。

允许原样展示医院报告中已有文字，但必须明确其来源为原始报告。

## 9. 任务提醒规则

### 9.1 触发条件

- 一批上传任务全部完成；
- 一批任务中有处理失败文件；
- 用户正在使用 Web 系统，或已主动授权浏览器通知。

### 9.2 提醒方式

- 用户在线时，在页面右上角展示站内提示和任务状态徽标；
- 用户授权且浏览器支持时，可以发送浏览器通知；
- 用户关闭标签页且未授权浏览器通知时，不发送外部消息；下次登录后在首页展示结果；
- 系统只能在用户主动操作后申请一次浏览器通知权限，被拒绝后不反复弹窗。

### 9.3 提醒内容

允许：

“你上传的资料已整理完成，点击查看结果。”

不允许：

- 指标名称或数值；
- 异常、风险和诊断内容；
- 患者完整身份信息；
- 任何疗效判断。

未获得浏览器通知授权时，仅使用站内提示和首页任务状态。

## 10. 数据埋点与验证

### 10.1 埋点原则

- 只记录验证产品流程所需信息；
- 分析事件不得携带原始医疗文本、指标值、文件名或搜索关键词；
- 搜索埋点只记录查询长度、结果数量和是否打开结果；
- 第三方分析平台不得接收敏感医疗内容。

### 10.2 核心事件

| 事件名 | 触发时机 | 主要属性 |
|---|---|---|
| login_succeeded | 手机号验证码登录成功 | 是否首次登录、耗时 |
| patient_created | 建档成功 | 建档耗时 |
| upload_entry_clicked | 点击上传 | 来源页面 |
| files_selected | 完成选择 | 文件数、页数、格式分布 |
| upload_started | 开始上传 | 文件数、总大小分段 |
| file_upload_succeeded | 单文件原件保存成功 | 格式、大小分段、耗时 |
| file_upload_failed | 单文件上传失败 | 错误类型 |
| processing_finished | 单文件解析结束 | 最终状态、耗时、字段数 |
| browser_notification_enabled | 用户开启浏览器通知 | 浏览器类型、授权结果 |
| archive_viewed | 打开病案页 | 文档数量分段 |
| search_submitted | 提交搜索 | 查询长度、结果数 |
| search_result_opened | 打开搜索结果 | 结果序号、文档类型 |

| document_deleted | 删除单份资料 | 文档类型 |

### 10.3 核心漏斗

首次进入 → 建档完成 → 选择文件 → 原件上传成功 → 看到整理结果 → 打开详情 → 打开原件 → 7 天内再次打开或搜索 → 下次检查后再次上传

## 11. 非功能要求

### 11.1 性能

在约定测试网络和服务容量下：

- 首页首屏可交互时间不超过 3 秒；
- 病案列表首屏加载不超过 3 秒；
- 单患者 300 份文档以内，搜索结果 P95 不超过 2 秒；
- 原件查看器首张图片或 PDF 首页面 P95 不超过 3 秒；
- 一批不超过 20 个文件、总计不超过 60 页的资料，在全部原件上传完成后 5 分钟内产生第一批整理结果；
- 长任务必须持续显示状态，不能以无反馈等待代替性能。

### 11.2 可靠性

- 系统只有在原件持久化成功后才显示“资料已保存”；
- 解析服务异常不得影响原件读取；
- 解析任务支持幂等重试；
- 完全重复文件不得生成重复文档；
- 自动更新解析结果时保留旧解析版本；
- 搜索索引可以根据原始数据重新生成。

### 11.3 安全与隐私

- 手机号验证码登录采用会话过期、发送限频和异常尝试控制；
- 每次文档访问校验账号和患者归属；
- 原件地址不得作为永久公开链接；
- 传输和存储采用适合敏感个人信息的保护措施；
- 日志不记录原始 OCR、指标值、文件名和搜索原文；
- 通知不包含医疗内容；
- 退出登录和注销后清理主动生成的本地敏感缓存；
- 外部 OCR/模型服务不得将数据用于通用模型训练；
- 跨账号访问测试必须为零泄露。

### 11.4 可用性与无障碍

- 核心流程支持鼠标和键盘操作；
- 所有可交互元素具有清晰的悬停、聚焦和禁用状态；
- 主要按钮高度不小于 40 像素，图标按钮点击区域不小于 40×40 像素；
- 正文默认字号不小于 14；
- 状态不只依赖颜色表达；
- 关键按钮使用明确动词，如“上传资料”“查看原件”“重新整理”；
- 错误信息同时说明发生了什么和用户可以做什么；
- 不使用需要医疗知识才能理解的产品术语。

### 11.5 兼容性

- 支持桌面版 Chrome 和 Edge 当前主版本及前两个主版本；
- 支持桌面版 Safari 当前主版本及前一个主版本；
- 支持 Windows 10/11 和仍处于厂商安全支持期内的 macOS；
- 最低有效视口为 1280×720，推荐 1440×900 或更高；
- 第一版不承诺手机端和平板端适配；窄屏访问时提示“请使用电脑访问”；
- 图片方向信息缺失时仍允许人工旋转查看；
- PDF 文本层缺失时自动转入 OCR；
- 平台不支持的格式必须在选择或上传前明确提示。

## 12. 验收标准

### 12.1 功能验收

| 编号 | 验收场景 | 通过标准 |
|---|---|---|
| AC-00 | Web 登录 | 用户可以用手机号验证码登录；登录过期后重新登录并返回原访问路径 |

| AC-04 | 上传失败 | 不生成已保存记录，用户可重试 |
| AC-05 | 解析失败 | 原件仍可打开，状态为仅原件或处理失败 |
| AC-06 | 完全重复 | 不创建重复文档，并可打开已有资料 |
| AC-07 | 日期未识别 | 文档进入“日期未识别”分组，不要求用户填写 |
| AC-08 | OCR 搜索 | 未结构化文档可通过 OCR 关键词找到 |

| AC-13 | 实验趋势 | 仅符合入口条件的数据进入；每个点可回到原件 |
| AC-14 | 一键反馈 | 用户可反馈不准确，且不被要求填写正确答案 |
| AC-15 | 单份删除 | 二次确认后资料从列表、搜索和查看入口消失 |
| AC-16 | 账号删除 | 立即停止访问并启动全量数据删除流程 |
| AC-17 | 任务提醒 | 站内提示和浏览器通知不含指标、诊断或患者完整身份信息 |
| AC-18 | 数据隔离 | 账号 A 无法通过页面、搜索或文件地址访问账号 B 数据 |
| AC-19 | 埋点最小化 | 埋点和日志不包含原始医疗内容 |
| AC-20 | 未来解析 | 同一原件可用新解析版本重新处理且旧版本可追溯 |
| AC-21 | 桌面布局 | 1280×720 及以上视口可完成全部核心流程，无横向滚动和内容遮挡 |
| AC-22 | 浏览器兼容 | 支持范围内的 Chrome、Edge 和 Safari 可完成登录、上传、搜索、原件查看和删除 |

### 12.2 流程验证指标

| 指标 | 第一版目标 |
|---|---|
| 无指导首次上传完成率 | ≥80% |
| 上传成功原件可打开率 | 100% |
| 首个整理结果时间 | 约定批量规模下 ≤5 分钟 |
| 失败文件可恢复率 | 100% 有明确状态和重试路径 |
| 30 秒找资料成功率 | 5 个任务中完成 ≥4 个 |
| 强制医疗录入项 | 0 |
| 跨账号串读 | 0 |
| 再次使用意愿 | 超过半数试用用户明确愿意继续使用 |
| 真实再次使用 | 发生新检查的试用用户中记录再次上传比例 |

解析精确率和召回率必须报告，但不作为第一阶段流程验证的一票否决项。

## 13. 测试场景

测试至少覆盖：

1. 新用户正常建档和首次上传；
2. 一批 20 张清晰检验报告图片；
3. 包含多页检验报告的 PDF；
4. 低清、旋转、截图和裁切不全的图片；
5. 双栏、多表格和跨页报告；
6. 影像、病理、出院小结等仅 OCR 文档；
7. 完全相同文件重复上传；
8. 同一报告的截图和 PDF，验证只提示可能重复；
9. 日期未识别或多个日期冲突；
10. 指标名称识别但值与单位关联不明确；
11. 未检出、阴性、阳性和半定量结果；
12. OCR 服务失败；
13. 结构化解析服务超时；
14. 上传过程中网络中断；
15. 处理过程中用户退出并再次进入；
16. 搜索 OCR 关键词、指标名和值；
17. 点击字段定位原件；
18. 删除单份资料；
19. 删除账号；
20. 两个测试账号互相尝试访问资料地址；
21. 通知内容和埋点内容敏感信息检查；
22. 新解析版本重跑同一原件。
23. 手机号验证码登录、错误次数限制和会话过期；
24. 拖拽上传、文件选择上传及混合格式批次；
25. 关闭标签页后重新登录，验证后台任务状态连续；
26. Chrome、Edge、Safari 及 1280×720、1440×900 两种视口验证。

## 14. 发布与试用计划

### 14.1 内部验证

- 仅使用授权范围明确的现有样本；
- 验证格式兼容、原件保存、状态机和字段来源；
- 完成 AC-00 至 AC-22；
- 完成跨账号隔离和删除验证。

### 14.2 封闭试用

- 招募 8–10 名真实照护者；
- 每人上传一批真实资料；
- 不提供操作培训；
- 观察其能否独立上传、找到目标资料和打开原件；
- 记录需要口头解释或人工帮助的环节；
- 跟踪其是否在下一次检查后再次上传。

### 14.3 放行条件

进入封闭试用前必须满足：

- 所有 MUST 功能通过验收；
- 原件保存成功后可打开率为 100%；
- 无跨账号数据访问；
- 删除流程可执行；
- 通知和埋点不含医疗原文；
- 不存在阻断上传和原件查看的已知严重缺陷。

解析准确率较低不阻断封闭试用，但必须明确披露并记录基线。

### 14.4 暂停或回退

出现以下情况时暂停新增上传或关闭解析能力：

- 原件丢失或无法打开；
- 跨账号数据泄露；
- 外部处理方出现未授权留存或使用；
- 大量任务无状态卡死；
- 用户普遍把自动结果当成诊断结论。

关闭解析能力时，已保存原件和病案浏览应继续可用。

## 15. 风险与控制

| 风险 | 影响 | 第一版控制 |
|---|---|---|
| 解析准确率低 | 用户认为整理无价值 | 原件优先、OCR 搜索、真实基线、后续迭代 |
| 用户被迫纠错 | 放弃使用 | 无强制校对，只提供可选反馈 |
| 自动结果被误读 | 医疗风险 | 禁止判断文案、固定声明、字段回源 |
| 上传网络不稳定 | 首次流程中断 | 逐文件状态、失败重试、明确保存边界 |
| 重复资料污染列表 | 查找困难 | 完全相同文件去重、相似文件提示 |
| 外部服务失败 | 任务卡死 | 原件先保存、异步重试、仅原件降级 |
| 敏感信息泄露 | 严重信任和合规风险 | 账号隔离、非公开地址、最小日志、供应商约束 |
| 功能范围膨胀 | 延误流程验证 | MUST/SHOULD 分级和明确裁剪顺序 |
| 后续难以扩展 | 重构和数据迁移成本 | 稳定标识、来源链、原件不可变、解析版本化 |

## 16. 后续兼容要求

第一版完成时必须保留以下演进能力，但不开发对应完整功能：

- 增加多患者和家庭成员时不重建已有 Patient 和 Document；
- 增加分享权限时可基于稳定文档标识授权；
- 增加专业复核时可为现有字段创建复核任务；
- 增加速查卡、PDF 和导出时可复用来源证据；
- 增加诊断、治疗、病理和基因结构时可关联现有文档和事件；
- 新字典和新模型可重新解析历史原件；
- 新旧解析版本可对比和回退；
- 回收站上线后可扩展删除状态，不改变文档标识；
- 趋势能力升级时可使用原始值、单位、机构、方法和来源信息。

## 17. 默认产品决策

为避免实现期间出现歧义，第一版采用以下默认决策：

1. 默认载体为桌面 Web，第一版使用手机号验证码登录；
2. 一个账号只能创建一个患者；
3. 病案界面按文档组织，不自动合并成临床事件；
4. 每批默认最多 20 个文件、总计不超过 60 页；
5. 用户不需要选择文档类型和日期；
6. 指标字典至少覆盖 125 项；
7. 解析失败优先降级为仅原件；
8. 趋势不进入一级导航；
9. 第一版删除后不支持用户恢复；
10. 第一版不提供下载、分享、离线和导出；
11. 解析准确率用于建立基线，不作为流程试用的硬门槛；
12. 原件保存、账号隔离和删除属于不可降级能力。
