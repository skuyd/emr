# 现有方案全面审查结论

> 审查对象：`design/肿瘤电子病案系统-产品方案-v1.md` 及其三份评审报告、两位患者样本。

## 总体评价

现有 v1.2 对真实医疗单据的观察很深入，尤其是双栏错位、参考范围 OCR、定性/半定量结果、自由文本引用和复杂治疗方案。这些内容具有很高价值。但文档更像“医学文档解析系统说明书”，尚未完整回答一个消费级医疗产品如何获得信任、形成使用闭环并安全上线。

综合判断：方向成立，直接按当前 V1 开发风险较高；应先完成范围重切、可信数据模型、金标准和诊室体验验证。

## 值得保留的设计

- 锁定家属照护者而非泛患者，用户画像真实；
- “跨院归集 + 原文回溯”抓住了医院系统无法覆盖的断点；
- 以真实样本修订方案，而不是仅凭流程想象；
- 识别 bbox、版面分栏和参考范围为前置技术依赖；
- 不做诊疗建议、DICOM 阅片和自动 RECIST，边界方向正确；
- 接受部分解析失败并保留原文，符合复杂医疗文档现实。

## 主要问题与修正方向

| 维度 | 现有问题 | 影响 | v2.0 修正 |
|---|---|---|---|
| 产品战略 | 核心输出排到 V2，V1 导入后缺少回访理由 | 技术成功但产品不留存 | 速查卡、导出、离线前移 V1 |
| 用户场景 | 重浏览、轻诊室压力场景 | 最有价值时刻操作失败 | 30 秒速查、离线缓存、问答式信息组织 |
| MVP | 125 项若全部承诺同等能力，关键能力会过浅 | 资源分散，准确率承诺虚化 | 保留 125 项覆盖；40–50 项核心保障，扩展项分级验收 |
| 医学语境 | V1 趋势缺治疗背景 | 化疗后谷值等容易被误读 | 最小治疗背景前移，取消自动谷值判断 |
| 跨院比较 | 未建模检测方法与可比性 | 核心趋势可能是伪趋势 | 方法/标本/单位可比组，不可比则断线 |
| 数据信任 | 依赖用户通过原文发现错误 | 用户通常没有能力与动机 | 系统三态路由，高风险字段二次复核 |
| 异常表达 | 用偏离比例映射“显著/危险” | 临床意义不等于数值偏离比例 | 只做范围对照，去诊断化词汇 |
| 数据模型 | 缺方案组、溯源、字典版本、状态机 | 复杂样本无法稳定承载 | 补齐核心实体和字段级证据链 |
| 字典治理 | 模型映射自动回写 | 可能静默污染全库 | 候选—审核—发布—迁移 |
| 去重 | 只看图像相似度 | PDF/照片重复污染趋势 | 文档指纹 + 语义事件幂等 |
| 数据权利 | 导出、恢复、停服预案不足 | 用户不敢托付唯一病案 | 原件/结构化导出、回收站、删除说明 |
| 家庭伦理 | 默认患者与家属全透明 | 与真实告知习惯冲突 | 可见范围与授权机制进入合规设计 |
| 质量 | 指标口径不自洽，无金标准 | 无法客观验收 | 双人标注，全量/子集双口径 |
| 样本 | 两位均为胰腺癌、两家医院 | 不能支撑“全癌种”承诺 | 补癌种、医院、版式和高危样本 |
| 商业/成本 | 免费但无配额与总预算 | 重度导入可造成成本失控 | 配额、预算止损和透明降级 |

## 特别需要警惕的产品误区

1. 广覆盖有归档价值，但指标越多不等于首页价值越大。保留 125 项的同时，首屏仍应聚焦关键指标，并明确不同能力等级。
2. 原文回溯不是质量兜底，只是审计能力。真正兜底是让可疑数据不进入结论性视图。
3. 跨院趋势不是天然成立。检测方法、标本、参考体系不同，数值可能不可直接连接。
4. “只陈述事实”也可能形成暗示。系统主动选择“持续上升”作为标题，本身就是一种判断。
5. 一页纸生成在工程上成本低，不代表产品上简单。字段选择、来源、时间范围和缺失说明决定它是否误导。
6. AI 开发可以降低编码成本，不能替代医学标注、合规判断和真实用户研究。

## 建议的开发启动顺序

1. 先完成字段定义、标注规范和 120–140 页高风险摸底集；
2. 做“上传—病案事件—证据定位—速查卡”的完整垂直闭环；
3. 只选血常规和肿瘤标志物验证趋势可比性；
4. 用真实家属测试诊室 30 秒任务和趋势误读；
5. 通过发布闸门后，再扩指标、癌种和协作能力。
