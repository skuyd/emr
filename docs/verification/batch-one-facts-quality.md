## 实际行为

事实提取器版本为 `literal-sections-4`。医嘱提取要求同页出现真实表头及明确的起始日期、
药疗类别、长期或临时类型、医嘱内容和执行状态，按行关联剂量、途径、频次及停止时间。
原始药品文字不由词典改写；签名列不纳入医嘱正文。同一时刻的不同医嘱分别保留，
非药疗行和残缺行参与行边界，防止相邻内容串行。下一页没有表头时不继承前页表格。
医嘱日期保持事件原文，不能替代未知的报告日期，也不据此推断治疗周期或给药建议。

段落提取新增明确的检测概览等节标题边界，避免空临床诊断吸收后续检测表。
诊断正文中的收样、采样标签只在明确的元数据边界截断；影像叙述不套用这一规则。
空报告日期标签不再借用后面的手术日期。仍保留未解决的日期错配，见下表。

仅当相邻 OCR 区域在几何位置上重叠且重复识别了相同字符时合并重复部分；普通相邻
重复数字保持原样。每次实际合并都保存原 OCR 片段、原件区域和阅读顺序、去重前后
文本、规则版本 `medication-overlap-1` 与原因。列表和详情提示
“重叠文字已合并，请核对剂量”，可以展开原片段和过程。确认、修订仍保留最初的
自动内容及修订历史。页面截断的候选继续标记范围限制，不能默认为完整医嘱。

段落和医嘱关联使用 `layout_polygon`，旧对象缺失时回退到原有 `polygon`；来源记录
及合并审计使用原件坐标。多块医嘱保留页级来源，不伪造单个包围框。现有核对、有效
版本和导出流程继续要求确认；这些摘录没有直接进入趋势计算或自动成为治疗方案。

## 固定全量结果与人工核对量

本次沿用 64 个文件、60 个报告组、124 页，保留 232 条已判断事实的全部分母，
包括 105 条叙述/字段及 127 条完整药品医嘱。34 页未判断范围和 2 个截断后无法判断的
源字段继续单列；不通过删除困难文件、合并同日医嘱或改变标注降低分母。

| 指标 | 原始基线 | 集成候选 |
| --- | ---: | ---: |
| 正确 | 60 | 97 |
| 错配 | 15 | 104 |
| 漏提 | 157 | 31 |
| 额外 | 1 | 1 |
| 精确率（正确 / 候选） | 60 / 76，78.9474% | 97 / 202，48.0198% |
| 召回率（正确 / 已判断源事实） | 60 / 232，25.8621% | 97 / 232，41.8103% |
| F1 | 38.9610% | 44.7005% |
| 有候选 / 无候选 / 处理失败文件 | 52 / 12 / 0 | 55 / 9 / 0 |
| 报告日期正确 / 错配 / 缺少对应候选 | 62 / 13 / 157 | 188 / 13 / 31 |

日期的“正确”包括金标准与候选均为未知。新增医嘱大多保持未知报告日期，因此不能把
日期正确数增加解释为新增识别了 126 个实际日期；原有 13 条日期错配仍然存在。
评分以一对一完整事实为单位，只沿用空白、NFKC 和标题可省略的既有规范化；
剂量、否定、上下文等仍须一致。整段叙述和单条医嘱长度不同，不能解释为医学准确率。

| 核对工作量代理 | 原始基线 | 集成候选 | 变化 |
| --- | ---: | ---: | ---: |
| 所有需要检查的候选 | 76 | 202 | +126 |
| 需修正或移除的候选（错配 + 额外） | 16 | 105 | +89 |
| 需手工补录的已判断事实 | 157 | 31 | -126 |
| 修正/移除加补录的条数 | 173 | 136 | -37 |

提取覆盖提高使更多原本需要手工录入的内容成为可对照候选，但绝不能因此略过核对。
这些是条数代理，没有测量人工耗时，也没有证明额外检查 126 个候选一定节省时间。
对当前结果应同时考虑精确率下降 30.93 个百分点和完整正确事实增加 37 条。

## 逐条保真及错配归因

用原始预测和相同的一对一评分逐项追踪原来 60 条正确事实，全部仍正确，退化为 0；
配对源位置的摘要保存在[归因制品](artifacts/batch-one-facts-attribution.json)。
增加的 37 条正确事实由 35 条医嘱和 2 条诊断元数据边界修复组成。

| 匿名源编号 | 完整医嘱金标准 | 正确 | 错配 | 漏提 | 额外 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 22 | 32 | 6 | 26 | 0 | 0 |
| 26 | 32 | 5 | 27 | 0 | 0 |
| 27 | 31 | 11 | 20 | 0 | 1 |
| 42 | 32 | 13 | 18 | 1 | 0 |
| 合计 | 127 | 35 | 91 | 1 | 1 |

首轮医嘱提取有 92 条错配，检查发现两个可归因于解析的问题：一条重复的重叠字符使
整条错配，修复后变为正确；另一条停止时间串入第二层表头，修复后其正文仍有 OCR
字符差异。当前剩余 91 条医嘱错配均只涉及内容正文，起始日期、类型、状态和停止时间
与冻结标注相符。逐项回查固定 OCR 后，48 条完整采用一个原始内容框，43 条拼接
同一原始行的多个内容框，91 条都有自身 OCR 行的支持；其中 26 条仅有标点或符号差异，
65 条还存在其他字符差异。这里归因的是固定 OCR 与原件转录之间的差别，未重新 OCR、
未修改金标准，也不把这些候选重新算作正确。

最初的额外候选是匿名源 9 的空临床诊断吸收检测概览，本次已消除。现在唯一额外候选
来自匿名源 27 页底截断的医嘱，带有页面范围限制，仍完整计入额外和人工核对量。
它不由相邻截图补全。剩余一条医嘱漏提来自匿名源 42：固定 OCR 将执行状态与签名
跨列合为一个框，当前没有可靠的自动分割依据。源 27 原有的两个无法判断字段仍保留。

## 评测身份和复现

历史工具使用 `default_dictionary()`，生产流程已使用 `current_dictionary()`。
本次工具默认绑定生产字典，并增加 `--dictionary` 和 `--dictionary-sha256`；实际入库的
解析版本必须与所选字典版本、哈希一致，否则评测失败。匹配、规范化及分母规则没有
改变；F1 只是从原有计数计算的新增统计。

保留三份独立执行的基线，不回写旧证据：

| 制品 | 应用代码及评测方式 | 结果 |
| --- | --- | --- |
| [原始执行](artifacts/batch-one-facts-baseline-original.json) | 原始 `b7d5f34` 应用和工具，隐式历史字典；原执行内容保留，未补造字典身份或 F1 | 60 / 15 / 157 / 1 |
| [显式历史字典重放](artifacts/batch-one-facts-baseline-historical.json) | `b7d5f34` 应用，仅替换当前评测工具，显式字典 `1.0.0` | 60 / 15 / 157 / 1 |
| [显式生产字典重放](artifacts/batch-one-facts-baseline-production.json) | 相同基线应用和当前工具，显式字典 `phase-two-1` | 60 / 15 / 157 / 1 |
| [集成候选重放](artifacts/batch-one-facts-evaluation.json) | `edd2f3c` 应用、同一当前工具，字典 `phase-two-1` | 97 / 104 / 31 / 1 |

三份基线预测规范内容的 SHA-256 均为
`1411fb2055ab1cc4c390d932f1928fd29eeff65bef23aaa20860ee36d5b2bdf9`。
历史和生产字典的事实计数相同，并不等于可事后把旧执行标识成新工具执行。
原始基线以 Windows 检出字节记录源码哈希；两次显式重放保留相同应用字节，仅更换
评测工具。当前候选的解析依赖字节与 `edd2f3c` 的 Git blob 逐个核对一致。

[验证清单](artifacts/batch-one-facts-verification.json)。原运行 JSON 使用 CRLF，公开副本按
仓库规则只转换为 LF，JSON 内容没有改变；清单同时记录原执行与公开文件的哈希。

在空 SQLite 中重新执行实际处理流水线和持久化，原件与固定 OCR 字节均先验证。
`PHR_FACT_INVENTORY` 和 `PHR_FACT_ANNOTATIONS` 指向本地既有冻结文件，不是仓库依赖。

```powershell
$factsDictionaryHash = (Get-FileHash -Algorithm SHA256 -LiteralPath apps/labs/dictionaries/phase-two.json).Hash.ToLowerInvariant()
python -X utf8 tools/phase_three_evaluation.py --inventory $env:PHR_FACT_INVENTORY --annotations $env:PHR_FACT_ANNOTATIONS --annotation-sha256 c94a74c1e83fc92263ecf5b2e9ff8af5bebdf7bf1d311b7f2d9cbfa941307e19 --dictionary apps/labs/dictionaries/phase-two.json --dictionary-sha256 $factsDictionaryHash --report .runtime/facts-quality/replayed.json --private-output .runtime/facts-quality/replayed-private
```

复现基线时使用独立的 `b7d5f34` 只读应用检出，并仅复制上述哈希的当前评测工具；分别
显式选择历史和生产字典运行相同命令。不得以该旧检出开始新功能开发。
这里是固定 OCR 的开发集重放，未覆盖新的 OCR 推理质量或耗时，也没有独立保留集。
