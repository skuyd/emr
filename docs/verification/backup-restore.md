# 备份、恢复与删除账本验证

## 当前结论

备份/恢复脚本的安全契约、PowerShell 语法、YAML 编排和同步删除逻辑已自动验证。当前机器
缺少 Docker、`age` 和真实 S3/数据库，尚未执行一次端到端加密备份与隔离恢复。因此 RPO、
RTO 和物理对象删除没有真实测量值，发布状态为 `BLOCKED`。

## 已实现的安全边界

- 备份包含 PostgreSQL、自有对象前缀、签名删除账本、元数据和 SHA-256 清单；
- 归档使用 `age` 公钥加密，明文临时目录在成功/失败路径均清理；
- 保留期硬限制为 1–30 天，路径拒绝磁盘根目录和越界子路径；
- 恢复必须输入精确确认词、`*_restore_drill` 数据库和 `restore-drill/*` 对象前缀；
- 数据快照 A 与最新删除账本备份 B 分离，B 不得早于 A；
- 两个加密备份均先校验 SHA-256，再用 B 的签名账本覆盖 A 的旧账本；
- 删除在隔离进程内同步执行，不向正式 Celery 队列发送任务；
- 对象删除失败或仍有依赖文档时演练失败，正式流量始终不切换。

## 必做演练

1. 在合成环境创建两个账号及可搜索、可打开的文档；
2. 执行备份 A，记录时间和最近可恢复点；
3. 删除一个独立文档和另一个完整账号，等待正常删除任务完成；
4. 执行备份 B，确认 B 的 UTC 时间晚于 A；
5. 按 `deploy/runbook.md` 用 A 恢复数据、用 B 回放最新删除账本；
6. 验证被删目标在数据库、首页、病案、搜索、详情、原件和隔离 S3 前缀均不存在；
7. 验证未删除目标仍能登录、搜索和打开原件；
8. 记录备份结束、故障假设、恢复开始、可验证完成时间，计算 RPO/RTO；
9. 验证加密备份超过 30 天会清理，隔离目标经审批后单独销毁。
