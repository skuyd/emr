# 检验报告整理与来源关联需求规格

日期：2026-09-28

状态：`active / verified`。整理功能已由 [PR #121](https://github.com/skuyd/emr/pull/121) 合并并随 [v2.3.0](../releases/v2.3.0.md) 发布；完整本地门禁与独立逐份核对工作区的交付边界见[验证记录](../verification/lab-report-organization.md)。实际交付状态以[文档登记表](../document-registry.json)为准。

## 1. 目标

在“健康档案 → 报告详情 → 整理报告”提供一个低频操作入口，用于处理同一份检验报告的续页、重复来源及错误关联，让系统明确哪些原图属于哪一份报告。

正常情况下，上传后的处理继续按既有规则自动关联归属明确的报告来源，用户直接逐份核对报告内容。只有归属不明确或关联错误时，用户才需要人工整理。

用户侧统一称为“整理报告”，不再把“报告归并”和“来源关联管理”分成两套入口。此功能独立于[检验报告逐份核对确认](2026-09-28-lab-report-review-workspace.md)，遵守各自单一职责。

## 2. 功能位置与职责边界

### 2.1 入口

- 主入口固定放在健康档案的检验报告详情内，名称为“整理报告”，作为次要操作；不新增一级导航、全局管理中心或待办中心。
- 默认带入当前患者、当前资料及选定报告，不能进入后要求用户从头寻找对象。
- 当前资料标识和返回位置随入口保留；关联对象可来自同患者的其他资料，但不能因此把首页展开成全患者来源管理列表。
- 一份上传资料包含多份检验报告时，先在当前资料范围内选择目标报告；不将整个文件默认视为一份报告。
- 正常报告保留低频入口，便于纠正后来发现的误关联；有疑似续页、重复来源或归属冲突时，在报告详情提示“报告来源待整理”。
- 既有“报告关联核对”入口由本功能承接，入口文案与上下文统一；不在逐份核对页增加整理表单或管理按钮。
- 保存后留在整理页查看结果，也可返回原报告详情；保留当前患者和资料上下文。

### 2.2 职责划分

| 功能 | 负责的事情 |
| --- | --- |
| 上传后的自动处理 | 按现有规则识别报告单元，并自动关联证据充分的来源 |
| 整理报告 | 查看原图与归属依据，判定是否同一报告，纠正或撤销来源关联 |
| 逐份核对确认 | 对照当前报告原图，修改错误、补录遗漏指标，并确认内容准确完整 |

整理页只处理来源归属，不编辑指标值、单位、参考范围、医院、采样时间或报告号，也不确认报告内容已核对完成。需要更正原报告字段时使用统一核对功能。

本次不增加上传、重新识别、手工创建报告、图片裁切或 PDF 重组、跨患者移动、永久删除来源、批量整理、历史数值比较、医学解释、字典管理、导出分享或授权复核功能。取消授权复核的要求继续有效。

## 3. 整理对象和基本规则

### 3.1 对象

整理对象是同一患者名下已经存在的检验报告单元及其来源关系。原图可以来自报告续页、不同截图、重复拍照或不同上传资料；同一图片内也可能存在多个报告单元。

来源卡片应显示原件缩略图、文件名称、页码及已有报告区域，并展示原件已有的医院、报告号、采样时间等身份信息，帮助用户判断归属。未识别的信息明确显示未识别，不猜测或自动填入。

已明确关联但没有提取出指标的续页也要显示，不能仅从指标列表反推来源。无法确定报告单元或原件仍在处理时，只显示相应状态，不在整理页创建报告或执行识别。

### 3.2 自动关联沿用现有规则

自动关联条件以[检验报告上传校验、报告归并与结果去重](2026-09-17-lab-report-consolidation.md)的 MG-01～MG-06 及其引用的续页例外为准。本需求调整操作位置与人工整理体验，不另设一套归并算法。

- 仅处理同一患者的来源；医院、报告标识、采样时间及其他依据应满足既有规则。
- 同日同院、结果相同、图片相似、文件名相同、上传时间接近，均不能单独证明属于同一报告。
- 证据不足或存在身份、采样时间、重叠结果冲突时，保留来源并提示，不自动归并或用其中一份覆盖另一份。
- 已人工判定不同或已撤销的关系，不因相同证据再次立即自动归并；依据发生实质变化时按既有规则提示重新判断。
- 多来源分组仍遵守既有关系规则，不仅凭 A 与 B、B 与 C 的关系，就自动推定 A 与 C 也属于同一报告。

### 3.3 整理不改变原始资料

归并只是调整报告与来源的组织关系，不合成或删除图片，不改写原始识别内容，不删除人工修订历史，也不把不同来源的数值平均或强制改成一致。

“重复来源”指同一份报告的重复拍摄、重复扫描等已存在来源。处理重复来源不等于物理删除文件；既有上传文件去重规则不在本次变更范围内。

## 4. 人工整理流程

### R1：查看当前报告的来源

页面先显示当前报告的来源清单和原图，再显示与它有关的待判断来源。自动关联、人工关联、待判断及存在冲突的关系应有易懂的状态说明。

用户可切换原图、放大查看已有页或报告区域。沿用现有查看器，不另建原图编辑工具。

### R2：关联续页或重复来源

用户选择同患者已有的来源作为判断对象，查看双方原图与报告身份信息，再选择“属于同一报告”。页面明确显示本次涉及的来源及整理后报告范围，保存时记录判断依据。

候选优先展示与当前报告有关的来源；需要选择其他来源时也限定为当前患者的已有检验报告单元。每次只处理当前选择的关系，不提供跨报告多选或一键归并全部。

系统自动带入来源、页码和已有报告标识，用户只补充必要的简短判断依据。保存成功后刷新当前报告的来源清单，保留全部原图及各自结果来源。

### R3：判定不同报告

对于系统提示的疑似关联，用户可选择“不是同一报告”，保存后双方独立保留。页面不再把相同依据的同一候选反复作为新问题提示。

如果已经存在归并关系，则通过 R4 解除相应关联；不能只隐藏提示而继续在后台归并。

### R4：纠正错误关联

用户选中当前报告中归属错误的来源，查看受影响关系后执行“取消关联”。保存后按有效关系重新计算报告分组，来源及原始资料均保留。

有多个来源或相互关联时，应明确本次取消的关系及影响范围，不在后台顺带解除未选择关系。若解除一条关系还不足以分开目标来源，展示实际结果及剩余关系，不误报“已全部拆分”。

取消错误关联后，可在同一整理功能内按 R2 关联到同患者的正确报告；不跨患者移动资料，不把文件拆成新的物理文件。

### R5：依据、状态与失败反馈

保存的关系决定保留操作者、时间、来源依据和变更前后状态，用户能够查看本报告的整理记录。复用现有关系事件与撤销能力，不引入额外审批或授权复核流程。

保存前来源已变化、原件被删除、解析版本切换或另一个窗口改变关系时，停止本次写入，提示重新查看最新来源。重复提交不重复生成相同决定；失败不产生半完成关系。

## 5. 与逐份核对确认的衔接

整理成功表示来源关系已保存，不表示报告指标已经核对，也不自动确认任何报告。整理页不放“确认报告内容”“确认并下一份”或指标编辑表单。

逐份核对页按整理后的明确报告范围加载原图和指标。报告归属未解决时，核对页仅提示当前报告暂不能完成确认，允许切换下一份；整理操作仍由报告详情中的独立入口承担。

关系变更使报告所含来源或指标范围发生变化时，旧的整份内容确认保留为历史，不能直接作为新范围已完整核对的证明。当前报告需要重新核对；指标原有的有效更正不因来源整理而被删除或回退。

报告字段更正和来源整理可以分开保存，避免循环依赖：例如原报告号识别错误时，用户可先在核对页保存该字段更正，即使整份报告暂不能确认；再从报告详情进入整理页判断来源关系。

现有检验对比、趋势及有效结果输出应读取一致的报告关系；本次不为整理页新增这些功能，也不扩大原有分享的来源范围或访问权限。

## 6. 权限与既有实现衔接

- 沿用既有关系修改权限，不扩大权限层级；只读成员可以查看获准资料，不能通过旧地址或伪造请求修改关系。
- 页面进入、原图读取及每次提交均校验患者、资料和来源范围。跨患者、无权来源、已删除原件及已失效登录不能作为关联对象。
- 提交两端须是不同的当前有效报告单元，拒绝重复选择同一单元或使用旧解析版本。原件中患者信息冲突继续提示，不能因资料上传在同一患者档案就认定原文一致。
- 旧报告关联读取地址在保留患者与来源上下文的前提下导向“整理报告”；旧关系写入只能复用相同权限、版本及审计约束，不留下较宽松的旁路。
- 本功能优先复用[报告关系服务](../../apps/labs/reports.py)、[报告读取](../../apps/labs/report_reads.py)及[现有关系页面](../../templates/labs/report_relation.html)；不为入口迁移重建报告模型或改动不相关功能。
- 资料详情已有的混合入口见[资料详情模板](../../templates/documents/detail.html)。实施时将来源整理入口归到本功能，报告字段更正与内容确认归到逐份核对页，避免两处各自处理相同事务。

## 7. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 从健康档案打开报告详情 | 有低频“整理报告”入口，无新增一级菜单；进入后保留当前患者、资料和报告 |
| AC-02 | 同一上传资料包含多份报告，或一张图包含多个报告区域 | 能选定目标报告，来源范围准确，不将整份文件/整张图自动归成一份报告 |
| AC-03 | 证据充分、证据不足、同日同院、身份或结果冲突 | 沿用现有自动归并规则；不因新入口放宽条件；不确定来源独立保留并提示 |
| AC-04 | 同一报告的续页或重复拍摄来源 | 对照原图后可保存同报告关系，完整展示全部关联来源，包括零指标续页 |
| AC-05 | 两份不同报告被提示疑似关联 | 可判定不同并各自保留；相同依据不反复触发自动归并或新提示 |
| AC-06 | 来源被错误归并，且存在多个关系 | 可取消明确选中的关联；显示实际影响和剩余关系，不删除原图或误改无关关系 |
| AC-07 | 取消错误关系后重新关联正确报告 | 正确报告包含相应来源，其他报告范围准确，原件、指标修订和关系历史保留 |
| AC-08 | 来源归属变化前后分别查看逐份核对页 | 显示最新原图和指标范围；整理不自动确认内容，旧整份确认不覆盖新范围 |
| AC-09 | 报告号等识别错误与归属冲突同时存在 | 可先在核对页保存字段更正，再整理关系；不要求先整份确认才能处理归属 |
| AC-10 | 只读、跨患者、伪造来源 ID、已删除原件、旧地址 | 不能越权关联、读取或修改；取消的授权复核不成为访问依据 |
| AC-11 | 两窗口修改、重新识别切换版本、重复点击、保存失败 | 拒绝过期依据，无重复决定或半完成关系，错误提示可理解 |
| AC-12 | 检查整理页及逐份核对页的全部操作 | 整理页仅管理来源关系；核对页仅改错、补漏与逐份确认；没有批量操作或授权复核 |
| AC-13 | 桌面及手机查看原图、选择关系、保存、返回详情 | 原图可读，操作可完成，错误靠近相关对象，返回上下文不丢失 |
| AC-14 | 关系改变后读取对比、趋势及受限输出 | 各处遵循相同有效关系；不扩大分享范围，不删除或改写原件与人工修订 |

实施验证使用关系服务与视图测试、权限/并发回归及桌面/手机浏览器场景；已执行门禁及生产放行边界见[验证记录](../verification/lab-report-organization.md)。文档变更须通过 `python tools/verify_documentation.py`。

## 8. 文档关系与交付状态

本文补充[报告归并规格](2026-09-17-lab-report-consolidation.md)的用户入口和人工整理流程，复用其身份、接纳、归并、来源保留及撤销规则，不整体取代原规格。

本文与[逐份核对确认规格](2026-09-28-lab-report-review-workspace.md)是两份独立需求：本功能确定报告来源范围，核对功能确认该范围内的内容准确完整。二者通过已有报告和来源关系衔接，不互相嵌入管理功能。

整理报告功能已随 [v2.3.0](../releases/v2.3.0.md) 发布。逐份核对工作区继续按其独立规格交付；两项功能的共同验收边界由验证记录如实说明。
