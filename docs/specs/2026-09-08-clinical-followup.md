# B3 剩余影像、病理、分子资料与排序规格

本规格细化[五批需求](2026-09-07-batches-one-five-requirements.md) B3-01 至 B3-04。
基础 PR #51 已合入 `7bb35e1`，提供七类影像字段、独立报告边界、逐字段来源和核对、
导出及精细分享。该部分的[验证记录](../verification/batch-three-clinical-foundation.md)
不代表下面的剩余能力已经完成；B3 整体仍为 `implementing`。

## 1. 各项共同契约

- 自动字段继续复用 `ClinicalReport`、`Fact`、`FactSourceFragment` 和追加式修订。
  自动原文、原始 Unicode 区间、原件几何、解析版本与规范化原因均保留。
- 同文件的检查、标本或 panel 独立分段。来源不清晰时保留限制和待核对候选；
  不借同页存在一段文字证明另一个字段的来源，不将未标注页视为没有事实。
- 确认、更正、暂缓、排除、补录及撤销贯通详情、搜索、速查、CSV/JSON/ZIP 和分享。
  不覆盖自动内容；冲突记录并列，不用字典键覆盖同字段的多个有效值。
- 跨报告关系另建有版本的关系记录，保留实际作者、候选依据、两端身份和来源令牌。
  原始报告内实体键保持不变；长期关系不通过改写原始 `entity_key` 实现。
- 患者 → UUID 有序批次 → 文档 → 领域子行的锁序、真实操作者及实时授权沿用主线。
  新读写/来源路由进入患者定位与审计矩阵；资源定位不授予权限。
- 报告排除/替换、字段修订、解析启用、删除恢复与撤权必须使相关关系、趋势、导出和
  分享重新核验。撤销旧操作不能复活跨越来源版本变化的旧确认。
- 导出保留现有键和关系。每次新增关系数组或值类型明确其模式版本并兼容已保存内容；
  完整材料和关系修订进入共同指纹，展示投影仅携带选中且可用的部分。
- 精细选择不能从另一端关系带出未选报告、其他标本、字段原句、完整原件或外部令牌。
  分享使用自己的资格与章节投影，不复用普通档案访问权限。

## 2. 影像量化与对比字段

扩展 `lesion.suvmax`、报告及病灶的原文对比表达，以及明确的最大/较大病灶限定。
SUVmax 保存十进制原值、约数/比较符/区间、原单位（若原文出现）和本次/历史/不明的
时间角色。不得把尺寸、摄取时间、注射剂量、背景组织值或 SUVmean 当作病灶 SUVmax。

SUV 与尺寸、部位的关联必须来自同一明确报告范围和局部原文。多个相似病灶或角色
不明时保留待关联状态，不按最近数字静默拼接。没有原文值时不填零。

对比表达保留完整否定、不确定和限定，明确引用的检查日期保留原精度。尚未保存的
对比检查只能作为原文引用；存在多个匹配检查时并列提议，由用户选择。

“本报告明确最大病灶”与“某组内较大者”分别保存。不能从不完整的已抽取候选中求
最大值，再称其为报告明确的最大病灶。字段模式的增量扩展必须保持旧模式值、确认和
来源可读，不能仅因部署新版本就使旧报告的正确确认丢失。

### 首项字段与接口

| 字段键 | 实体与类型 | 保存的原文契约 |
| --- | --- | --- |
| `lesion.suvmax` | 本报告局部观察；`SCALAR` | 1 或 2 个十进制字符串、EQ/LT/LE/GT/GE/RANGE、原单位或空、约数、本次/历史/不详及原表达 |
| `lesion.maximum_scope` | 本报告局部观察；`CODED` | `GROUP_LARGER` 或 `REPORT_MAXIMUM` 与对应原词，不按数值排序产生 |
| `comparison.statement` | 独立 `comparison:*`；`TEXT` | 完整原文，包括复合结论、否定、不确定及限定；不生成检查关系 |
| `comparison.reference_date` | 同条 `comparison:*`；`DATE` | 明示引用日期及年/月/日/不详精度；不借本报告检查或签发日期补值 |

新字段模式为 `1.1`。原七类字段仍使用自己的 `1.0` 模式；模式校验按字段定义，
已有报告、自动值和用户修订不会仅因全局提取版本更新而变为不可用。日期和普通文本的
旧值形状不变。范围必须有两个有序值，其他比较符只接受一个值，未知单位保持为空。

继续使用 `/facts/<fact_id>/` 的 GET 核对与 POST 修订，以及
`/facts/reports/<report_id>/` 的明确页来源补录。比较日期只允许选本报告的对比实体；
SUV 和最大限定只允许选本报告的局部观察。CODED 表单分开保存类别原词和完整来源片段，
确认原值不会把部位原词意外替换成整段文字。数值更正后的显示从有效值生成，自动原值
及字符区间仍保留在审计和原件核对中。

首项复用既有 `clinical_reports`、`clinical_fields`、`clinical_field_sources` 数组及对应
CSV 表；集成已合入主线的日常记录后，portable data 为 `1.2`，可同时携带明确选中的
`self_records`。`clinical_fields[].schema_version` 仍表示该字段自己的模式版本，新四类
字段为 `1.1`、旧七类为 `1.0`；旧摘录表不变，读取器继续接受旧 portable 1.0/1.1。
报告/字段细选遵守来源上下文允许清单，普通章节选择不扩大范围；未确认候选不进入
默认速查、导出或分享。报告、字段、来源和选定日常记录的修订进入各自快照指纹。

## 3. 稳定病灶关联和趋势

患者拥有独立的稳定病灶标识。报告内观察通过追加式关联修订连接该标识；每条观察
保留报告、实体键和所用位置、侧别、尺寸/SUV、日期及方法字段的身份和来源令牌。

自动提议结合明确的对比引用、部位和侧别，展示逐项依据及候选之间的差异。它不直接
确认同一病灶，更不产生医学结论。相反侧、不同器官、同报告多灶、多个相似候选、
只提及既往治疗或不确定对比均不能自动合为一条。无明确日期不伪造日期。

用户能确认、拒绝、重新关联、拆分、命名和撤销；关系冲突不覆盖其他关系审计。
确认必须同时核对两端的当前来源，过期候选不能依靠旧预览提交。

趋势只采用有效确认的关系和字段，保存有序维度与原单位。仅在单位、轴、方法和
时间角色可比时连线，厘米换毫米须展示原值及转换依据；轴不明或方法不同保留点和
原因，不强行连线。SUVmax 使用独立量纲；本次测量和报告引用的历史值不重复计点。
每个稳定病灶及报告明确的最大病灶可查看尺寸变化，不计算 RECIST 疗效等级。

## 4. 云影像来源

支持报告明文链接和本地二维码解码结果。二维码证据单独标为二维码来源，保存原件
页、区域及本地解码器身份，不能伪造 OCR 字符偏移；同页多报告归属不明时先待核对。
现有 OpenCV 依赖可用于本地解码，不引入付费服务或后台远程抓取。

用户对照原件确认后，通过受控入口打开合法的 HTTP(S) 地址；不接受脚本、文件协议、
嵌入凭据或其他可执行地址。入口展示外部站点和访问性质，检查当前权限/来源并记录
无原始 URL、令牌或医疗正文的审计。医院登录和验证由医院完成，外部影像不被声明为
本系统已保存的原件。打不开或失效可修订、排除或重新补录。

外部访问信息不能因为选择了普通影像章节就自动扩展分享权限。必须明确选择该来源，
并清楚说明它是外部访问入口；未选择的 URL 参数和二维码内容不能进入分享或细选导出。

完整来源模型、二维码身份、默认投影保护、受控打开和三次 PR 的待审细化见
[云影像来源设计](2026-09-08-cloud-imaging-sources.md)及
[实施计划](../plans/2026-09-08-cloud-imaging-sources-implementation.md)；此链接不表示功能已交付。

## 5. 病理结构化

第 5、6 节的[字段与来源细化草案](2026-09-08-pathology-molecular-evidence.md)已进入独立
评审，保留 27 页目视覆盖及 97 页未判断；草案不取代本规格，也不表示病理/分子已经交付。

自动提取常见叙述和有真实表头的结构化表：取材/手术、标本、组织学类型、分化、部位、
有序三维大小、浸润、切缘、淋巴结、报告记载的 pTNM，以及 IHC 名称与结果。
每份标本及其报告身份独立；多个组织块、补充报告和复会诊不能按同日期自动合并。

IHC 保留原名称、结果、强弱/比例/范围及原始量纲；命名别名不能抹去原表示。
“未见”“倾向”“不能除外”等原义必须留在类型化有效值和原文中，不因提到癌名就
改成阳性结论。pTNM 仅摘录报告明确文字，不从大小或淋巴结数推导分期。

## 6. 分子与基因结构化

以报告、样本和 panel 为检测上下文，保存样本类型、检测日期、panel 名称及大小。
变异记录保存基因名称、完整变异原文、编码/蛋白位点、密码子表达、转录本（若有）及
丰度和原量纲。同基因不同变异、不同标本或检测上下文均保持独立身份。

MSI-H、MSI-L、MSS 和未明确类别分别保留，只有明确别名才规范化；MSI-L 不冒充 MSS。
TMB 保留数值/范围、原量纲和报告定性；PD-L1 保留 TPS/CPS/IC 等原评分类型、数值或
范围、比例/分数及检测条件（若有）。缺失值、未检出、阴性和未判断相互区分。

报告原有的药物匹配信息保留药物原名称、匹配叙述、证据等级及明确关联的变异/检测
上下文；不能把跨列或同药不同依据合成一条。系统不查询外部药物服务、不增加推荐，
也不把报告中的药物信息改成已采用的治疗事实。

## 7. 癌种候选与显示排序

从明确诊断文字产生有来源的候选，保留不同报告之间的冲突、否定和不确定范围。
用户可选择、改正或回到通用排序；可选诊断不成为建档必填项。

选用的排序配置只改变指标组及项目的置顶和顺序，不改变解析、保存、检索、历史值、
可比性或核对状态。切换前后所有指标、事实及稳定身份应完全保留。无可靠候选时采用
通用排序，不把用户选用的显示偏好声明为系统医学诊断。

## 8. 验证边界

先逐份核对授权原件，再为新增字段或关系冻结独立范围和标注，之后才运行新预测。
旧七类字段的 gold、初始/最终预测、严格评分器及 64 文件旧摘录证据均保留。
新增字段按声明的任务范围单独评分，同时公开完整候选数、漏提、额外、未核实来源和
无样本范围；旧任务投影只排除明确的新字段类别，不排除旧类别中的困难或错误候选。

正常与边界回归覆盖同页多报告、多病灶、多标本/同基因异位点、拆列/续页、大小和 SUV
相邻、比较方向与日期精度、否定/未提供、两端来源变化、撤权、并发提交和细选泄漏。
每个 PR 至少一条真实持久化、原件核对、修订、页面、搜索/速查、导出/分享的完整链路；
代表性浏览器及真实 PostgreSQL 竞争验证不能用静态页面或 mock 响应替代。

缺乏真实样本的类型以合成反例验证实现契约，真实质量明确写为未评测，不推算准确率。
按[实施计划](../plans/2026-09-08-clinical-followup-implementation.md)逐个交付，源码发布、
整个 B3 的验收和生产放行分别记录。
