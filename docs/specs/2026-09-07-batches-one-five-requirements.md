# 后续第 1—5 批功能需求与验收

2026-09-07，用户授权依据已讨论的第 1—5 批范围自主完成需求细化、设计、开发、测试、
文档和代码交付，允许拆分多个 PR，经必要检查与审查后 Squash 合并到 `main`，由
Release Please 发布源码版本，并允许子代理处理独立任务。本规格将该范围落实为可逐项
验证的需求；授权不是功能通过证据。当前交付状态见[登记表](../document-registry.json)。

来源为[原始产品需求](../product/original-product-requirements.md)、

## 1. 完整范围与边界

| 批次 | 用户成果 | 必须覆盖的功能 |
| --- | --- | --- |
| B1 | 更容易导入、减少识别错误与补录 | 图像裁边/纠偏/去阴影、非单据识别、检验及事实提取改进、真实回归评测 |
| B2 | 一家人共同管理多位患者 | 多患者、成员邀请、管理员/协作者/只读权限、在线分享及到期撤销、完整访问审计 |
| B3 | 复杂报告成为可追溯的结构化资料 | 影像字段与病灶追踪、病理骨架、基因变异和检测上下文、癌种候选与指标排序 |
| B4 | 按治疗过程理解数据变化 | 治疗周期自动提议、方案分组、周期时间轴、周期叠图、多指标趋势、基线及变化速率 |
| B5 | 记录报告以外的日常数据 | 体重/体温/症状自记录、日内多点血糖及多天热力表 |

长辈模式、生活质量量表、复查提醒、微信小程序属于后续第 6—7 批，本轮不扩入；此前
暂缓的离线查看、外部环境验证和生产放行继续保留原安排。生产门禁仍以
[放行记录](../verification/release-gate.md)为准，不把源码发布解释为生产已放行。

原稿的诊疗建议、疗效判断、用药推荐和完整 RECIST 自动判定仍在产品边界之外。
原稿中的严重程度着色、默认人群参考范围等已调整事项不因本规格恢复启用。所有推断
只形成可追溯、可纠正的候选；不凭指标变化创建诊断、病情风险或治疗持续状态。

## 2. 全局契约

1. 原始文件字节保持不变；页面、OCR、候选、人工修订、有效结果和派生展示分别记录。
2. 自动及人工数据均保留来源、时间精度、作者、版本和不确定性，不能静默覆盖或填零。
3. 所有读写从当前用户的患者访问资格出发。客户端隐藏按钮不能代替服务、任务与下载
   入口的授权检查；删除、撤权、到期、退出和资料版本变化都影响派生访问资格。
4. 已有账号和患者、文档及人工修订可迁移；迁移不丢数据、不扩大访问权、不复活删除项。
5. 现有授权真实样本与合成边界分别评测。不要求额外凑齐固定 200 份报告，不把合成通过
   当作真实质量。无样本的类别显示未评测；失败、漏提取、仅原件均保留在全量范围中。
6. 使用现有本地处理能力。新增付费服务或向新外部供应商发送真实资料须先提交具体方案，
   在取得相应授权前保留本地实现与评测路径。公开制品只含合成数据或去标识统计。
7. 采用现有 Web 样式、可访问表单和响应式布局。每个新增流程包含空、失败、权限不足、
   冲突和恢复状态；重要变更在桌面及手机视口执行实际浏览器验收。

## 3. B1：采集与解析质量

### B1-01 图像增强与原件坐标

- 手机照片支持自动识别纸张边缘、保守裁边、纠偏与去阴影/对比度增强，供 OCR 使用。
  无可靠边缘或变换失败时自动使用未增强图，不丢原件和后台处理状态。
- 原件查看采用现有方向校正后的整页坐标。裁切、旋转、透视和缩放记录可逆几何关系；
  OCR 多边形须映射回原件后才作为来源保存。无法可靠反映射时降级到页，不伪造高亮框。
- 纠偏后的布局坐标与原件来源坐标分别保留；行列关联使用布局坐标，字段证据使用来源
  坐标。不能先还原为斜拍坐标再丢失纠偏对表格关联的收益。
- 文本型 PDF 保持文本层优先；扫描页按相同来源契约处理。记录预处理版本和降级原因。
- 验收覆盖阴影、斜拍、深色桌面、已裁好的扫描件、贴边文字、低对比度、透明图、EXIF、
  大图和多页文件。检查原件哈希、文本保留及已知图形在原件中的定位，而非只测图像尺寸。

### B1-02 非单据识别

- 对明显生活照片等产生非单据提示；不确定图片继续尝试识别。用户可以保留为资料并
  重新整理，不因分类自动删除、阻止已接受文件查看或消耗错误的重复配额。
- 提示在上传结果、列表和详情可见，与 OCR 失败、未知资料类型分别表示；类别判定可追溯。
- 验收正常报告、报告局部截图、手写资料、空白图和非单据正反例，验证误分类后的恢复路径。

### B1-03 实际提取改进

- 修复固定真实回归集中可复现的项目/结果/单位关联、标本与日期、段落和医嘱表漏提问题。
  医嘱只转录报告事实，不生成服药建议。不能用减少评测分母或停抽所有内容换取精确率。
- 数字修复要有可验证的上下文，保留原文和变换原因；歧义进入候选，不能静默将姓名、
  生物序列、解释文字或图表数字映射为检验结果。
- 对比固定主分支基线，报告检验联合/分字段及事实分类型精确率、召回率、F1、错配、漏提、
  质量限制、趋势可用量和人工核对量。至少取得有实际样本支撑的改进，已正确字段和来源
  出现退化时须修复或明确解释取舍，不能仅凭合成通过结束该项。
- 本批采用一次有边界的改进并建立持续回归；后续批次继续保留未解决质量差距，不承诺
  无证据的医学准确率。OCR 实跑与固定 OCR 后解析评测分别说明。

## 4. B2：多患者与家庭协作

### B2-01 多患者与既有数据迁移

- 一个账号能创建和管理多位患者，明确显示当前患者并可切换；上传、检索、事实、趋势、
  导出、回收站、自记录、任务和配额均使用显式患者范围。
- 既有单患者归属迁为创建者所有，旧原件、版本和修订标识不变；没有患者时进入建档，
  多位患者时不能用无排序的第一条替代用户选择。切换后旧页面提交不能误写新患者。
- 患者级删除覆盖其资料和派生数据，账号注销删除其拥有的患者，并撤销其在其他家庭的
  成员资格；被邀请成员注销不能删除其他创建者的患者。注销产生的任务逐患者可重试。

### B2-02 成员与角色

- 创建者拥有最终管理权；家庭成员分为管理员、协作者（读写）、只读。管理员可管理普通
  成员及资料，创建者专有的患者删除和所有权操作不能被普通管理员或协作者调用。
- 创建者可授予/撤销管理员；创建者与管理员可管理协作者和只读成员。只有创建者与
  管理员可以创建分享，只读成员与协作者不能另行授予访问权。
- 邀请按患者和角色限定，默认 7 天失效，接受时须登录；令牌不可猜测、摘要存储、可撤销
  且不能重复接受或升级角色。邀请绑定指定接收账号或其已验证手机号，其他登录账号
  不能接受。提供复制邀请链接，不在自动化执行期间向真实他人发邀请消息。
- 协作者能上传、核对、更正、整理和创建日常记录；只读成员能查看其授权资料，不能通过
  直接请求、批量接口、字典复核或解析版本切换绕过只读限制。记录实际操作者而非患者所有者。
- 成员移除、降权、患者删除及账号失效立即生效。检查已打开页面、旧会话、排队任务、
  运行中的生成和随后下载；后台权限缓存不能使撤销失效。
- 通知偏好、已读及推送订阅属于实际账号与患者关系；成员操作不改变全家已读状态，
  撤权后停止发送。内部专业复核仍需独立任务授权，不随家庭角色自动授予。

### B2-03 在线分享

- 用户可选择资料生成只读在线分享，指定有效期、查看范围与是否允许原件下载，默认
  24 小时、最长 7 天。默认接受者须登录，访问不取得患者全量资格。
- 分享在服务端保存高熵令牌摘要；列表可查看范围和到期时间并立即撤销。链接不可发现
  未选资料、其他患者、内部复核记录和未授权导出。页面不向外部资源泄露令牌。
- 生成、查看和下载均复核当前分享、来源和资格。原件移入回收站、永久删除或分享撤销
  后停止后续访问；不会宣称能收回此前下载到用户设备的静态文件。
- 分享创建者失去管理分享资格时，其创建的分享立即失效；不得因令牌尚未到期继续有效。

### B2-04 完整访问审计与并发

- 按患者记录上传、查看、原件/导出下载、修订、切换版本、删除/恢复、成员/分享变更及
  拒绝访问等事件，包含实际操作者、资源类型、时间和结果。授权管理者可筛选查看。
- 审计不包含医疗正文、原图、登录凭据、邀请/分享原始令牌；普通成员不能读取其他患者
  审计。禁止将产品埋点当作完整访问审计。
- 所有动态路由、缩略图、内嵌来源、事实、检验与字典复核入口纳入角色/对象矩阵。
  PostgreSQL 验证撤权与修订、生成与删除、邀请接受等实际竞争，失败保持隔离并可重试。

## 5. B3：结构化资料与病灶

### B3-01 统一的结构化证据与修订

- 在现有事实原文及核对链上增加有类型的字段。每个字段保留来源页/区域/原文、自动候选、
  有效修订及结果类型；多份冲突事实同时存在，不自动归并成唯一当前诊断。
- 一个文件可以包含多个报告和检查，每个报告独立保留日期、类型、分段/页范围与来源。
  新解析读取原始 OCR 报告段，不能受旧摘录对“检查所见”等章节的停止规则限制。
- 用户能对照原件确认、更正、暂缓、排除、补录和撤销。重新解析、原件变更或删除使关联
  候选与派生图按规则重新核对；不能仅创建空模型或继续以全文摘录充当结构化完成。
- 新字段进入详情、检索、已核对速查卡、CSV/JSON 和 ZIP；格式带版本并保留旧数据可读。

### B3-02 影像与病灶追踪

- 抽取检查日期及精度、方法、部位、病灶位置/侧别、最多三维尺寸及原单位、SUVmax、
  报告结论和原文对比表达。未出现的值保持缺失，尺寸与 SUV 不混用。
- 同患者病灶有稳定标识；按部位、侧别和报告明确表达自动提议跨报告关联，用户能确认、
  拆分和纠正。不同器官、多个相似病灶或不确定比较不能静默合成一条。
- 显示每个病灶和报告明确的最大病灶尺寸趋势，尺寸单位规范化可回看原值；不同测量轴、
  方法或不可靠关联不强行连线。仅显示变化，不计算 RECIST 疗效等级。
- 保存报告已有云影像链接/二维码来源字段，并提供受控访问入口；不抓取第三方影像、
  不绕过医院访问验证，也不将外部内容当作已保存原件。

### B3-03 病理与分子检测

- 病理包含取材/手术、标本、组织学类型、分化、部位、三维大小、浸润、切缘、淋巴结、
  报告记载的 pTNM 及 IHC 名称/结果。报告中的不确定、否定和范围表达保持原意。
- 基因保存名称、原变异表达、编码/蛋白位点（例如同基因不同密码子变异不能合并）、
  转录本（若有）、丰度、样本类型、检测 panel 名称/大小和检测日期。
- 支持报告记载的 MSI/MSS、TMB、PD-L1 及其量纲/评分类型；别名规范化须保留原始表示。
  已有报告中的药物匹配与证据等级可结构化展示，系统不另行推荐药物。
- 自动提取覆盖明确结构化表和常见叙述。缺乏样本的字段用合成边界验证契约，真实质量
  标为未评测；固定真实分子报告的未标注页不能推断为没有事实。

### B3-04 癌种适配

- 从报告明确诊断提取癌种候选，保留来源及冲突，用户可选用或更正；不自行诊断患者。
- 对应指标组只改变置顶和排序，所有指标仍完整保存和可检索。无可靠候选时使用通用
  排序；更改癌种不会丢数据或改写历史报告。

## 6. B4：治疗周期与高级趋势

### B4-01 治疗事实、方案与自动周期提议

- 从报告提取手术、放疗、药物方案、实际治疗日期、明确周期序号和周期内日（C/D）。
  按方案分组，支持方案切换、暂停、延迟及不完整日期，原文与用户更正分别记录。
- 先用报告明确的周期信息；缺少序号时结合治疗/住院日期聚类与有足够可比记录的周期性
  自动提议周期锚点。给出依据和不确定性，可确认、纠正、合并、拆分或拒绝，不以纯手工
  录入替代自动提议，也不凭检验谷值宣布发生化疗。
- 不完整日期不补造某一天；停药和治疗结束仅依据报告明确记载或用户记录。存在日期
  冲突时保留冲突，用户不确认仍可使用日历轴和原件。
- 原稿周期推断准确率 ≥80% 保留为质量目标，按可信标注的方案、边界和序号报告联合
  正确/错误/遗漏与完整分母，另报召回率。与功能验收分列，不以合成结果证明真实目标
  已达到；样本不足或目标差距须在最终证据中保留。

### B4-02 双维度时间轴与周期曲线

- 提供“按时间 / 按治疗周期”切换；方案→周期→周期内检查三级组织，保留全部报告，
  能展开来源；确认与候选的周期锚点清楚区分。
- ANC、PLT、HGB 按距治疗锚点的实际天数叠加不同周期，独立数轴、可选周期、每点回源。
  缺失、同日多份、不可比、边界周期和方案改变均保留，不静默平均或拼接。
- 纵向比较提供关键节点与完整模式；关键节点根据可验证的治疗前、周期内最低值、
  报告明确评估节点和最近记录选择，说明选择依据并允许查看全部。

### B4-03 联合趋势、基线与变化

- 多指标联合趋势支持选择项目、时间范围、分组/单位说明及来源交互；量纲不同使用分图
  或明确归一化方式，保留原始数值，不让多条异量纲曲线共享误导性数轴。
- 比较表支持行尾迷你趋势、分组折叠及有限列宽横向浏览，保持键盘和手机可用。
- 对满足现有项目/标本/单位/方法/来源条件的精确数值计算上次变化、近三次个人均值
  偏离及按实际间隔的变化速率；明确公式、基线记录和缺失条件。零/负基线、重复日期、
  比较符、半定量、不可靠来源及不足样本时不输出伪精确百分比。
- 沿用原稿的个人变化提示：一般指标偏离近三次有效均值超过 30%、肿瘤标志物超过 50%
  只作淡色陈述提示；不是病情严重度或诊疗阈值。报告参考范围仍只采用可信报告自身值。
- 此项有意扩展旧版“不计算百分比变化”的阶段限制，实施时同步更新当前页面及相关
  设计说明；既有无法比较的数据不会因开放变化率展示而自动获得资格。

## 7. B5：患者自记录与日内血糖

### B5-01 日常记录

- 提供快速记录体重、体温和症状的表单、列表与历史图；记录测量/发生时刻、单位、来源、
  实际作者和可选备注。症状可记录名称、用户自述程度与时间，不自动判断病因。
- 支持更正、撤销/删除与历史追踪，明显格式错误及时提示。医学范围外的值不静默修正，
  原始输入、单位换算和用户确认分别保留。
- 自记录与报告来源明确区分；按患者权限共享，能进入用户选择的速查及结构化导出，
  患者/账号删除覆盖记录。日常快速路径以 30 秒内完成一条为设计目标并实际计时验证。

### B5-02 日内血糖

- 使用独立记录，测量时间精确到分钟并明确时区，支持一天多次及同一分钟多来源，不能
  按日期去重。来源包括检验单、护理记录、血糖仪自测和患者手动记录。
- 时段包含空腹、早餐后 2h、午餐前、午餐后 2h、晚餐前、晚餐后 2h、睡前、凌晨 3 点、
  随机/未注明；原始时间与时段分别保存，不根据时间自动断言进餐关系。
- 保留 mmol/L 与 mg/dL 原值，按有来源的明确规则提供统一展示。导入血液/床旁血糖，
  排除尿糖、HbA1c 等不同项目；人工与报告记录不能静默合并。
- 提供日内多点曲线及“多天 × 时段”热力表。一个格子多记录可展开，缺测显示缺失，
  不以颜色生成疾病风险判断；每个报告来源可打开原件，自测可打开记录历史。
- 只有日期的报告值进入时间不详区域，不能填成午夜；重复请求使用幂等标识，真实的
  同刻多次测量可独立保留。仅有自记录、没有上传文档的患者也能导出自己的记录。
- 时间不详记录不进入依赖精确分钟的曲线；用户可核对来源后补充时间，记录原始精度
  与此次修订，避免把修订当作原报告自动提取值。
