# 病理、IHC 与分子检测字段设计

本稿细化[五批规格](2026-09-07-batches-one-five-requirements.md) B3-03、
[后续临床规格](2026-09-08-clinical-followup.md)第 5、6 节及原计划 Task 7。
原件覆盖、实体合同与必要语义投影已通过独立设计审查，登记为 `active / implementing`，版本未知。
现进入首个病理/IHC 功能的原件标注和 TDD 实施；合同检查不是应用或临床验证。
旧影像字段的已发布结论不扩展到本稿；B3 和五批总状态保持 `implementing`。

## 1. 目标与交付边界

用户能按报告、标本和检测上下文查看自动候选，对照原件确认、更正、排除、补录和撤销，
再把明确选择的可用字段用于搜索、速查、CSV/JSON/ZIP 和限时分享。
自动候选须覆盖有表头的结果表和明确叙述，不能只交付空字段或人工录入接口。

按两个完整功能交付：病理与 IHC；分子变异、检测上下文、免疫相关结果及报告药物依据。
后一项使用前一项已合入主线的公共接口；新功能从当时最新的 `origin/main` 创建独立分支。
PD-L1 的 IHC 评分使用同一套字段，嵌在分子报告中时也不另建互相矛盾的表示。

B3-04 癌种候选和指标排序仍是必做的后续独立交付。本稿只保留明确诊断的来源角色，
不建立排序偏好，不从变异、组织标记或送检信息推断癌种。TNB、ITH、HLA 分型、
药物代谢 SNP、肿瘤新抗原明细及完整临床试验目录不属于本次字段集合；它们的原件、
已有摘录和未判断状态继续保留，不能映射成 TMB、变异丰度或治疗记录。

## 2. 已核实的真实覆盖及限制

固定授权集合为 64 文件、124 页，128 个原件/OCR 文件的 SHA 均已重新核对。
固定 OCR 仅作定位，字级拆块会漏掉跨块关键词；31 页的字面命中不是可评测分母。
本次独立目视核对了 9 个来源的 27 页，其余 97 页保持未判断。
其中一份多页分子报告实际为 40 页，本轮只查看其中 18 页，不把未读页当阴性。

| 已审原件范围 | 能支持的后续原件标注 | 当前不能声称的结论 |
| --- | --- | --- |
| 一份不完整 IHC 报告 | 检测方法、抗体、标本、独立 TPS/CPS 评分、收样与报告日期；送检信息和对照图边界 | 不能补全缺失报告页，不能据此评估完整手术病理 |
| 同一检测的概览与结果表照片 | 以明确报告身份关联的 panel、两条实际变异、转录本和丰度、分列药物依据 | 不能只凭同基因、日期或患者姓名合并其他照片 |
| 一张分子解读照片 | 实际结果复述与背景解释的区分 | 独立报告编号、日期的绑定未证明，暂不并入上述报告 |
| 一份较长分子报告的已审范围 | 完整主变异表 46 行：44 条小变异、1 条拷贝数、1 条融合；相关检测上下文、MSI/TMB、否定结果及药物列 | 46 行只是已审表的计数，尚非字段金标准，也不代表整份报告已标完 |
| 其他已审页面 | 病史转述、普通影像的病理免责声明、循环肿瘤细胞检测及一般查体边界 | 这些页面不整体登记为“无病理/分子事实”负例 |

目前已审范围没有建立完整独立手术病理、切缘、取样淋巴结计数或 pTNM 的真实评测切片。
这些能力仍须实现并用合成正反例验证，真实质量写为未评测；不能声称整个固定集合没有该类报告。

`b9fb471d1a2a6974d942e69798ace5bb9604ed14a4685f1a8e2b5b6a18001a2f`，
来源与制品回执 SHA-256 为
`21e657ad3e53f5654bb7e1d718d1a9cfd25da6e1a600b1f34e02cf35324940f9`。

## 3. 主线接口与必要扩展

原设计基线为已合入主线的 `d53657a5c78343cbd4b65a3b6b2f3579ad712ae0`。
实施先同步源码 1.12.0，随后已合实际主线
`830f06b2dd1d745fa79e0c92cefe9b13527e769b` 的血糖功能；共享输出按其已合入的 1.4 格式接入。
以下“现有接口”记录设计时的缺口；字段核心和病理解析已在本功能分支实现，尚未独立交付。

| 现有接口 | 本次复用与缺口 |
| --- | --- |
| `ClinicalReport`、`ClinicalReportSpan` | 复用独立边界、来源版本与替换审计；当前自动分段主要识别影像，病理/分子标题只是终止边界 |
| `Fact` 的 `FIELD` 与 `EXCERPT` | 两者继续独立；`clinical_schema.py`、持久化和人工补录目前固定 `IMAGING`，需按字段与报告范围校验类型 |
| `FactSourceFragment`、`SourceEvidence` | 复用原 OCR 的 Unicode 半开区间、页和原件 polygon；人工转录只有原件页，不能伪造字符坐标 |
| `ClinicalExtraction` | 每个 ParsingVersion 一个完成记录；部署时不能删除已完成记录或覆盖旧字段以补跑新算法 |
| `clinical_readmodels.py` 与修订服务 | 复用来源令牌、有效值、冲突、父报告排除/替换和撤销；新增上下文依赖必须进入同一失效判断 |
| `clinical_forms.py` 与现有事实路由 | 复用确认链路；现有类别标签、实体选择和数值表单是影像专用，需要领域标签及空单位支持 |
| 导出 `clinical_projection` 与分享 `project_snapshot` | 复用允许清单和精细选择；现有章节只映射 `IMAGING/PATHOLOGY`，新增分子类型需显式接入 |

`FieldSpec` 已增加允许的类别和实体上下文声明，旧字段默认保持原 `IMAGING` 行为。
病理/IHC 使用 `PATHOLOGY`；分子字段使用新增 `MOLECULAR` 类别，并同时更新搜索、
章节和展示映射。报告的 `routing_kind` 只标识内容范围，不授予权限，也不替代逐字段类别校验。
旧七字段模式 `1.0`、SUV 等字段模式 `1.1`、既有自动内容及确认均保持可读和有效。
新增字段采用自己的模式版本；版本扩展不能使旧字段仅因部署而失效。

## 4. 实体、范围与来源合同

### 4.1 报告与实体

报告身份包含原件、解析版本、明确页/块范围及边界修订。新增本报告局部实体
`specimen:*`、`assay:*`、`ihc:*`、`variant:*`、`drug_evidence:*`，沿用 `entity_key`。
实体键不从基因名或日期生成。字段的逻辑上下文包括所属标本、检测及必要关联的字段身份；
服务只接受同一有效父报告内的允许类型，不能接受任意跨患者/跨报告引用。

新模式在 `Fact.automatic_content.entity_context` 保存不可变的关联声明：
`context_version`、`report_id`、`membership_policy`、`bindings`。
每个绑定只含 `role/state/target_fact_id/target_entity_key/proof_fragment_ordinals/reason`；
BOUND 必须指向有本字段原片段证明的目标，UNKNOWN 必须显式为空并说明原因。
旧字段没有该属性仍按旧契约读取；声明新模式却缺失上下文必须拒绝。
初始最小限定保存在 `automatic_content.semantic_qualifiers`，不保存第二份可写的上下文状态。

新增 `specimen.identity`、`assay.identity`、`ihc.marker` 三类 FIELD 锚，条件数据库唯一键为
`(clinical_report_id, entity_key, field_key)`。排除的锚仍占其键；普通结果不因此去重。
SPECIMEN、ASSAY、MARKER 各指向相应锚，同一声明的必需角色恰好一次，包括 UNKNOWN。
引用必须同患者、文档、报告和解析版本；评分的 marker 属于同一 IHC 实体，检测及标本
必须与该 marker 的父链一致。服务器定义标本 10、描述 11、结果 12、检测 20、条件 21、
marker 30、IHC 结果 40 的等级，只接受向下引用；共同服务另做 DFS 循环检查，最多
32 个依赖节点、深度 8，超限明确拒绝。表单验证不能代替事务内的入库校验。
`assay.collection_date/received_date/report_date` 也属于检测属性 rank 21，各自必须声明
SPECIMEN、ASSAY 两个角色；它们保留各自原标签、日期精度和未知值，不互相继承。

普通确认/更正在 `FactRevision.after.content` 保存有效值，保持原关联不变；服务器在锁内
生成 `after.context_snapshot` 和 `after.source_token`，before 保留旧状态和快照。
改标本、检测、marker 身份或 TPS/CPS 槽时必须创建新实体和待核对字段，在同一事务中
排除旧依赖项；EXCLUDE 事件外层保存 `context_replacement={operation_id,replacement_fact_ids}`。
整体 UNDO 核验全部旧/新头和来源，排除替代项并把旧项恢复为待核对，不能恢复旧确认。
单字段 UNDO 必须拒绝拆开这种操作；原自动内容、实体键和来源永不重定向。

marker/评分的来源闭包除锚外还包含同绑定实体的 `specimen.description/site/procedure`、
`assay.method/antibody` 的完整成员身份，包括新增、排除和冲突成员。每个依赖头含原始来源、
有效值摘要、修订 ID/序号/状态、当前来源令牌和实际作者及完整修订作者元组。
未选上下文更改、作者注销或 UNDO 恢复同值仍改变令牌；本字段自己的最新确认不进入
自己的 source token，其修订头单独进入输出指纹，避免确认立即使自身失效。
标本/检测锚不反向依赖子属性，不递归散列整份报告。

上下文不明时保留未关联，允许核对字段自己的原文，但不把它作为另一标本或 panel 的结果。
被借用的上下文字段更正、排除或来源失效后，依赖它的归属和产物必须重新核对。
同报告多标本、组织与配对样本、同基因不同位点、同基因小变异与融合均独立保存。
概览、正文表和解读中同一结果只有在完整身份明确一致时才合并来源；冲突值并列，不能覆盖。

续页归属须有报告标识、连续页标记或明确检测/标本标题等证据。PDF 页码和印刷页码分别保存。
截断照片、旁页窄条和无身份的解读材料不因文字相似而自动合并。

### 4.2 字段来源与原文角色

每个自动字段保留原文件/OCR/解析版本、实际页、原 block、reading order、原始字符区间与
polygon。布局处理只使用 `layout_polygon` 组织阅读顺序，最终高亮仍指向原件坐标。
跨块或字级 OCR 合成表格行时，保留每个原块的映射，不能把拼接字符串或 Fact 的局部偏移
当作原 OCR 偏移。原字符缺失或关联不能证明时保留来源未核实，不自动补造位置。

值来源、表头/单位、标本/检测标题、日期角色和作用域限定分别绑定证据。
继承的表头必须与本行位于同一明确表格/面板；同页出现一处单位、日期或组织类型不足以继承。
OCR 别字可作为待核对候选，自动原文与更正值分别保留，不能在来源层静默纠正符号或单位。

原文角色至少区分本次结果、送检信息、引用既往结论、解释/文献、对照、质控和未判断。
基本信息里的送检诊断不是本次检测得出的诊断；历史活检的“倾向”不是本次确诊。
阴性对照/阳性对照、图轴、检测阈值、肿瘤含量和背景癌种表不产生患者阳性结果。
角色与否定/不确定限定必须进入有效值和核对页面，不能只藏在原文审计中。

### 4.3 不可变原值、值窗口与标签窗口

新自动候选可在 `Fact.automatic_content.literal_source` 保存
`PATHOLOGY_LITERAL_SOURCE_V1` 声明，包含 `version`、`literal_fragment_ordinals`、
`value_fragment_ordinals`、`label_fragment_ordinals`。三个列表只引用本字段实际持久化的
`FactSourceFragment.ordinal`；拒绝重复、布尔值、无效序号、未知版本和显式 null。
原值与值列表非空，没有原标签则标签列表为空；旧记录缺少整个声明仍按原合同读取，
不得部署回填，也不能由映射器根据附近文本补造标签证明。

原值列表是自动提取时保存的首组片段，其逐字换行连接必须等于不可变 `raw_value`。
值窗口覆盖这些原字符的实际位置；只有旧式内联元数据开头的明确字段标签和原位置空白
可不计入值覆盖，标签本身必须由标签窗口覆盖。声明“标签”不能免除评分数字、量纲或
尾部原值的证明。不同位置的相同词不能替代，新增窗口也不能借入祖先片段。
表格 marker 的规范编码与旧原值前缀保持不变，值窗口另保留完整印刷描述。
TPS/CPS/IC 的标签窗口保留本条明确类型表达式及适用的原列头，不跨到另一评分。

新自动 BOUND 的 proof 必须覆盖目标声明的完整自身值区间（包括原空白），可由多个
相邻原区间共同证明，不能仅指向目标的公共列头、规范前缀或祖先证据。新自动绑定不能
为无声明旧锚补造完整值窗口；旧自动候选及明确人工页转录继续使用既有资格规则。
声明保存在自动内容中，人工更正仍追加有效修订，不覆盖原值和原来源角色。来源声明、
片段、原 OCR 或父关联改变都进入当前令牌，旧确认及选定产物需要重新核对。
精细输出继续移除这些私有片段角色与未选正文，保留必需语义，不扩大原件授权。

显式标签和值位于不同 OCR 块时，仅在同一已划定报告范围内、同页水平对齐、框不相交且
右侧值唯一时关联；另一明确标签结束该值范围。提供方 reading order 不替代空间归属。
缺坐标、并列多值、跨栏或下一行日期保持未判断，不插入冒号、不修 OCR 字符。
报告标题前已证明的成对元数据可进入同一报告的原始范围；未配对的“检测项目/名称”
标题不提供字段值，也不吞掉已证明的其他元数据。收样、采样和报告日期仍分角色保存。

原文位置正确还必须满足章节归属：质控、阳性/阴性对照、图谱和检测说明等明确排除章节
中的编号、类型、检测项目与日期，不能作为患者当前结果的标本或检测锚。这个约束同样
适用于标题前元数据、行内标签和同一 OCR 块内的换行。正常送检/基本信息可以提供本次
样本元数据，但其送检诊断仍不是当前检测结论。后续独立结果章节只允许之后的当前内容，
不追认此前排除段中的锚；不同报告各自重新确定章节范围。原 OCR 与报告来源保留，
未找到合格患者锚时继续显示未关联，不为获得完整关联而借用质控内容。

生产映射先重查实际字段、片段、证据及原 OCR 索引，再消费这些角色；新声明无效时
保留候选并标来源错误，不回落为看似有效的旧前缀。无声明旧候选只保留可证明原值前缀，
标签证明为空。此映射版本变化不修改既有两次真实输出、金标准或评分规则；任何再次
真实运行均须新的完整身份批准，不能用合成通过推定真实来源质量已达标。

### 4.4 云影像默认省略与病理语义兼容

集成实际主线 `9675f0e3f61f96eb4895c364229b9da9d8a27bdb` 后，病理选定值同样应用
默认外部访问字符串省略。先对所选值生成明确省略标记，再生成分组计数、断言、评分与
标本/检测范围的展示文字；地址末尾不能吞掉系统生成的“检出”等限定。

可携带格式校验只在独立副本内识别对象自身为真的 `external_access_omitted`，且必须
存在可见省略标记。由于标记长于最短可省略地址，长度校验按每次匹配至少 8 个原字符计；
父对象标志不放宽子对象，未标记字符串、额外键、数值、断言及角色仍按原模式严格校验。
输出保留完整省略标记，原候选、OCR、修订及完整依赖指纹不因此缩短或改写。

分享重选时，标本和检测按已核实的真实锚 Fact 身份分组，再生成本次选择内的不透明别名。
不能用已经省略的任意实体键分组，否则两个不同原实体可能错误合并；关联锚与其字段仍须
属于同一范围。内部锚身份不作为别名解析接口或原件访问授权。

实际导出/回读、分享、原值保留及失效回归入口为
`tests/exports/test_pathology_cloud_projection.py`。这些是输出兼容合同，不改变真实提取
评分、原金标准或再次真实执行的批准要求。

## 5. 拟冻结的字段集合

下表是字段合同范围；每个可独立选择的值都有自己的字段身份和来源。
新值类型必须严格校验键、量纲与空值；不把任意报告 JSON 当作可携带字段。

| 字段组与拟用键 | 实体 | 类型与语义 |
| --- | --- | --- |
| `specimen.identity/description/site/procedure` | specimen | 原件标本锚及描述；取材/手术与标本部位分别保存 |
| `specimen.histology/differentiation/invasion/margin` | specimen | 带原始否定、不确定、范围的陈述；不从词表生成肯定诊断 |
