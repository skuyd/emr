# 病理、IHC 与分子检测字段设计

本稿细化[五批规格](2026-09-07-batches-one-five-requirements.md) B3-03、
[后续临床规格](2026-09-08-clinical-followup.md)第 5、6 节及原计划 Task 7。
这是待独立评审的设计，登记为 `draft / implementing`，版本未知。
本阶段完成原件覆盖调查和接口设计；未开发新解析器，未建立字段评分金标准，未运行新预测。
旧影像字段的已发布结论不扩展到本稿；B3 和五批总状态保持 `implementing`。

## 1. 目标与交付边界

用户能按报告、标本和检测上下文查看自动候选，对照原件确认、更正、排除、补录和撤销，
再把明确选择的可用字段用于搜索、速查、CSV/JSON/ZIP 和限时分享。
自动候选须覆盖有表头的结果表和明确叙述，不能只交付空字段或人工录入接口。

按两个完整功能交付：病理与 IHC；分子变异、检测上下文、免疫相关结果及报告药物依据。
后一项使用前一项已合入主线的公共接口；新功能从当时最新的 `origin/main` 创建独立分支。
PD-L1 的 IHC 评分使用同一套字段，嵌在分子报告中时也不另建互相矛盾的表示。

B3-04 癌种候选和指标排序仍是必做的后续独立交付。本稿只保留明确诊断的来源角色，
不建立排序偏好，不从变异、组织标记或送检信息推断癌种。TNB、ITH、HLA 分型、
药物代谢 SNP、肿瘤新抗原明细及完整临床试验目录不属于本次字段集合；它们的原件、
已有摘录和未判断状态继续保留，不能映射成 TMB、变异丰度或治疗记录。

## 2. 已核实的真实覆盖及限制

固定授权集合为 64 文件、124 页，128 个原件/OCR 文件的 SHA 均已重新核对。
固定 OCR 仅作定位，字级拆块会漏掉跨块关键词；31 页的字面命中不是可评测分母。
本次独立目视核对了 9 个来源的 27 页，其余 97 页保持未判断。
其中一份多页分子报告实际为 40 页，本轮只查看其中 18 页，不把未读页当阴性。

| 已审原件范围 | 能支持的后续原件标注 | 当前不能声称的结论 |
| --- | --- | --- |
| 一份不完整 IHC 报告 | 检测方法、抗体、标本、独立 TPS/CPS 评分、收样与报告日期；送检信息和对照图边界 | 不能补全缺失报告页，不能据此评估完整手术病理 |
| 同一检测的概览与结果表照片 | 以明确报告身份关联的 panel、两条实际变异、转录本和丰度、分列药物依据 | 不能只凭同基因、日期或患者姓名合并其他照片 |
| 一张分子解读照片 | 实际结果复述与背景解释的区分 | 独立报告编号、日期的绑定未证明，暂不并入上述报告 |
| 一份较长分子报告的已审范围 | 完整主变异表 46 行：44 条小变异、1 条拷贝数、1 条融合；相关检测上下文、MSI/TMB、否定结果及药物列 | 46 行只是已审表的计数，尚非字段金标准，也不代表整份报告已标完 |
| 其他已审页面 | 病史转述、普通影像的病理免责声明、循环肿瘤细胞检测及一般查体边界 | 这些页面不整体登记为“无病理/分子事实”负例 |

目前已审范围没有建立完整独立手术病理、切缘、取样淋巴结计数或 pTNM 的真实评测切片。
这些能力仍须实现并用合成正反例验证，真实质量写为未评测；不能声称整个固定集合没有该类报告。
已观察到的结果及范围不作为训练答案，不从未来解析输出反向改写标注。

本阶段只有去标识计数和方法可进入公共材料。私有覆盖清单 SHA-256 为

## 3. 主线接口与必要扩展

设计基线为已合入主线的 `d53657a5c78343cbd4b65a3b6b2f3579ad712ae0`。

| 现有接口 | 本次复用与缺口 |
| --- | --- |
| `ClinicalReport`、`ClinicalReportSpan` | 复用独立边界、来源版本与替换审计；当前自动分段主要识别影像，病理/分子标题只是终止边界 |
| `Fact` 的 `FIELD` 与 `EXCERPT` | 两者继续独立；`clinical_schema.py`、持久化和人工补录目前固定 `IMAGING`，需按字段与报告范围校验类型 |
| `FactSourceFragment`、`SourceEvidence` | 复用原 OCR 的 Unicode 半开区间、页和原件 polygon；人工转录只有原件页，不能伪造字符坐标 |
| `ClinicalExtraction` | 每个 ParsingVersion 一个完成记录；部署时不能删除已完成记录或覆盖旧字段以补跑新算法 |
| `clinical_readmodels.py` 与修订服务 | 复用来源令牌、有效值、冲突、父报告排除/替换和撤销；新增上下文依赖必须进入同一失效判断 |
| `clinical_forms.py` 与现有事实路由 | 复用确认链路；现有类别标签、实体选择和数值表单是影像专用，需要领域标签及空单位支持 |
| 导出 `clinical_projection` 与分享 `project_snapshot` | 复用允许清单和精细选择；现有章节只映射 `IMAGING/PATHOLOGY`，新增分子类型需显式接入 |

拟在 `FieldSpec` 增加允许的类别和实体上下文声明，旧字段默认保持原 `IMAGING` 行为。
病理/IHC 使用 `PATHOLOGY`；分子字段使用新增 `MOLECULAR` 类别，并同时更新搜索、
章节和展示映射。报告的 `routing_kind` 只标识内容范围，不授予权限，也不替代逐字段类别校验。
旧七字段模式 `1.0`、SUV 等字段模式 `1.1`、既有自动内容及确认均保持可读和有效。
新增字段采用自己的模式版本；版本扩展不能使旧字段仅因部署而失效。

## 4. 实体、范围与来源合同

### 4.1 报告与实体

报告身份包含原件、解析版本、明确页/块范围及边界修订。新增本报告局部实体
`specimen:*`、`assay:*`、`ihc:*`、`variant:*`、`drug_evidence:*`，沿用 `entity_key`。
实体键不从基因名或日期生成。字段的逻辑上下文包括所属标本、检测及必要关联的字段身份；
服务只接受同一有效父报告内的允许类型，不能接受任意跨患者/跨报告引用。

拟为新增模式保存不可变的 `entity_context`，含本报告的标本/检测实体键和实际采用的
上下文字段及来源令牌。旧字段没有该属性仍按旧契约读取。上下文是身份和依赖，
不复制整页文字；关联更正采用有审计的旧范围排除与新关联候选，不改写原始实体键。
准确存储及 portable 形状在实现前随字段合同冻结，不增设未经确认的跨报告自动合并。

上下文不明时保留未关联，允许核对字段自己的原文，但不把它作为另一标本或 panel 的结果。
被借用的上下文字段更正、排除或来源失效后，依赖它的归属和产物必须重新核对。
同报告多标本、组织与配对样本、同基因不同位点、同基因小变异与融合均独立保存。
概览、正文表和解读中同一结果只有在完整身份明确一致时才合并来源；冲突值并列，不能覆盖。

续页归属须有报告标识、连续页标记或明确检测/标本标题等证据。PDF 页码和印刷页码分别保存。
截断照片、旁页窄条和无身份的解读材料不因文字相似而自动合并。

### 4.2 字段来源与原文角色

每个自动字段保留原文件/OCR/解析版本、实际页、原 block、reading order、原始字符区间与
polygon。布局处理只使用 `layout_polygon` 组织阅读顺序，最终高亮仍指向原件坐标。
跨块或字级 OCR 合成表格行时，保留每个原块的映射，不能把拼接字符串或 Fact 的局部偏移
当作原 OCR 偏移。原字符缺失或关联不能证明时保留来源未核实，不自动补造位置。

值来源、表头/单位、标本/检测标题、日期角色和作用域限定分别绑定证据。
继承的表头必须与本行位于同一明确表格/面板；同页出现一处单位、日期或组织类型不足以继承。
OCR 别字可作为待核对候选，自动原文与更正值分别保留，不能在来源层静默纠正符号或单位。

原文角色至少区分本次结果、送检信息、引用既往结论、解释/文献、对照、质控和未判断。
基本信息里的送检诊断不是本次检测得出的诊断；历史活检的“倾向”不是本次确诊。
阴性对照/阳性对照、图轴、检测阈值、肿瘤含量和背景癌种表不产生患者阳性结果。
角色与否定/不确定限定必须进入有效值和核对页面，不能只藏在原文审计中。

## 5. 拟冻结的字段集合

下表是字段合同范围；每个可独立选择的值都有自己的字段身份和来源。
新值类型必须严格校验键、量纲与空值；不把任意报告 JSON 当作可携带字段。

| 字段组与拟用键 | 实体 | 类型与语义 |
| --- | --- | --- |
| `pathology.procedure`；`specimen.description/site` | specimen | 原文文本；取材/手术与标本部位分别保存 |
| `specimen.histology/differentiation/invasion/margin` | specimen | 带原始否定、不确定、范围的陈述；不从词表生成肯定诊断 |
| `specimen.dimensions` | specimen | 最多三维、有序原值/单位/轴、约数及测量对象；不能把整体标本大小冒充肿瘤大小 |
| `specimen.nodes`；`specimen.reported_stage` | specimen | 取样/阳性计数及分组原文；明示 pTNM 原词及前缀，不能由计数、尺寸或查体推导 |
| `ihc.marker/result/method/antibody` | ihc | 名称、完整结果、强弱/比例、检测方法与抗体；对照结果独立排除 |
| `ihc.score` | ihc | 明示 TPS/CPS/IC 等评分类型、数值/比较符/范围、原单位和检测条件；不同评分各一字段实例 |
| `assay.name/panel_name/panel_size` | assay | 原名称；panel 大小包含原约数或范围，近似规模不变成精确计数 |
| `assay.collection_date/received_date/report_date` | assay | 独立日期角色与原精度；缺失保持缺失，不互相补值 |
| `variant.gene/expression/coding/protein/transcript/location/kind` | variant | 原名和完整原变异表达；转录本含原版本，位置及变异类别独立，未给蛋白位点不推导 |
| `variant.allele_fraction`；`variant.copy_number` | variant | 原十进制字符串、比较符/范围及原单位；拷贝数不是百分比，缺单位不能补 `%` |
| `variant.fusion` | variant | 有序 5′/3′ 伙伴及各自转录本/位置；基因名称含连字符不等于融合 |
| `variant.tier`；`assay.negative_statement` | variant / assay | 报告分级原词/体系；阴性限定在原检测和变异类型内，不泛化成该基因所有变化阴性 |
| `assay.msi_category/msi_value` | assay | MSI-H、MSI-L、MSS、未明分别保存；原分值/比例/阈值另列，MSI-L 不并入 MSS |
| `assay.tmb_value/tmb_qualitative` | assay | 原数值/范围、原量纲和报告定性；TNB、ITH 或背景阈值不变成 TMB |
| `drug_evidence.drugs/statement/direction/level/context` | drug_evidence | 原药名和组合、报告叙述、潜在获益/耐药等原方向、证据等级及其体系/语境；只关联报告明确指向的变异 |

文本保留删除插入、终止符、等号、内含子偏移及转录本版本，不按标点拆坏一个变异。
编码/蛋白表达的别名显示须保留原词，不自行推算另一种表达。丰度、肿瘤纯度、拷贝数、
IHC 比例、CPS 分数及背景研究百分比不可互换。明确未检出、阴性、不确定、未提供和
无法判断分别保存；缺失不是零，斜杠不是通用阴性。

结果状态还须区分“未检测”与“检测后未检出”：只有报告明确说未做该检测才记录
`NOT_TESTED`；没有一行结果只是 `NOT_PROVIDED`，不能产生阴性候选。
阳性/检出、阴性、未检出、不确定均保留相应原词和检测种类的限定，不跨变异类别传播。

分期字段只转录报告记载，不进行医学分期计算。药物字段始终标注“报告记载”，保留报告
日期和证据体系；报告所称批准地区或研究结果仅是当时报告的陈述。系统不核定当前适应证，
不连接外部药物服务，不增加推荐，也不写入已采用治疗或周期事件。

## 6. 核对、补录及可见行为

继续使用现有报告列表、`/facts/reports/<report_id>/` 和 `/facts/<fact_id>/` 路由。
按标本、检测、变异和 IHC 组织条目；每项能展开本字段及采用的标题/限定证据，并回到原件。
手机端有可读表头、分列含义和键盘入口；长变异表达不裁掉尾部，药物获益/耐药列不互换。

人工报告可选择病理或分子范围，并明确原件页；人工转录不能生成 OCR 坐标。
更正只追加修订，保留自动值、旧来源、实际作者和冲突。未核对、来源失效及不确定角色
在列表和详情可见；默认速查和携带沿用已确认且来源有效的资格。
已有解析完成记录不在部署时补写。对旧资料，用户可明确发起重新解析或按原件补录；
新解析通过当前版本切换使旧确认重新核验，不能伪装为旧版本的同一次执行。

搜索支持新类别和有效原词，不从药物知识背景生成治疗命中。速查以来源限定的报告文字
展示，不把送检病史升格为当前诊断。同字段冲突并列，字段集合不按基因名变成字典覆盖。

## 7. 细选导出、分享与来源失效

继续使用 `clinical_reports`、`clinical_fields`、`clinical_field_sources` 及既有 CSV。
字段模式与 portable 包装版本分别管理；现有 portable `1.2` 和旧 `1.0/1.1` 的读取契约保留。
若新增上下文形状需要包装扩展，须先定义兼容读取再改版本，不能按应用发布号猜模式号。

明确选择字段时，只投影该字段值、必要语义限定及来源身份/页/坐标。上下文引用不能递归
带出未选标本、其他变异、药物整列、原报告 span/body 或旧摘录/检验。
选整个报告与附带完整原件是独立、明示的范围；字段选择不隐式打开原件。
新类别必须经过导出章节和分享章节各自的过滤，资源 ID 不能绕过真实访问者资格。

快照包含实际采用的父报告、字段、上下文关联、修订、作者及文档材料状态。
字段/父报告排除、替换或撤销，活动解析切换，删除/恢复，作者注销，成员撤销/降权，
分享撤销/到期都必须在相应读写入口再次验证。序列化后读取与下载流继续检查当前状态，
不能用旧预览或旧幂等键复活失效材料。

遵守主线 Patient → UUID 有序批次 → Document → 领域对象锁序和真实操作者授权。
新增 FK 与作者注销需用真实 PostgreSQL 正常 COMMIT 竞争验证，不能通过吞异常、
放宽材料指纹或测试事务统一回滚掩盖死锁。

## 8. 标注和评分的下一阶段

逐字段核原件并绑定固定 OCR 的原位置；无 OCR 原词的人工可读内容单列，不能伪造精确定位。
尚未读完的 97 页维持未知，不从未命中关键词、没有候选或旧报告标签推导负例。

先冻结明确分母、可判断负例、排除原因和未判断范围，再独立审查 scorer、生产输出映射、
字典、输入与执行源身份，之后才允许真实预测。原件不足的切片单列未评测，合成正确率
不能替代真实准确率；字段正确数不冒充报告准确率。

按来源 SHA、报告/标本/检测范围和原位置配对，不按预测值找 gold。
严格来源正确、值错配、漏提、来源未核实及额外/重复候选分别记账，未知范围不制造 FN。
主变异表不能只评显著变异而删除其余等级、融合或拷贝数；不同量纲和负例也有明确范围。
旧影像字段和 202 条历史摘录的评测身份保留；共享代码有变化时另留同范围重放及逐条保真，
未重跑时只能声明源码身份相同，不能冒称新的全量执行。

## 9. 验收与评审入口

实现须通过原始 OCR → 报告/字段持久化 → 实际核对/修订 → 搜索/速查 → 选定导出/分享
的完整路径。必要边界包括同页多面板、跨页表、逐字拆块、阴性与不确定、同基因异变异、
