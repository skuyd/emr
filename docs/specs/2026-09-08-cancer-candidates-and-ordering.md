## 用户行为

默认 `AUTO`：上传资料后形成带来源的报告诊断候选。当前候选明确、可靠且没有冲突时，
自动采用对应显示顺序，并展示“按报告表述排序”及可核对的依据。自动排序不替用户确认
任何 Fact 或候选，也不把患者档案写成系统确诊。无可靠依据时保持通用排序。

用户可核对、更正、排除、暂缓和撤销候选；也可选择某个当前候选作为排序依据、直接选择
显示偏好、显式使用通用排序，或恢复自动模式。选择不是上传或查看资料的前置条件。
新报告不能覆盖用户的明确选择。更改排序立即生效，原值、来源、修订历史和所有指标不变。

不同报告、同报告不同诊断及原文中的否定、疑似、历史和他人病史分别保留。界面称为
“诊断表述不同/待核对”，不自行裁决医学冲突，不把转移部位当成原发癌种。

## 首批显示配置

配置独立于检验字典、单位规范化、可比性、数值资格、参考范围及异常阈值。采用最初需求
已有的两组例子，不由标记物、IHC、变异、取材部位或治疗方案推导癌种。

| 配置键 | 原需求显示组 | 置顶顺序（既有标准码） |
| --- | --- | --- |
| `GENERAL` | 通用 | 完全保留现有顺序 |
| `LUNG` | 肺癌 | `LAB_CEA`、`LAB_CYFRA21_1`、`LAB_NSE`、`LAB_PROGRP` |
| `PANCREAS` | 胰腺癌 | `LAB_CA19_9`、`LAB_CEA` |

初始字面映射清单固定为 `LUNG` 的“肺癌”“右肺上叶浸润性腺癌”和 `PANCREAS` 的
“胰腺癌”“胰头癌”“胰头导管腺癌”。肺叶例子采用第 3.7 节完整字面，不将其他器官、
肺叶或组织类型通过组合规则扩展成医学分类。允许其后保留原文分期，但不解释分期。
这些字面必须位于明确诊断/病理诊断表述内；完整原文和原始字符区间独立保存，不能仅凭
“肺”“胰腺”“腺癌”等局部词完成分类。匹配采用最长字面优先，较长未支持诊断中的
局部子串不能冒充独立诊断。可执行的标题及分句边界在 Task 1 用合成契约固定，新增
字面映射须单独审查和记录规则版本。
不支持的诊断保留原文候选和未知原因，自动回到 `GENERAL`；用户仍可明确选择显示偏好。

## 候选与来源契约

新增独立 `apps/cancer_ordering/`。候选保存患者、来源 Fact 或域内叙述来源及 Document、可空 ClinicalReport、
原始表述、候选标签、可空配置键、断言及作用对象、抽取规则版本、原页/块/字符区间和来源
快照。既有 Fact、OCR 和已完成抽取结果不可覆盖。不同原文出现位置有独立身份，不能按
标签去重而丢失来源或冲突。

第一接入使用主线现有 `DIAGNOSIS`/`PATHOLOGY` EXCERPT。类别本身不是诊断证明：必须
核对其原文标题、局部断言和归属；送检说明、质量控制、家族史、否定或疑似文字不能冒充
当前肯定诊断。病理的 `specimen.histology` 适配器只接入已经真正合入主线的字段接口，
不能从尚未合并的病理分支复制源码，也不能沿标本/IHC 上下文推导癌种。

类型化入口严格限定 `PATHOLOGY_IHC_V1` 的 `FIELD / specimen.histology`。有效的当前结果角色、
完整 `ContextResolver` 标本关联、原件和解析状态均成立后，才读取有效字段的组织学原文。
原始断言标志不代表系统确认癌种，仍使用上述固定五字面和原有局部否定、疑似及归属规则。
标签、值、关联依据和置信度来自实际片段；不得补造标题、借用邻近同名片段或推断坐标。
人工或更正文字保持转录身份，缺失原文证明保持待核对。候选确认不能代替父字段或标本核对。

字段、报告和完整标本依赖的当前及历史作者状态都参与输入与实时身份。历史作者失效使旧
确认过期，但不能永久禁止当前合法用户重新核对；当前有效审核作者及人工来源创建者无效时，
来源仍不可用。重新收集或换源不得恢复旧确认或绕过原位置的排除、暂缓、更正后撤销障碍。
私有详情显示实际绑定的报告与标本身份；输出仍仅携带明确选择的正文和来源交集。

类型化接入使用附加的原位置审核记录保留源删除后的决定：精确区间保持独立；原位置不明确
时仅保守承接同文档、同版本及可能重叠页的障碍，不按标签合并不同明确区间。
新增历史迁移只复制数据库已有候选审核与已捕获的原位置快照，不改写旧行，不扫描原件，
不重新抽取，也不执行真实评估。它与下文限定叙述首次建空表的迁移属于不同阶段。

断言至少区分 `AFFIRMED`、`NEGATED`、`UNCERTAIN`、`UNKNOWN`；作用对象区分当前原发
诊断表述、转移部位、历史、他人及未知。限定作用到具体分句，原文否定或疑似不能因报告
另一处肯定文字被抹去。NFKC 仅供匹配，来源区间仍使用原字符串索引；多块来源逐片段验证。

自动候选可以待核对展示；进入自动排序还需当前原件、解析和来源身份有效，诊断为明确
肯定且归属当前患者，映射唯一，没有待处理的不同癌种或未知癌种冲突，候选未被排除/暂缓。
未经人工核对的原文候选，其参与定位的 OCR 来源置信度须全部至少为 `0.95`；缺失或不足
时不自动采用。该值是来源可靠性规则，不是诊断概率。已核对候选仍需当前来源及归属成立，
人工核对不能把已记录的否定、历史或不确定语义静默改为肯定；更正必须是有历史的明确操作。

候选原稿不可变。确认、更正、排除、暂缓、撤销使用附加修订，记录实际操作者、预期修订号、
原/新值、原因及服务端计算的来源身份。更正不覆写原文，人工补充或显示偏好明确标为人工。
确认候选不隐式确认父 Fact；父 Fact 的排除、更正、旧解析或不可用状态仍参与失效判断。

### 限定诊断叙述来源

除既有诊断/病理摘录，接入原页上五类有明确边界的诊断叙述。先识别栏目及实际原文角色，再在
该范围内识别固定五字面；禁止无标题 OCR 全文扫描后倒找标题，也不能用虚构的“诊断：”前缀
把病程送入旧摘录匹配器。没有既有 Fact 的页面可以有真实叙述来源，不伪造 Fact 或临床报告。

| 角色 | 有限入口 | 保守边界 |
| --- | --- | --- |
| 主诉 | 明确“主诉”字段 | 疾病字面可作为报告表述；用药或不适本身不推导疾病。 |
| 现病史 | “现病史”，或“病例特点”下的“病史”子项 | 标题本身既不证明当前，也不使整段全部成为历史。 |
| 辅助检查叙述 | “辅助检查”内有“诊断／检查所见／结果”等实际诊断陈述的同一检查条目 | 数值、结果表格列头、治疗建议不赋予肯定诊断。 |
| 入院介绍 | “首次病程记录”中的“因……入院／收入院”介绍句 | 只限定介绍槽，不覆盖其后的全部病程。 |
| 会诊摘要 | “会诊记录／会诊意见”中的“病史摘要”或明确患者诊断陈述 | 会诊者、家属、建议及鉴别对象不冒充当前患者确诊。 |

送检者提供的诊断、质控、文献/指南案例、图谱和治疗适应证不进入该适配器。新文书、同级或
上级栏目、签名/页脚、患者信息区、不连续布局终止当前范围；不跨页或横向栏拼接。缺标题续页
与布局歧义记录未知范围，不用前页或邻栏补造上下文。没有癌字的已识别栏目也进入覆盖库存。

新 `NarrativeSource` 及不可变父依赖记录保存真实 Document/Page/ParsingVersion、角色、原文
逐字符位置及标题/上下文/字面片段。原块内多行保留真实 Unicode offset；合成分隔空白明确不
属于原串。每份证明绑定原块、原页、原版本、几何及置信度。候选与 Fact/叙述来源在数据库约束
中二选一；叙述不绑定伪造的 ClinicalReport。不覆盖 Fact、原抽取顺序、OCR 或已存来源证明。

断言/对象规则继续保留否定、不确定、历史、他人、转移和未知。日期只有在同一记录中实际日期
标签与局部事件日期均可定位、可判断且无冲突时，才可用于过去/当前关系；文件名、跨页推送的
日期或孤立日期不作证明。完整决定上下文参与来源核对和全部 OCR `0.95` 门槛，不能只证明
癌种字面而省略低置信度标题、否定、对象或时间。标签可定位但属性不明时保留候选及未知原因。

沿不可变原区间关联同版本/同页旧 Fact：与诊断/病理来源的同一字面位置重合时优先原路径，
不创建干净副本绕过其决定；相交的其他类别也必须绑定实际父记录。父原位置可能相交但无法
唯一证明时停止自动资格，不视为无父。父排除/暂缓/不可用阻止新来源使用；父内容更正后的
原 OCR 不能在重收集或撤销确认后重新取得自动资格，须明确核对当前父依赖。

**稳定发生身份与可变依赖分离：**同一解析版本、原页、原癌种字面位置及相同原文范围的叙述
发生身份，不因相交父 Fact 的 CONFIRM、revision/token、当前或历史作者状态而改变。父集合
新增、删除或原范围关系变化，也不能以新建无审核历史候选清除既有 EXCLUDE、DEFER、人工
CORRECT 后 REVOKE 等限制。可增删父集合、修订、继承链和作者只进入完整 input/live 指纹，
不进入稳定 occurrence key。真正范围或规则变更需要新建不可变来源世代时，以稳定原始发生
位置承接既有审核障碍并保持需核对；不继承旧确认，也不空历史恢复原 OCR 的 AUTO 资格。
不同解析版本或实际不同原文位置保持独立，不能按标签合并或继承确认。

完整范围包含尚未物化的叙述、成功零候选、范围外/未知库存、失败/部分结果及适配器版本。
所有当前父集合及其修订/作者均参与实时身份；READ 只读，上传 worker 或明确 WRITE 才固化。
READY 提取输入与 PUBLISHED 生命周期分开，正常发布不使刚完成的收集永久过期。新来源即使
未选作公开正文，也使旧排序、预览、worker、分享和后续流按统一指纹失效。

私有页面提供真实原页核对及完整有界上下文；有实际 Fact 才生成事实详情链接。该版本选定
叙述候选仍只投影现有允许字段，并明确 `OMITTED_SOURCE`；不输出虚假或空 Fact ID、叙述私有
ID、完整病程、作者及依赖。原 Fact 引用的选择交集不变，完整原件仍需单独明确选择。
新迁移只建空表/约束并保留全部旧数据，不在迁移中扫描原件或改写历史候选。

## 选择、自动解析与失效

显示选择是患者级独立状态，不复用现有按账号保存通知开关的 `PatientPreference`。模式为
`AUTO`、`GENERAL`、`CANDIDATE`、`MANUAL_PROFILE`，默认未创建选择记录等同 `AUTO`。
显式选择及撤销采用不可变事件历史；记录配置版本、候选身份（如适用）、实际作者和当前
修订号。手工显示偏好不能获得报告来源证明。

自动模式基于全部当前有效候选解析；任何相关新增候选、冲突、来源或决定变化都重新判断，
不会沿用旧的成功结果。用户显式选择不因新自动候选切换；其自身来源失效时展示原因并使用
通用顺序，保留原选择历史，直至用户重新选择。恢复原件或撤销父排除不自动复活旧确认。

自动解析同时验证完整上游输入范围，不能仅枚举已产生的候选。范围包含当前相关
`DIAGNOSIS`/`PATHOLOGY` Fact、其真实解析/原件、当前修订和相关作者状态，以及限定叙述的
发现库存、完整父依赖和接入时已支持的 typed 来源。每次收集保存所覆盖的输入身份、规则版本、完成/失败状态；成功但
零候选也有范围记录。存在尚未收集、失败、部分覆盖或规则过期的当前输入时，`AUTO`
使用 `GENERAL` 并展示原因；用户可通过明确的 `WRITE` 请求重新收集。新诊断 Fact
已发布但尚未产生候选，也必须立即参与这项判断。恢复收集后重新判断完整当前输入，
未知诊断仍为未知，不为通过完整性检查而补造癌种。

收集身份区分不可变提取输入与实时发布生命周期。worker 可在受当前租约保护的
READY 阶段收集，完成凭据绑定实际 Fact/OCR 输入及规则；正常 READY→PUBLISHED 激活
不伪装为输入变化，也不让新候选永久过期。是否当前、已发布及可访问由读时单独验证。
输入或人工修订发生变化则旧覆盖失效；不能用正常发布为由忽略真正的源内容变化。

私有来源身份绑定真实患者、Document、当前 ParsingVersion、Fact 本体与修订、可空报告及
报告修订、原文片段、候选与选择修订、当前/历史实际作者状态和规则/配置版本。不能只比较
相同文字或可继承的旧 token。父源更正、删除、重解析、排除、作者注销或生命周期变化均
触发重新核对；保留匿名历史，不显示已清理作者身份。

写操作在事务内复查 `Capability.WRITE`、预期修订和来源；读操作使用实时 `READ`，渲染后
再次复查。用户提供的 JSON、患者 ID、来源 ID 或 token 都不是服务端授权。锁顺序遵循
已合主线的患者优先规则，worker 不得在持有文档锁时逆序获取患者锁。

## 保留完整指标的排序

排序在现有过滤、可比性分组、日期/数值资格、基线及个人变化计算完成后应用。它是稳定
排列：置顶码按配置顺序，其余项维持原顺序；同码不同单位/标本/方法及同日多条全部保留。
通用模式与既有结果顺序一致，不改变观察项 ID、原值、异常标记、搜索谓词或历史报告。

对比表、默认趋势摘要和指标选择器采用该顺序；用户已明确选择的联合趋势码顺序保持原意。
未知码、非数值及缺测不能因配置未列出被隐藏。资料检索的结果集不受排序偏好影响。

## 速查、导出与分享

速查和输出先完成既有明确选择及权限交集，再对允许携带的指标重排。选择显示顺序不隐式
携带诊断文字、候选标签、作者、完整历史、未选报告/字段或访问 URL。预览展示实际内容。

当前候选和显示选择如需随资料携带，必须有独立明确选择，投影只含选中的当前值、断言、
可理解的来源状态及必要关系。缺少允许携带的来源时说明省略，不能泄露未选 Fact/报告内容
或把未知来源降成无条件诊断。完整原件继续单独选择。现有可携带格式与旧数组保持兼容，
格式号按实际已合主线核定；本次在主线 1.6 上增加癌症数组，使用便携格式 1.7。
此格式号不是应用发布版本，登记表的应用 `releases` 仍为空。

使用排序的输出，其私有指纹包含有效配置、模式、选择/候选集合及所依赖来源；即使来源
未选作公开内容，也参与失效验证，不因此授予分享接收者整文档权限。自动模式中新候选或
冲突也会使旧快照过期。`AUTO` 使用与当前解析相同的完整上游输入及收集状态指纹，新增
或更正但尚未收集的 Fact 也使旧预览、排队输出和已生成快照失效；不能依赖普通导出的
显式文档集合碰巧包含它。复用预览、生成、发布、分享渲染及流式下载的实时检查；失效后清理
旧快照并拒绝旧内容，不能通过无声重排已生成文件掩盖来源变化。

### 选定内容的可携带契约

选择增加 `cancer_candidate_ids` 和 `include_indicator_ordering`，两者默认均为空；含新正文的
提交还须带页面初始 `cancer_expected_fingerprint`，由服务端对照完整当前身份验证。只有
来源当前、未变化且未排除/暂缓的候选可以携带；待核对、否定、历史及他人归属继续明确
保留，不能因导出升级为已确认的当前诊断。

新增 `cancer_candidates` 与 `indicator_ordering` 两个数组。候选只包含选中的当前标签、
断言、作用对象、核对状态、报告/人工更正来源类型和最小来源引用；不自动携带原始完整
分句、分期附文、作者或修订历史。来源 Fact/字段与文档也在实际输出中时，才保留其 ID、
页码及定位级别；否则明确记为来源内容未选择。显示决定最多一行，包含当前模式、有效
配置及回退理由；候选关系只指向同时明确选中的候选。手动偏好明确作为显示偏好。

尚未匹配固定字面的自动未知候选，其当前标签可能仍是完整原始分句，不能把它当作独立
短标签输出。此时明确拒绝生成，选择表单保留该候选并提供本患者的核对入口；用户对照
原件更正需要携带的标签（最多 160 字）后可正常导出与分享，未知显示配置可保持为空。
仅确认原件不等于选定分句中的某段文字。原候选身份、完整私有原稿和位置均不变；不能
自动截断、换成泛称或改映射以绕过此要求。输出策略变更使旧癌种快照失效，重新选择后生成。

两类正文可以独立生成或分享，无须附带整份报告。速查与分享使用独立的“报告表述与显示
偏好”范围；选择整份原件仍按原流程单独授权。分享再次按其真实字段/展示范围收窄来源
引用。只使用排序时，这两个数组为空；完整依赖指纹只留在服务器快照，不进入 JSON、
CSV、PDF、ZIP 或接收者页面。便携 1.7 保留实际主线的病灶、云影像、IHC 和全部旧数组。
旧 1.6 非空病灶及云影像可以读回，缺少的两个癌症数组补空；任何旧版本非空癌症数组
均须拒绝。三域的显式选择与私有依赖分别保留，任一域来源失效须使整个旧快照失效，
不能通过保留另外两域的旧正文继续释放已失效内容。

## 验收与证据

验证上传到候选持久化、原件回看、默认自动排序、用户覆盖/恢复自动、逐项核对/更正/撤销、
冲突及所有失效路径。跨模式更改前后逐 ID 核对完整结果多重集、数值和来源，搜索结果不丢失。
用实际 HTTP、PostgreSQL 跨连接提交及 Chromium 检查家庭权限、作者清理、移动/键盘与
真实输出，不用替换生产授权函数来制造通过。
另外验证新 Fact 发布后收集未执行/失败、零候选成功、部分覆盖、规则变化及恢复收集，
包含旧 AUTO 顺序、预览、worker 发布、分享和已打开下载流的实际行为；正常发布必须
保留有效完成覆盖，不能把所有自动结果退回必须手工收集的流程。

真实评测前先固定原件范围、独立标注、分母、评分规则、源码和唯一执行参数，再运行预测。
未知页不是阴性；原文候选、字段归属/来源和显示组映射分开评分，合成测试不代替真实质量。
候选与排序全部流程、独审、确切 PR CI 和实际源码发布完成后按证据更新登记和版本清单。
