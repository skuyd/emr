# 检验报告逐份核对确认需求规格

日期：2026-09-28

状态：`active / verified`。逐份核对确认已由 [PR #125](https://github.com/skuyd/emr/pull/125) 合并，随 [v3.0.0](../releases/v3.0.0.md) 发布；完整本地门禁见[验证记录](../verification/lab-report-review-workspace.md)。交付状态以[文档登记表](../document-registry.json)为准，执行步骤见[实施计划](../plans/2026-09-28-lab-report-review-workspace.md)。

## 1. 目标与已确认范围

用户只核对当次检验报告的准确性和完整性：打开一份报告，对照原图，在同一页面改错、补漏、处理多识别或重复识别的项目，核对完成后确认这份报告。

已确认要求：

1. 桌面左侧为报告原图，右侧为本报告全部指标，可逐行对照。
2. 指标错误、遗漏和报告自身信息均在当前页面修改或补齐。
3. 支持多页原件、未识别出指标的页、原文结果及目录外项目。
4. 保存修改与确认整份报告分开；支持确认后继续下一份。
5. 检验报告确认统一到本功能，收起现有分散的确认和更正页面。
6. 核对页只对照原图与录入内容；历史结果对比保留在现有检验对比页面。
7. 取消授权复核功能，关闭任务入口、创建和处理，以及存量任务及其原件的授权访问；已保存的核对结果与历史保留。
8. 取消批量确认，当前页面一次只打开、编辑和确认一份报告，通过上一份/下一份继续核对。页面遵循单一职责，只做当次报告核对确认。

本页仅包含原图、当次报告内容、核对所需的改错/补漏/排除误识别及保存/确认操作。“补充信息”仅指本份原报告已有、但系统未录入或录入错误的内容。报告选择与翻页只服务逐份核对，不新增独立列表管理页或任务中心。

本页不加入报告创建、拆分/合并、来源归属管理、上传/重新识别、解析版本切换、授权复核、字典管理、历史对比、趋势、导出分享、医学解释、治疗建议、日常记录或个人备注功能。其他既有功能按原范围保留；授权复核按用户明确要求取消。

成功标准：对于范围已明确的当前报告，用户无需离开核对页即可完成全部来源页、全部指标及报告自身信息的查看、改错、补漏与确认；每次提交只作用于当前一份报告；重新打开后内容和状态正确保留；所有患者侧报告内容确认均使用这一页面。

## 2. 当前实现依据与设计选择

改造前的批量页从已有指标归组，展开后仍链接到单项原图、单项更正及报告信息页。没有指标的报告单元及续页不能靠这一查询完整枚举；本次实施已移除旧批量模板与服务。

单项更正通过[修订服务](../../apps/labs/revisions.py)保存，报告信息通过[报告服务](../../apps/labs/reports.py)保存；[现有有效结果读取](../../apps/labs/readmodels.py)默认依赖当前解析版本。原图查看器已有翻页、缩放、旋转及位置高亮能力，见[查看器组件](../../templates/documents/_viewer_panel.html)。检验指标人工补录和明确排除目前需要新增能力。

直接把当前批量确认页改为单份报告核对页，复用现有原件、修订和权限能力。入口、表单和报告内容确认服务统一，底层继续保留原始识别内容和修订历史。只新增实现本报告准确性与完整性核对所必需的保存能力，不扩展为报告管理工作台。

## 3. 单份报告的边界

核对对象是按现有规则明确归并的完整报告，包括其续页和重复来源。上传文件、PDF 页、同日同院的对比列均不自动等于一份报告。

- 从报告单元及已确认关联枚举报告和来源页，再装载指标，不从指标反推全部来源页。
- 多页文件里不属于本报告的页不得纳入确认；同一页内的不同报告也要保留区域边界。
- 已有报告单元但零指标，仍可逐份打开并补录；已关联但零指标的续页仍显示在原图导航。
- 没有报告单元或报告范围尚未明确的资料，不在本页新增报告、圈选建立报告或管理来源关系；显示“报告范围尚未确定，暂不能确认”，不把整个混合文件默认归成一份报告。
- 原图尚未生成或资料仍在处理中时，清楚展示处理状态，不能以空指标列表代替已完成识别。
- 报告归属不确定时，仅提示当前报告暂不能完成确认，并允许跳过到下一份。现有报告关联管理在本页之外处理；本页不提供归并、拆分或关联决定按钮。

“健康档案 → 资料详情 → 选定报告 → 整理报告”的独立入口和操作要求另见[检验报告整理与来源关联规格](2026-09-28-lab-report-organization.md)，不纳入本页功能。

同一指标的重复来源可折叠展示，但来源仍可展开；不同数值或参考信息不得被折叠隐藏。更正明确指向实际来源，不能把对一个来源的修改静默复制到其他报告或未选择来源。

## 4. 统一入口与兼容

用户可见功能名称统一为“报告核对”。检验工作区保留一个主入口，进入后直接显示当前一份报告；没有指定报告时优先打开待核对报告。当前页支持逐份切换，不新增独立报告列表页。取消批量确认及独立单项内容确认表单。

上下文中的结果数值、报告名称可继续点击，直接打开同一核对页并定位本报告/该指标。这些链接只承担导航，不形成另一套确认流程，也不在各页面反复增加确认按钮。

| 现有位置 | 调整后的行为 |
| --- | --- |
| 检验对比的批量确认入口 | 改为唯一“报告核对”入口，当前页一次打开一份报告，取消多选、全选和跨报告提交 |
| 对比单元格、来源列表中的指标详情链接、资料详情中的检验结果链接 | 打开所属完整报告，必要时定位指标；保留合法的返回位置和筛选条件 |
| 单项“与原件一致”“识别有误”“主动更正”页面 | 患者侧不再独立提供表单；旧读取地址导向核对页对应位置 |
| 报告医院、采样时间、报告号核对页 | 整合为当前核对页中的报告信息区域 |
| 既有报告关联管理 | 不迁入本页、不作为另一套内容确认；原有归属管理能力按既有范围保留 |
| 原图来源链接、历史解析结果 | 保留只读来源/历史能力；历史内容不能误跳到当前版本后直接确认 |
| 授权复核队列、任务及任务原件 | 功能取消，入口和创建/处理能力移除，旧链接不再提供任务或来源内容 |
| 分享链接与导出资料 | 保持既有只读及选定范围，不导向患者整份报告的编辑入口 |

旧单项内容核对、批量确认及报告详情地址的 GET 跳转必须重新校验患者和访问权限，返回地址只允许站内安全目标。资料详情为每份报告分别提供“报告核对”导航和独立的“整理报告”入口；旧报告详情地址直接定位统一核对页，不再保留另一张只读详情页。旧表单 POST 不用重定向方式重放写入：旧跨报告批量、独立单项及报告信息更正提交停止受理，清楚提示进入统一核对页，且不产生修改。新的核对页提交统一经过第 7 节服务。报告关联管理的既有独立路由与服务不在本次收口停用范围，本页不调用其写入操作。

单项的 `source/image` 原件地址与指标详情地址区分处理：普通患者有权访问的原件地址继续只读供核对页、趋势等使用，不重定向成编辑页。授权任务的 `source/image` 则按下一节全部停用。

### 4.1 取消授权复核

按用户追加要求，取消整个授权复核功能，不保留另一种任务核对模式：

- 移除普通页面及管理界面的授权复核导航、授权按钮、人员分配、任务队列与任务处理表单；不再生成新的复核任务或可操作任务通知。
- 关闭创建、分配、执行复核等写入入口；存量未完成任务不能继续处理。旧任务 GET/POST、任务 source/image 地址均返回统一的功能停用响应，不展示任务内容、身份或原图，也不自动跳到患者整份报告。
- 存量有效期未到、已有复核权限、已打开的旧页面或手工请求旧地址，均不能继续凭旧任务授权读取/修改资料；资料读取本身须遵循现有请求内权限复核，不能只靠隐藏菜单关闭。
- 字典候选列表、详情、审核来源等间接读取同样停止使用旧复核任务授权。当前[字典候选来源筛选](../../apps/labs/dictionary_workflow.py)直接引用任务，实施时须一并移除该授权支路；其他本来合法的患者或字典管理权限仍按其原有范围校验。
- 保留已完成核对形成的有效结果、修订事件和必要历史，不因功能下线删除或撤销此前有效更正；历史读取沿用既有有权访问方式，不在本页新建历史管理功能。
- 历史任务及授权记录仅作为既有数据留存，不作为继续访问的凭据。本次不进行历史任务表的破坏性清空，也不把旧单项授权自动升级为患者编辑权限。

只有具备当前患者写权限的用户可在核对页保存与确认；已有只读成员继续只读。非检验资料的核对及患者成员权限管理不受本次调整影响。

## 5. 页面与操作

### 5.1 当前页逐份核对

当前页面一次只展示一份报告的原图和全部指标。顶部显示该报告的医院、采样时间、报告号、来源页数和核对状态；原图未提供的信息明确标记未提供或未识别，不编造标题或时间。

使用上一份/下一份在同一页面逐份切换，可跳过暂不能确认的报告。入口带有明确报告时打开该报告，否则优先打开尚未确认报告；均已确认时显示完成提示并允许返回查看。没有报告时显示空态。本页没有报告多选框、全选、批量操作栏或跨报告“一次确认全部”。

### 5.2 原图与指标

桌面采用左右布局，左侧原图可缩放、旋转、适合页面和切换本报告来源页；右侧滚动、编辑时仍能看见原图。右侧默认显示本报告全部指标，不受检验对比页面的分类选择和日期筛选裁剪。

指标按原页及原图阅读顺序排列。默认展示原项目名称、结果、单位、报告参考范围、原异常标记；标本、检测方法等本报告已有信息可在行内展开更正。标准目录匹配作为辅助信息，不覆盖原报告名称、单位或参考范围。

点击指标时，有可靠来源坐标则定位高亮；无坐标时显示对应原页并明确位置精度，不伪造框选位置。输入过程中不得因自动排序、刷新或翻页丢失焦点与内容。

手机采用同一核对页的上下布局，可展开原图并返回当前编辑位置；不挤压为不可读的两列，不跳转到另一套单项核对页面。所有操作支持键盘，字段错误贴近字段并可定位。

### 5.3 同页改错、补漏和排除

- 多行、多字段可连续修改，一次保存；不要求逐字段提交或逐指标确认。
- “添加遗漏指标”创建一行，默认关联当前明确报告和其当前原页/区域，不改变报告范围。录入名称和原文结果，单位、参考范围、标记、标本及方法按原件填写。
- 支持数字、比较符、阴阳性、半定量及报告状态文字等原文结果；不把所有结果强制转为数值。
- 项目不在标准目录中时，允许按原文保存和核对，归入现有“其他”/待匹配表示；不要求用户输入标准编码，不伪造标准匹配或修改公共字典。
- 原件未提供的可选字段允许为空；参考范围及单位不从字典自动补写成报告原文。原文为空或破损无法辨认时可保留问题，不能为通过校验随意填写。
- 对多识别或重复识别的项目提供“排除此项”，选择相应原因并支持恢复。排除是保留历史的有效性决定，不物理删除原始识别和原图。
- 医院、采样时间、报告号等报告自身信息在同页修改。采样时间不能用打印时间、报告时间或上传时间代替，也不能补出原件没有的时分。
- 原图来源、页码及字段位置由页面自动带入；通常的按原文更正不要求用户反复手填同一段依据。本页不作报告归属决定。

## 6. 保存与整份确认

固定操作区提供“保存修改”“确认本报告”“确认并下一份”。确认动作包含保存当前编辑，避免用户先保存再确认的重复操作；纯保存不会把本报告标记为整份核对完成。

| 情况 | 行为 |
| --- | --- |
| 保存修改 | 原子保存本次合法编辑、补录和排除，保留待核对状态；错误时定位问题并保留输入 |
| 确认本报告 | 校验并保存当前编辑，记录用户已对照全部来源核实准确性和完整性，留在当前报告 |
| 确认并下一份 | 只确认当前一份，成功后在当前页面切换下一份；失败留在本报告，不自动确认后续报告 |
| 切换或离开且有未保存编辑 | 提示保存、放弃或继续编辑；不静默丢弃 |
| 已确认内容再次修改、补录、排除/恢复或来源范围变化 | 原确认留在历史；当前内容需要重新确认，不继承过期的整份确认 |
| 未解决的识别错误、来源归属或修订冲突 | 可以保存已核对内容，但不能显示整份已完成；同页指出剩余问题 |

确认前简洁展示本报告当前保留的指标数、排除数、来源页数及待处理问题。系统统计不能宣称知道原图本应有多少项；“完整性”来自用户对照原件后的整份确认，不由“现有指标全部已确认”推断。

原报告确实缺少计算所需信息，与转录是否准确完整分开。可以如实核对原件内容，但不得虚构缺失字段，也不得因整份确认绕过现有接纳、比较、趋势或派生计算规则。目录外项目不是禁止保存原文和确认转录的理由。

历史有效单项确认保留，不删除、不改写。新整份确认必须绑定当时的报告来源、字段、人工补录、排除状态和结果版本；历史单项确认本身不证明没有漏页或漏项。

## 7. 数据与服务约束

本节确定实现必须满足的合同，具体迁移和函数拆分由后续实施计划细化。

### 7.1 统一读取与人工条目

在 `apps/labs` 内建立核对页的报告读取和提交服务，复用报告身份、关联读取、原件读取及现有修订事件。核对页按报告来源集合读取，包括低置信度、无效、待处理、已排除和人工补录条目；普通对比、趋势及输出继续使用一致的有效结果投影。

采用以下最小数据扩展，不另建一套检验结果系统：

- 人工指标仍使用 `LabObservation` 和 `SourceEvidence`，增加可跨解析版本延续的人工条目身份及明确的人工来源；同一解析版本内同一人工身份只能出现一次。人工证据允许无 OCR block、置信度和精确框，不创建伪造的解析版本。
- 人工补录只关联当前已经明确的报告单元及原页；本页不创建人工报告单元。完全没有可用解析版本或报告范围时显示尚不能核对的状态，不能伪造解析版本或绕过来源合同补录。
- 在现有指标修订中增加排除/恢复状态和原因，并覆盖本次新增的可编辑原文字段；沿用不可改写的历史事件。
- 新增单份报告核对事件，保存作者、完整来源清单、实际保留指标、排除决定、报告信息及最终版本指纹。旧批量确认记录保留为历史，不仅凭其数量摘要生成完整性结论。

人工条目必须有稳定身份、所属患者、报告来源、原页/区域、原文内容、作者和创建依据。不能只向某个解析版本插入一条结果便视为完成：切换/重新识别后，即使新版本仍漏识别，也必须可在当前报告核对页找到原人工补录及其历史。

新识别与人工条目唯一对应时保留一个有效项目及来源链；对应不唯一、报告区域变化或结果冲突时，进入同页待处理区，不自动覆盖人工内容，也不静默生成双份有效结果。历史解析结果仍按相应版本读取，不能把当前编辑回写成旧版本的原始识别内容。

排除状态必须进入共享有效结果读取，不能只在核对页隐藏；对比、趋势、导出和分享的实时有效结果应一致排除，恢复后按现有规则恢复资格。原始识别、来源和审计历史继续保留。已有静态分享/导出的有效性沿用既有修订与撤回规则，不越过选定范围重建快照。

补录及更正后的解析值、类型、标准匹配、参考范围与质量状态必须从有效内容重新计算；不能保留与新原文矛盾的旧缓存。手工输入的依据明确标为人工转录，不能伪造 OCR 置信度或自动来源。

### 7.2 一次提交与权限

统一提交服务一次只接收当前一份报告的字段编辑、指标修改、新增、排除/恢复和可选的整份确认动作。服务端也拒绝一次请求多份报告及跨报告指标，不能只靠前端取消多选。沿用患者写权限及既有锁顺序，校验所有来源确实属于当前患者和当前明确报告范围。

提交带报告、来源、结果及关联的版本指纹和操作标识；在锁定后复核，避免识别版本切换、其他窗口编辑或报告归并变化时写入旧内容。相同操作重复提交不重复补录或生成确认记录；相同标识但不同请求拒绝。

确认提交中任何校验失败时整体不确认，不出现“部分保存却显示整份成功”。普通保存也采用本次提交整体成功/失败的规则，出错保留输入并定位。若其他既有流程改变了报告归属关联，本页提交旧指纹时拒绝写入并提示重新加载，不在本页处理关联关系。

当前报告的变更保留作者、时间、前后内容及原件依据；撤销/恢复追加历史。VIEWER 只能查看，旧 URL、伪造患者/页码/指标 ID、已取消的任务授权、资料删除及后台权限变化均不能绕过写入或读取范围。

## 8. 验收场景

| 编号 | 场景 | 可验证结果 |
| --- | --- | --- |
| AC-01 | 从检验工作区、结果数值、资料详情及旧单项地址进入 | 同一核对页/组件，定位正确报告和指标，患者范围及合法返回筛选保留 |
| AC-02 | 扫描普通患者页面及提交旧批量、单项更正/确认、报告信息表单 | 无平行内容确认表单；这些旧提交不产生业务修改并指向统一入口；报告关联管理未被错误停用 |
| AC-03 | 一份报告多页、重复来源、同文件多报告及同页多报告 | 完整展示本报告全部来源，零指标续页可见，不误纳入其他报告 |
| AC-04 | 已有报告单元但零指标，以及完全没有报告单元的资料 | 前者可在当前报告补录；后者显示范围未定、不能确认；本页无创建报告或归属管理操作 |
| AC-05 | 对比页仅选少数指标后打开核对页 | 仍展示本报告全部指标，原图顺序与来源关联正确 |
| AC-06 | 连续修改多个指标/字段及报告信息 | 同页一次保存，重新进入后有效内容及原始来源、历史均正确 |
| AC-07 | 补录数字、比较符、阴阳性、半定量及目录外项目 | 原文不丢失，标准匹配不伪造，同一提交重试不重复创建 |
| AC-08 | 原图未提供单位/范围或完整采样时间 | 不自动补成原文、不强迫编造；现有接纳与计算限制仍成立 |
| AC-09 | 排除误识别/重复项并恢复 | 核对页状态和历史准确，对比、趋势、实时输出遵循相同有效性规则 |
| AC-10 | 保存后离开、确认、确认并下一份 | 保存不等于整份确认；确认含当前编辑；仅当前报告成功后在本页显示下一份，其他报告不被确认 |
| AC-11 | 仍有识别、归属或版本冲突 | 留在同页，可保存其余内容；不显示整份已确认；输入不丢失 |
| AC-12 | 已确认后修改、补录、排除/恢复、改变报告来源 | 当前整份确认失效，旧记录保留，重新确认覆盖实际最新内容 |
| AC-13 | 既有重新识别流程仍漏掉手工项目、识别到同一项目或产生歧义 | 手工内容可恢复读取；无静默丢失/双计数；本报告内容冲突同页可处理，归属冲突仅提示、不能确认 |
| AC-14 | 切换历史解析版本 | 原始识别和历史修订按版本展示，当前整份确认不套用到历史或新冲突内容 |
| AC-15 | 两窗口修改、解析激活竞争、重复点击、提交失败 | 拒绝过期写入，无重复补录或确认，无部分成功误报 |
| AC-16 | VIEWER、跨患者请求、删除原件、权限变化 | 无越权读取或写入；不因统一入口扩大原件与报告可见范围 |
| AC-17 | 桌面及手机实际浏览器操作 | 原图可读可定位，多页切换正常，修改期间不丢输入，键盘与错误定位可用 |
| AC-18 | 非检验核对、已有分享、导出、历史对比 | 未被改为新编辑入口，保持既有范围与行为；有效检验结果与本次修订一致 |
| AC-19 | 授权复核旧页面、API、source/image、未过期任务、已有权限、旧通知及字典候选来源支路 | 均不能凭旧任务创建/执行复核或读取来源，无入口残留；旧授权不成为患者或字典来源访问权 |
| AC-20 | 授权复核功能取消后读取此前已完成的更正及历史 | 有权患者用户仍可查看有效结果及修订历史，无历史数据删除或结果回退 |
| AC-21 | 核对页控件检查、伪造多报告请求和连续切换报告 | 只有当前报告核对所需内容；无批量、报告管理或其他功能；服务端拒绝跨报告提交，切换不丢未保存输入 |

实施验证应包括服务/视图回归、人工条目重解析与版本切换回归、真实 PostgreSQL 并发与事务验证、桌面/手机浏览器主流程，以及检验对比、趋势、导出、分享和授权复核下线的相关回归。文档校验不能代替功能验收；本规格不声称上述测试已通过。

## 9. 与既有规格的关系和交付流程

本规格经评审生效后，取消[筛选与报告批量确认](2026-09-26-lab-comparison-selection-and-batch-confirmation.md)中的 R3 跨报告批量确认，改为本页逐份确认；调整 R2 单项核对目标及相关验收，保留分类筛选与原有来源展示规则。报告身份、原件、采样时间接纳及归并规则继续遵守[报告归并规格](2026-09-17-lab-report-consolidation.md)，本页只消费已有明确报告范围，不迁入报告关联管理。

按用户要求取消[第二阶段规格](2026-09-06-phase-two-requirements.md)的 P2-05 授权复核工作流，调整 P2-04 的患者核对入口以及 P2-06 对旧任务授权的依赖；已保存复核结果的来源连续性仍按 P2-09 保留。取消功能不改写此前已经发生的交付与验证事实。

本规格已作为本次实施依据，不把已有规格整体标为失效，不改写历史交付与验收事实。功能开发从最新 `origin/main` 创建独立功能分支和 worktree。

实施计划须逐项对应本规格验收，输入校验及缺陷先有失败测试，完成后进行独立审查和规定验证。提交与合并使用[本地 submit](../policies/local-submit.md)，版本由 Release Please 确定，不手工预填版本，不自动部署。任何新增文档及状态变化同步更新文档总索引和登记表。
