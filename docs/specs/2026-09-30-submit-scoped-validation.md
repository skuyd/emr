# submit 按影响选择验证范围

## 目标

用户手动调用 `$submit` 后，按候选相对主线的实际差异执行足以验证受影响行为的检查，避免小改动自动运行全量业务回归。计划在运行前列出测试目标、选择理由、建议全量的原因及未覆盖范围。验证结果只证明实际执行或有效复用的范围。

## 范围判定

- 普通文档、登记表、静态验证记录以及 `prototype-gallery/screenshots/` 内的静态设计截图，执行文件与既有文档治理检查，不准备业务测试环境。文档中的评估输入、脚本和生产镜像输入不能按普通文档处理。
- 原型 HTML、CSS、JavaScript 和原型测试运行原型自身相关测试，不触发业务全量。应用实际加载的 `static/`、`templates/` 不按原型处理。
- 前端样式、模板和 JavaScript 运行受影响页面的 UI、无障碍、JavaScript 或浏览器测试；共享样式扩大到受影响的共用页面。
  页面名、模板加载的资源和测试中的文件名引用共同补足页面覆盖，包括分段 `Path` 引用；首页明确包含 shell 浏览器测试。删除资源或模板仍按原路径选择相关测试。选择器自身的测试夹具不作为页面消费者。
- 单模块功能运行该模块测试以及明确的调用方、集成、浏览器和数据库测试。多个模块取这些目标的并集，不因模块数大于一而自动全量。
- 配置、依赖、数据库迁移、权限和共享基础代码按实际影响追加专门检查；影响不能可靠界定时建议全量，同时保留可确定的相关测试目标。无法确定任何相关测试，或测试选择为空时停止，不能用文件检查冒充功能验证。
- Linux 配置和依赖专项排除已知仅支持 Windows 的启动器测试，同时明确记录这一覆盖缺口；Linux 全量也不能补足该平台验证。直接修改、删除或重命名 Windows 启动器及其测试时停止，不能用其他 Linux 测试代替。其余必跑测试跳过仍失败。
- 混合变更合并所需检查。删除、重命名、文件模式变化和新文件均参与影响判定；未知输入停止并列出路径，不静默选全量或缩小范围。

## 全量选择与证据

建议全量时，`submit` 在运行重测试及推送前暂停，让用户针对当前候选选择运行全量或只运行相关测试。选择绑定候选提交和验证计划；候选或主线变化后重新判断。用户选择相关测试继续时，只有所选检查真实通过才能合并，并将建议全量的原因、未覆盖范围和用户选择写入验证凭据及结果摘要。该凭据不得表示业务全量通过。检查失败、全部跳过或空集合均不能通过，也不能自动改用另一范围掩盖失败。

验证凭据绑定精确候选源码、测试目标、命令、验证策略、环境和产物摘要。只有这些条件匹配才复用；不同测试目标不能共用同一通过结果。

## 发布阶段

发布候选只含允许的版本字段、Changelog 和已识别文档变化时，沿用仍有效的功能验证凭据，不重跑业务测试。每次真正发布新版本仍构建生产镜像并执行启动 smoke。若主线相对已验证功能基线新增业务差异或原凭据不可复用，重新展示受影响范围；不得自动运行全量。主线只有文档差异且没有可证明的业务凭据时停止，不能用文档检查冒充业务验证。发布 PR 自身含不允许的业务差异时也停止。发布凭据保留功能阶段的覆盖范围和未覆盖风险，不将专项验证改记为全量。

## 成功后的工作区清理

用户确认 `submit` 的全部前序步骤成功后，自动删除本次本地开发分支、同名远端开发分支及对应独立
worktree；无需发版时在确认无需发版后执行。未完成的验证、合并或发布保留工作区供恢复。
删除前核对已合并提交、本地与远端分支 SHA，以及工作区文件；新增提交、未保存文件或私有资料
会阻止清理。主工作区和其他任务不删除，Git 公共目录中的状态及验证证据保留。清理中断可以单独
恢复，不重跑测试或发布，也不删除已完成清理后新建的同名分支。

## 可验证结果

临时 Git 候选覆盖文档、静态设计资料、原型行为、局部与共享前端、单模块与跨模块、配置和迁移、混合与未知路径；各计划的精确命令与实际执行组一致。验证恢复、发布复用和用户选择均受候选身份约束。临时仓库验证成功后清理、失败保留、新提交及本地资料保护、清理中断恢复。仓库策略、`$submit` 技能说明和执行器行为一致。正式发布和生产部署不属于本任务。
