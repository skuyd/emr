# 治疗方案、周期与派生输出设计

本规格细化[后续五批需求](2026-09-07-batches-one-five-requirements.md)的 B4-01、B4-02，
以及 Task 8 尚缺的选定速查/结构化导出。已有 B4-03 [个人变化读视图](2026-09-08-personal-trend-comparison.md)
继续复用，不改变已发布公式。按[本功能计划](../plans/2026-09-08-treatment-cycles-and-derived-exports.md)实施，
当前为 active / implementing；五批总状态不因单项设计或合成回归而变成 verified。

## 范围与当前基础

当前治疗数据是 `apps/facts/` 的 TREATMENT 摘录，保留 text、日期精度、多个日期和人工修订。
本功能增加方案、事件、自动周期提议及全套确认决定，不把既有摘录直接当作已执行给药事件。
独立新域依赖已合入 main 的患者权限，统一报告/自记录接口在相应功能合入 main 后接入。

## 全局契约

- 原件、自动来源、人工更正和当前投影分别保存。未知日期不补齐，不从医嘱、计划、住院或检验谷值
  直接断言实际治疗；没有依据不生成治疗结束、风险等级、疗效判定或用药建议。
- 所有服务显式实际 actor，按 READ/WRITE/EXPORT 授权；撤权、来源修订、生命周期、退出和删除
  影响页面、派生数据与下载。原件/导出沿用流块前后的权限重验。
- 先冻结完整授权范围的真实标注，经独立原件审阅后才运行预测；合成与真实质量分别报告。
- 新功能从最新 origin/main 建独立 worktree；不以未合并分支为基础，不修改私有部署资料或应用版本字段。

## 方案选择

推荐独立 `apps/treatments/` 域，引用现有 Fact/SourceEvidence 和未来已合并的 ClinicalReport 来源。
不把周期复合关系塞进 Fact.text，也不复制一套 OCR/报告/检验模型。这样 B3/B5 的共享导出可按 main
顺序接入，治疗关联和修订有自己的迁移与服务边界。

候选由纯函数从当前有效来源自动生成，治疗页面无需先手工录周期。GET 只计算/展示，不产生写操作；
确认、纠正、拒绝等 POST 在锁内重新校验输入指纹并持久化本次自动基线与决定。批量提议可显式 POST
保存整个分析批次，按同一输入指纹幂等。无需为本轮引入另一个后台任务状态机，也不修改 OCR 管线结构。
来源更新会自然产生新的只读候选；有用户决定的旧输入仍保留历史，失效决定不能覆盖新来源。

## 用户流程

1. 资料页保留“按时间”，增加“按治疗周期”。同一资料集合改分组；现有搜索/日期/分页作用于同一集合，
   所有入口和 GET 表单显式保留 patient。提供治疗方案/周期管理及周期叠图入口。
2. 首次读取从现有治疗摘录及严格绑定的住院日期证据自动给出方案组和周期提议；卡片显示原文来源、
   实际/计划/未知发生状态、日期精度、推断依据、冲突和“尚待确认”。没有提议也显示输入范围与原因。
3. 创建者/管理员/协作者可对照原件确认、纠正、合并、拆分、拒绝；只读成员可以查看，不能决定。
   纠正必须区分“更正摘录/关联”和“本人补记实际治疗”。不暗中确认原 Fact，不改变原件。
4. 方案→周期→检查三级展开；未归组、日期不明、边界歧义和全部原始资料保留独立区域。
   已拒绝和已被合并/拆分替代的对象保留历史，但不在默认曲线当作有效锚点。
5. 叠图默认确认且精确到日的周期；用户可以显式预览未确认候选，标题和每个锚点持续标明候选。
   按方案分别显示，不把不同方案拼成一条周期序列。ANC/PLT/HGB 各自数轴，每个可比子组独立。
6. 速查/导出选择页可勾选治疗事件、方案、周期、关键节点/完整明细和个人变化，并先展示实际来源依赖。
   默认已确认有效内容；待确认提议只有显式选择才进入明确标注的附页/结构化区域。

## 来源、事件和模型

拟新增模型（字段名称可在实现中按 Django 约定细化，但下列身份/约束必须保留）：

| 模型 | 必需字段与关系 |
| --- | --- |
| TreatmentRegimen | UUID、patient、原始方案文本/规范化匹配键、发生段标识、初始候选载荷、revision_number；重复方案在中间有明确换方案时为不同发生段 |
| TreatmentEvent | UUID、patient、origin、初始结构化载荷、提取规则版本、来源信号唯一键、revision_number、实际创建作者；手术/放疗/药物/住院/出院/暂停/延迟/停止/评估节点分别分类 |
| TreatmentEvidence | event、document/page/version、Fact 或明确的 SourceEvidence 引用、来源/修订/生命周期/material 指纹、原文片段起止；人工自述用独立 USER 来源，不伪造报告来源 |
| TreatmentCycle | UUID、patient、regimen、原始提议载荷、可空原文周期序号、锚点及精度、状态、revision_number、derivation_run；组织边界与实际治疗结束是不同字段 |
| CycleEventLink | cycle/event、ANCHOR/CONTEXT/PAUSE/ASSESSMENT 等角色及来源指纹；同一患者与当前来源验证，不跨患者关联 |
| CycleRecordLink | cycle 与 document/report/observation 三类来源中严格一项、origin、当前来源指纹；保留人工检查归属更正，不能只改当次页面分组；报告 FK 在 B3 合 main 后接入 |
| TreatmentRevision | 实际 author、operation_id、目标 regimen/event/cycle 三者严格一项、sequence、action、before/after、checked_original、source_tokens、时间；追加不可覆盖 |
| CycleLineage | 合并/拆分前后的周期、operation_id；同患者，禁止环和复活已替代对象 |
| TreatmentDerivationRun | patient、规则版本、完整输入指纹、来源清单哈希、requested_by/access_revision、结果计数、创建时间；不重复存医疗全文 |

可查询的当前字段是修订事件的投影，事务内同时更新；历史 before/after 永远与自动基线分别保存。
约束：同一 source signal 幂等；目标修订序号唯一；CycleEventLink/Lineage 不越过患者；合并和拆分事务
必须逐项验证所有 expected_revision，任一冲突整体 409。方案相同但周期序号重复的矛盾保留，不能加唯一
约束后静默吞掉第二条来源。序号仅是原文或明确更正，不用显示排序号冒充 C1/C2。

当前源读取规则：有效 Fact（含当前 PENDING 但标为候选）可用于提议；EXCLUDED、来源不可用、旧解析
或被撤销的来源不能成为有效输入。DEFERRED 不主动重新提议。原始药疗医嘱中的“开始时间/执行状态/
停止时间”分别保留语义，不能把医嘱停止推成整个方案结束。多个日期须按同句/同行角色关联。

自动分割不跨 Fact/报告/原文段落边界；提取片段保存 Unicode 起止位置和原件区域，缺乏区域只回到页。
跨多份文件的同一次治疗可以形成一项提议并关联所有来源，但每个字段的依据不可被总体置信度替代。

## 自动提议规则 v1

`extract_treatment_signals(material) -> immutable signals` 与
`propose_cycles(signals, comparable_lab_context) -> proposals, exclusions` 都是无数据库写入的确定性函数。
不得调用人工周期标注或预测输出；所有阈值与规则身份写入可版本化常量和评测指纹。

1. 提取明确“第 X 周期/疗程”、C3D1、C3 D8 等；中文/阿拉伯序号规范化。范围、冲突、D0 或不合法
   序号给出歧义/无效原因。精确发生日期 + 明确 Dx 才可计算 `anchor = event_day - (x - 1) 天`。
   单有文书日期、计划日期或不完整发生日期不能作此推算；推得锚点仍是待确认的派生候选。
2. 方案分组只使用同一上下文明确的名称/药物组合，做 Unicode、空白和标点等文本规范化；不引入未经
   审查的药物等价字典，不把同药名的不同组合静默合并。未知方案进入待确认组。明确切换创建新发生段。
3. 缺序号时，同次明确治疗/同一住院区间的多条记录聚为一个候选锚点，保留原始事件。实际治疗日期
   优先于住院日期；只有住院线索时标为“住院线索锚点”，不能称为已发生化疗，也不自动填真实 C 序号。
4. 同方案存在至少三个独立精确治疗/住院锚点时，用实际间隔中位数和离散程度描述重复间隔。第一版
   相近间隔条件为偏差不超过 `max(2天, 中位间隔×20%)`，只是候选算法，不是任何方案的医学周期长度。
5. 周期性辅助使用同一可比组至少三个可验证局部最低节点及其实际间隔；节点必须由至少两个不同日期
   的邻近有效数值夹定，同日多值、比较符、特殊结果和不可靠来源不参与。只有与已有治疗/住院锚点
   的重复间隔相容才增加“检验变化呈相近间隔”依据，不从最低值创造治疗日期、不预测未来治疗。
6. 暂停、延迟、停止/完成仅来自明确原文或用户记录；缺药物后续记录不代表停药。明确暂停/换方案
   会打断自动聚类与辅助周期性。长间隔本身仅显示实际间隔，不填“延迟治疗”结论。
7. 冲突证据全部保留。相同源证明和规则版本下拒绝的提议不反复弹出；来源或影响分组的上下文改变
   才产生新输入身份。若旧决定的必要来源/边界改变，转为需复核，不能直接迁移为已确认。

## 决定及有效性

- CONFIRM：要求 checked_original 与精确来源指纹；仅确认当前载荷，未明日期仍不能成为默认叠图锚点。
  PLANNED/NEGATED 来源不能经简单确认变成已发生；需单独用户更正发生状态/日期并记录为本人补记。
- CORRECT：方案归属、周期序号、明确锚点、日期精度、事件类别/发生状态可改，完整保存前后与作者。
- MERGE：同患者的多个周期选择来源集合和冲突解决结果；旧周期 SUPERSEDED，新周期保留所有 lineage。
  冲突日期/方案不能取平均；用户必须明确选择或保留未知。
- SPLIT：显式将事件与检查来源分配给新周期，可留未分配；禁止复制无依据的实际序号/治疗日。
  原周期被替代；所有子周期独立锚点/精度与来源。重放提交只产生一次决定。
- REJECT/REVOKE：只改变候选或确认状态，不删原件/Fact；撤销确认后默认叠图与旧导出立即失效。

所有决定使用 Patient → 有序 UploadBatch → Document → 有序治疗对象的既有锁顺序；重新读取实际
actor 与来源后写入 FK/修订。保留现有账号删除 `Account FOR NO KEY UPDATE` 语义，PG 验证作者 FK
写入与账号注销不存在等待环。GET 构建使用一致的不可变 material；返回前复验 READ，来源指纹变化
不把旧候选呈现成当前结果。POST 以事务提交为线性化点，不在提交后泛化重验而误报失败。

## 周期组织、相对天及关键节点

- `build_cycle_timeline(material, selection)` 在原资料集合上建立引用关系，不搬动、去重或删除 Document。
  检验用有效 observation 日期，多报告资料在 B3 已合并的报告边界内使用报告日期；未知/混合日期
  不能用整份文件上传日归组。一份文件可因其中不同报告在多个周期出现，但原件集合仍可完整查看。
- 默认组织区间为当前精确锚点（含）到下一同发生段锚点（不含）；这是展示分组，不是治疗持续/结束
  断言。末周期明确标为边界未闭合，展示截止所选范围/最近记录；跨方案、暂停、同日两个锚点和
  日期不明的边界进入歧义区域，不静默择一。用户可显式修正关联，保留原自动关联与理由。
- `relative_day = observation_day - confirmed_anchor_day`，保留负天数。原文 C/D 保留原字段，显示
  D1 对应距锚点 0 天。实际间隔控制横轴；未测日期不补零，不按条目序号等距。
- 每个 ANC/PLT/HGB 的现有 comparable_cell.group_key 单独数轴；不可比记录仍在完整数据表说明原因。
  同一天多条独立点全部保留，在该日断线，不平均，不按 UUID 赋予临床先后；不同方案不连线。
- 关键节点默认模式包括：锚点之前最近的可比日（同日全部）、每周期实际观察到的最低值（并列全部）、
  报告明确评估节点或用户明确记录、最近可验证记录（同日全部）。标签是实际选择依据；不是预设 D8/D15
  谷值或疗效结论。锚点同日没有时刻时不能称为治疗前；无足够依据就保留缺失原因。
- 完整模式恢复所有符合当前筛选的来源点与不可绘制清单；切换不会修改或省略原数据。图提供可读表格、
  标题/单位/图例、键盘来源链接，窄屏内部横滚；每点回原件或用户补记历史。

## 选定速查、导出及分享契约

保留 `build_snapshot(patient, selection, *, now=None)` / `assert_snapshot_current(patient, snapshot)`。
新增 `apps/exports/treatment.py` 提供独立 material/fingerprint/projection；B3 的 clinical_* 数组不改名。
结构化 schema 在按最新 main 集成时递增兼容 MINOR（数据 schema，不手工改应用发布版本）。

- 选择字段：treatment_event_ids、regimen_ids、cycle_ids、cycle_metric_codes、cycle_mode（key/full）、
  personal_change_ids（observation UUID）、include_pending_cycles。缺省为空/false，旧选择不意外增加资料。
- 新数组：treatment_events、treatment_regimens、treatment_cycles、cycle_links、cycle_points、
  cycle_key_nodes、personal_changes、derived_sources。各含稳定 ID、origin/status/revision、规则版本、
  日期精度/原始日期与必要来源身份；缺失用 null+reason，不用 0。继承 CSV 公式防御与关联 schema。
- personal_changes 精确复用 changes_for_cells，包含 previous/baseline 三条来源 ID、实际天数、
  absolute/daily/previous_percentage/baseline_mean/baseline_percentage、阈值/提示和缺失理由；
  不把 UI 格式化后的两位小数当原始精度。近三次不含当前/未来、重复日期和比较符等限制不改变。
- 派生选择必须闭合来源范围。勾选某周期但缺其锚点资料、选某变化但缺此前基线资料时，准备页列出需要
  另行选择的资料；不暗中扩展 document_ids。若用户保持局部范围，受影响值输出 null/缺少已选来源，
  不泄露未选基线值、ID、日期或均值，不在缩小范围后悄悄换一组“前三次”。
- A4 一页正文显示用户选择的确认治疗节点/个人变化摘要；更多节点沿既有允许附页规则完整呈现。
  未确认周期明确放在候选附页，不混成已确认治疗。HTML/PDF/JSON/CSV 同一冻结快照、同一筛选。
- `dependency_fingerprint` 加入完整治疗输入及决定状态，来源变更/新边界/确认撤回/规则变更使旧导出
  失败并要求重新生成；所有来源锁、requested_by、session、worker 发布前和流块前后检查继续复用。
- 在线分享的新派生部分仅在明确选择时投影；cycle/event/change 等细选视为 PARTIAL，禁止完整原件。
  不复制未选基线、病例全文、原文上下文/普通来源 URL。新增 projection 与 source fingerprint 的回归
  覆盖同文档未选字段、同患者未选资料和跨患者 ID；分享资格不进入普通治疗入口。
- B5 的无文档自记录导出使用显式 self_record_ids 与独立 self_records 数组。本域独立用户补记通过
  显式 treatment_event_ids 接入已合并的有效独立源判断，缺省为空；不能伪造 Document，也不覆盖自记录数组。
  选择至少一份文档或一个有效独立源即可形成快照；来源修订与删除用真实关联立即使旧派生访问失效。

## 删除、审计和竞争边界

patient/owner 注销级联清除治疗实体与含医疗内容的修订；只注销成员不会误删患者数据，作者 SET_NULL
并保留已有实际操作审计。文档回收站/重解析/Fact修订/报告边界改变使必要依赖失效；恢复不复活旧确认。
物理删除文档时清除依赖它的自动事件和相关派生快照/决定中的医疗载荷，不能只删 Evidence 行而留下
可读周期内容。独立无文档用户补记按患者删除规则处理；审计只保留既有不含医疗正文的哈希事件。

新增 audit action/resource/route 映射覆盖治疗查看、提议、确认/更正/合并/拆分/拒绝、来源/导出和拒绝结果。
精确 entity→patient 解析；GET/HEAD immutable route 白名单回推患者，显式患者范围仍优先，POST 不隐式切患者。
不逐图点/流块生成海量审计；一个实际请求/决定记录真实结果与 operation_id。

## 真实质量与验收

真实开发评测保持已授权的 64 文件/124 页全部范围，原件及原始 OCR 哈希逐项核验。
定位清单 SHA256 为 `e354c060a349f9dd718d2879ab2ded2b806b3154b2f2353fc9de154b68c0cbf0`；
公开仅统计和哈希，测试/CI 不依赖私有原件或标注存在。

确认患者分组；不同患者绝不拼接周期，身份未明留待判断。分组只模拟真实上传所属患者，不作为治疗答案。
