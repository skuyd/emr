## 1. 用户路径与范围

用户在影像报告或资料详情找到“云影像来源”：系统列出报告明文地址、本地识别出的二维码，
以及无法判断归属或无法解码的状态。用户查看原页及来源区域，确认、改正、排除或重新补录。
确认后的入口先说明外部站点和访问性质，再由用户主动打开。医院的登录、验证码和影像展示
由医院完成；本系统保存来源与核对记录，不保存或抓取外部影像。

普通患者读者可查看核对结果和打开已确认入口；编辑者及以上拥有 WRITE 权限，才可提交
确认、更正、排除、归属及撤销决定。家庭管理者
可把明确勾选的云影像来源加入限时分享。分享读者获得该入口的有限访问资格，不获得患者
成员资格、普通资料详情、整份原件、其他链接或来源历史。

本次不加入远程二维码服务、付费识别、网站登录代理、服务器代取影像、健康探测或下载镜像。
“当前来源有效”表示本地资料和核对身份仍有效，不表示医院网站现时可用。

## 2. 现有基础与必要补充

`Fact` 的 `FIELD` 表达和 `FactSourceFragment` 已支持原始 OCR Unicode 区间与人工转录。
后者目前只允许 `OCR` / `MANUAL`：二维码结果没有 OCR 字符偏移，人工来源又不能带伪造的
OCR 坐标。不能把二维码文本塞入现有片段并冒充 OCR 来源。

`ClinicalReport` 提供同文档报告范围；`report_state` / `report_source_token` 提供当前版本、
范围与生命周期身份。`DocumentPage`、本地原件渲染以及 `processing.geometry.source_polygon`
提供原页和几何基础。现有 OpenCV 依赖有本地二维码检测/解码能力；设计阶段只检查本机接口，
没有识别真实二维码或访问任何外链。

新增独立 `apps/cloud_imaging/`，把外部访问来源作为专门资源，与报告通过真实 FK 关联。
报告页增加来源分区，不把带访问参数的 URL 新增为普通临床 `FIELD`。这样可保留二维码的
独立证据类型，并避免普通影像章节或报告字段投影自动携带新的访问秘密。

仅分离新模型还不够：既有报告摘录、字段上下文可能已经含明文链接。第一个 PR 就必须
建立默认输出边界，在普通结构化内容中省略外部访问串及包含它的未选来源上下文，说明
已省略访问内容；不能等第三个 PR 才处理这条旁路。用户明确选择完整原件时，原页本来可能
含链接和二维码，应按现有整份原件授权和提示处理，不声称可以从原件中撤回这些信息。

默认省略仅发生在输出投影，绝不改写原始 Fact、OCR、私有来源证据或已确认字段。私有
原文仍可在具备对应患者权限的核对页面查看；省略后的输出不能回写为新的原文或修订。
默认保护采用明确的投影合同：对将要交付的患者内容字符串检查绝对 HTTP(S) 访问串，
不要求候选已经确认或持久化才生效。访问串只可出现在显式所选云来源数组/专门卡片段落；
普通摘录或文本字段中的访问部分用省略标记代替，包含它的核对上下文不输出原文，标明
`external_access_omitted` 并清空对应已省略上下文的 offset。结构化数值和临床文字的其余
内容保留，不伪称省略后的串与原件逐字相同。技术元数据中由服务端固定转换规则产生的
公开依据 URL 单独允许；该白名单只接受服务端实际确认的固定规则 URL，不能由来源内容、
字段名称、用户输入的规则身份或同名 JSON 键建立例外。

旧输出的每个实际消费入口均执行同一访问串规则，覆盖预览 HTML/PDF、队列 worker、
生成后发布、实际下载首字节和每块、分享投影与渲染。含访问串却没有明确来源许可的旧快照失效并
清空，提示重新选择，不允许旧 schema 绕过新边界。已由用户下载的历史文件不改写；旧
可移植格式的读取兼容性也不据此删除原文件中的数据。保护规则身份进入私有依赖指纹。

## 3. 数据模型与不变关系

前四个模型已在 PR 1 实现，输出绑定模型仍属 PR 3。所有患者、文档、页、报告关系在服务和模型
校验中验证，不能接受只在页面中筛选的跨患者输入。

| 模型 | 必须保存的内容 | 约束 |
| --- | --- | --- |
| `CloudImagingScan` | UUID、患者/文档、请求者、原件/页集合指纹、扫描规则与解码器版本、幂等键、状态、完成摘要 | POST 发起；只在扫描输入仍为当前状态时发布候选；失败不清空旧扫描 |
| `CloudImagingEvidence` | UUID、扫描、文档/页、可空解析版本、类型、原始访问内容、内容哈希、原页身份及具体证据 | 追加后不可覆盖；OCR、QR、人工证据使用各自合法字段；内容属于敏感私有字段 |
| `CloudImagingSource` | 稳定 UUID、患者、文档、当前证据、可空报告、状态、当前 URL、站点摘要、实际创建者/更新者、修订序号 | 来源证据和报告归属的改变只能通过修订；状态包含待核对、已确认、已排除、来源过期 |
| `CloudImagingRevision` | source、唯一 sequence、实际作者、决定、前后状态、证据/报告/URL 身份、预期来源令牌、幂等键 | 追加审计；不能覆盖旧原文或把人工改正当作自动解码 |
| `CloudImagingExportSource` / `CloudImagingShareSource` | 输出对象与来源的真实 FK、冻结修订/来源标识 | 第三个 PR 接入；绑定缺失或范围不一致时拒绝整个旧输出，不静默缩小范围 |

证据、修订与当前值的原始 URL/二维码内容只保存在本患者受控的私有数据中，不进入对象
`repr`、默认管理表格、审计备注、异常文本或公共验证制品。公共身份只用不含原文的哈希。
不在通用 `clinical_fields.content` 或 `SourceEvidence.source_text` 中再复制二维码载荷。

当前来源证据及每条修订绑定同一文档；改成另一份资料需建立新来源，不能重用旧 UUID 冒充
同一原件。报告归属须属于同文档并覆盖对应原页。旧证据和修订通过引用保留；患者或文档
硬删除时按其聚合级生命周期清理，账号注销只把实际作者 FK 置空，不删除其他家庭记录。
物理级联与 `RESTRICT` 的具体组合必须用真实历史迁移和硬删除验证，不能只靠 `clean()`。

## 4. 明文、二维码与人工来源合同

### 4.1 明文地址

从当前 OCR 原始字符串识别完整 HTTP(S) 候选，保存实际 `OcrBlock`、页、原始 Unicode
`[start, end)` 与截取文字，并复用真实原页几何。去掉外围标点只能在可证明的地址边界进行，
保存实际选中区间；不把规范化字符串的偏移写回原始 OCR。

断行、多个拼接方式或无法唯一确定结束位置时保留待核对。人工补录可以补全地址，但必须
明确标为人工转录并指向真实原页；不能伪造机器已识别的字符区间。自动候选不因能通过
URL 语法校验就自动变为已确认来源。

### 4.2 本地二维码

PDF 的文字层页面也要按原页渲染扫描二维码，不能只扫描 OCR 选择为 raster 的页面。
图片遵守现有 EXIF 朝向和原页坐标约定。局部放大、旋转等尝试保存变换矩阵，检测四边形
经同一几何约定映射回标准原页；无法证明逆变换时保留页级待核对，不生成看似准确的框。

二维码证据保存：原件 SHA、页 UUID/页号及原尺寸、实际解码输入图像 SHA、渲染规格和版本、
OpenCV/解码器与规则版本、尝试变换、解码结果哈希、原页区域和结果类型。`ocr_block`、
Unicode offset 和 OCR `evidence` 都为空。载荷是 HTTP(S) 地址时仍要经过同一 URL 校验；
名片、纯文本、非 HTTP 协议等只记录不支持状态，不作为可打开入口。

同一次扫描的重复尝试可按载荷与实际区域去重；不同区域或不同报告的相同地址仍保留独立
证据。未解码、无二维码、页面处理失败和未判断分别计数，不能把失败页当作无来源。
扫描只读本地受控原件，不调用二维码内容，也不以第三方站点响应判断是否识别正确。

同一文档、输入指纹及规则的进行中扫描只能有一个；重复请求返回已有任务，不能靠换一个
客户端幂等键无限建立重复扫描。当前已完成结果可复用，失败重试保留原失败并创建明确
新尝试。每次请求及重试保存真实 actor；旧请求者撤权后不能借其他请求静默恢复旧 worker。
载荷超过支持长度时记录明确不可打开状态，不截断后当成完整地址。

### 4.3 报告归属与人工修订

同页只有一个明确覆盖该来源的当前报告时可预填归属，最终仍需用户核对。多报告、范围
交叠或二维码位于共同页脚时保持未归属，先显示在资料层；用户可关联到同页的具体报告，
或明确保留“资料级来源”。资料级确认不伪造一个新的临床报告。

决定包括确认、改正 URL/标题或报告归属、排除、重新补录和撤销最近决定。确认提交当前
来源令牌和预期修订号；冲突返回 409，显示重新核对提示。重复提交同一幂等决定返回同一
结果。更正生成新的实际作者修订，原扫描证据不改。恢复/撤销会增加修订号，不恢复旧导出
或旧分享的有效性。

## 5. URL 校验和受控打开

只接受完整绝对 `http` / `https` URL。必须有合法主机；拒绝 userinfo、反斜杠、控制字符、
换行和双向控制、脚本/文件/data 协议以及协议相对地址。显示有效主机的 IDNA ASCII 形式，
保留非默认端口；不把查询或 fragment 中的访问参数当作站点名称显示。

不对 path/query/fragment 做解码重排或截断后继续使用。校验失败应提示重新核对，不悄悄
改成另一个可打开地址。显式 IP 的环回、私有、链路本地及本机名称不作为医院外部入口；
不在服务器做 DNS、HEAD、GET 或重定向探测。该判断不声称验证域名实际归属于医院。

| 拟新增入口 | 方法 / 权限 | 返回前约束 |
| --- | --- | --- |
| `/records/<document_id>/cloud-imaging/` | GET READ；POST WRITE 发起扫描或人工补录 | 固定患者/文档；读后复验所显示来源、选项和作者；扫描不由 GET 触发 |
| `/cloud-imaging/<source_id>/` | GET READ；POST WRITE 决定 | 同一来源；原页定位只走既有患者权限；成功写入后按决定结果返回 |
| `/cloud-imaging/<source_id>/visit/` | GET READ | 仅显示已确认来源的站点、外部访问性质和状态，不把完整参数放进普通 href |
| `/cloud-imaging/<source_id>/open/` | POST READ + CSRF | 客户端只提交内部 ID、当前令牌/修订和患者范围；重新取受控目标，最终复验后交付导航响应或原生 303 |
| `/shared/<share_id>/cloud-imaging/<source_id>/visit/` | GET 精确分享授权 | 不使用家庭成员资格代替分享；只显示明确选定当前来源 |
| `/shared/<share_id>/cloud-imaging/<source_id>/open/` | POST 精确分享授权 + CSRF | 复查创建者资格、接收者登录会话、期限、来源选择和全部当前指纹，再读取目标 |

打开入口不接受任意 `url`、`next` 或来自 Referer 的目标。页面禁止缓存并设置
`Referrer-Policy: no-referrer`；新窗口隔离 opener，按钮必须实际点击才打开，预加载 GET
不能发出外部请求。医院最终地址出现在用户主动打开后的浏览器中是此功能的明确用途，
不能宣称这些已离开系统的访问内容可被本系统撤回。

浏览器脚本通过同源 POST 获取受保护的 200 空正文/Location 导航响应，禁止 fetch 跟随
外部重定向；只有最终来源检查通过后，才导航用户主动预开的空窗。空窗在异步操作前清除
opener 并设置 no-referrer，拒绝和网络错误时关闭。无 JavaScript 时明确禁用打开并保留
回原页入口。实际 TLS 浏览器证明 Origin 来自浏览器且仍被 CSRF 验证，不接受 Origin=null
来规避原生无 Referer 表单的限制。普通直接 POST 客户端仍使用同一校验后的 303。

审计动作区分扫描、核对决定、查看、打开已发起和拒绝。记录真实 actor、患者、来源 ID、
路由、request ID 与结果/稳定原因码；“已发起打开”不记为“医院页面成功访问”。审计、错误
报告和请求日志不得收集 URL、Location 内容、二维码载荷、原文、请求中敏感字段或其异常
局部变量。异常必须仍可定位到稳定原因码，不能靠吞掉整个故障解决日志边界。

## 6. 当前来源、授权与并发

来源令牌包含原件/页身份、解析版本（如有）、OCR 原词/位置或二维码证据、资料 material /
lifecycle revision、当前报告范围/修订、当前确认修订及实际作者状态。资料软删除、恢复、
重解析、原件替换、报告排除/替代、来源更正/解绑、作者匿名化和患者注销均使旧确认或输出
失效。恢复资料只恢复查看历史的资格；重新确认必须建立新修订。

所有域服务显式接收实际 actor。锁顺序复用当前主线：账号、患者、相关批次/文档，再到云
来源及其输出对象；患者读锁按实际主线已验证的 FK 兼容方式使用，不擅自升级为造成作者
清理死锁的锁模式。重采样/二维码解码放在锁外执行，发布阶段在锁内核对输入令牌、请求者
资格和任务身份；已经撤权或来源变化的 worker 不能发布新候选或恢复旧状态。

HTML 内容和表单选项在实际 render 后复验同一所显示依赖，变化时丢弃旧响应并提示刷新。
打开入口在交付重定向前复查；正常写决定在锁内完成，不因为后续状态变化把已提交成功
误报失败。选定导出的排队、构建后、存储发布、下载首字节及每块前后沿现有统一检查，
授权调用次数不产生重复访问审计事件。

## 7. 选定速查、可移植数据与限时分享

新增 `selection.cloud_source_ids`，默认空；普通 `imaging` 章节、文档或报告选择都不默认为
“允许外部访问”。单独选择来源可生成没有完整 documents 数组的速查/导出/分享；其文档和
报告只作为私有依赖，不能自动变为原件或其他字段许可。

三个可比较的选择维度保持明确：完整文档/原件范围、临床报告/字段范围、明确云来源范围。
若同时给报告/字段细选，来源必须属于所选报告，字段不授予云来源许可；资料级未归属来源
不能被细选报告间接带入。显式来源与这些限制冲突时返回可解释的范围错误，不静默忽略
选择或借此自动加入整份报告。来源独立选择且未提交临床细选时不强制附带普通报告数据。

新增独立 `cloud_imaging_sources` 和 `cloud_imaging_evidence` 数组，不改名或覆盖临床、日常、
治疗派生及届时实际 main 的其他数组。来源行关联 source/revision、document/page/report、
状态、必要说明和明确选中的 URL；证据只含该来源的证明，不输出其他候选、历史地址或
整页文字。二维码来源只带原页区域、解码器身份及结果类型，不伪造 OCR 偏移。

速查卡、PDF、JSON、CSV、ZIP 的普通章节不自动附带外部 URL；只有云来源明确勾选时才
显示目标站点及所选当前地址。选择控件说明下载中可能包含访问参数。完整原件另按现有
显式范围处理。CSV 沿用公式防御，JSON 保留原字符串语义，PDF/HTML 自动转义可显示文本。

限时分享快照只包含选中来源的安全站点摘要、当前修订、来源类型和必要页/报告身份，不
包含原始 URL、二维码载荷、作者账号或历史。分享打开服务从真实绑定读取当前受控目标，
只在明确主动打开时返回该目标。普通临床数组和原文上下文中的链接旁路继续默认省略。

## 8. 三个 PR 与验收门槛

| PR | 可用结果 | 此时必须完成的边界 |
| --- | --- | --- |
| 1：来源与核对 | 原件明文/二维码扫描、资料/报告归属、原页核对、人工补录与修订可用 | 真实证据、并发权限/worker、完整历史、默认 URL/二维码不进入通用投影；暂无对外打开和显式输出控件 |

| 3：选定输出与分享 | 单独及混合 PDF/JSON/CSV/ZIP、限时来源访问可用 | 默认空选择、细选闭合、普通原件隔离、全阶段失效、旧格式/所有旧数组兼容 |

每个 PR 均从届时最新 `origin/main` 建独立功能分支；后续 PR 等其必要前置实际合入。

验收必须包含真实本地二维码解码的合成图像/PDF、实际原页几何反查、同页多报告和重复码、
坏码/非 HTTP/危险地址、人工补录、撤销与过期预览。浏览器用合成站点拦截验证最终目标、
无 Referer/opener、无自动访问和移动宽度，不请求真实医院地址。PostgreSQL 使用独立测试库
验证扫描发布/权限撤回、原件或报告变化、作者清理、双重决定、混合输出和流式期间变化。

若验证已有授权的真实本地原件，先冻结页范围和原件身份，独立判断二维码/明文是否存在及
可判断性，再运行本地识别。公开仅匿名总数、覆盖和哈希；不输出真实地址、访问码、二维码
图像、医疗原文或本地路径。功能通过、解码覆盖、来源归属质量和第三方可访问性分别报告；
无真实目标或不可判断项不能由合成通过替代。
