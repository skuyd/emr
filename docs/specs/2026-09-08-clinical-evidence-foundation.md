# 结构化临床证据基础与首批影像字段

本规格落实[后续第 1—5 批需求](2026-09-07-batches-one-five-requirements.md)的 B3-01
共享证据基础，以及 B3-02 的首批影像字段。当前实现使一份有明确边界的影像报告从 OCR
形成逐字段候选，经过原件核对后进入详情、搜索、速查及可携带导出。
状态由[登记表](../document-registry.json)管理；本次不代表整个 B3 已完成。

## 首次交付范围

| 字段键 | 类型与保留信息 |
| --- | --- |
| `report.exam_date` | 日期及实际精度；检查日期不替换为报告或比较日期 |
| `imaging.modality` | 原文方法及受支持的代码，不构成诊断 |
| `imaging.body_site` | 原文检查部位，保留复合检查范围 |
| `lesion.site` | 报告内局灶异常或明确组的位置原文 |
| `lesion.laterality` | 明示的左、右、双侧、正中；没有原词时不由分段编号猜测 |
| `lesion.dimensions` | 一至三维有序数值、原单位、明示测量轴、约数及当前/历史/未知时间角色 |
| `imaging.impression` | 完整结论候选；没有足够来源时保留缺失 |

SUV、跨报告稳定病灶关联、病灶趋势、对比检查关联、云影像，以及病理、分子和基因字段
由后续 PR 实现。报告内 `lesion:…` 的 `entity_key` 不是患者长期病灶 ID，不能据此跨检查
自动合并。病理和基因将扩展字段注册表、值校验和提取器，复用当前报告、字段和修订契约。

## 持久化与来源

`ClinicalReport` 保存原件、解析版本、来源指纹、生命周期修订、报告边界版本、模式版本
和报告序号。边界原记录不可变；人工范围调整建立新报告，并以 `ClinicalReportRevision`
连接旧报告的替换事件和每条字段修订。

`ClinicalReportSpan` 保存页、OCR 块和半开区间 `[start_offset, end_offset)`。偏移绑定
数据库内原始 Unicode 串；NFKC 和空白整理只用于匹配，并通过字符映射回到原串。布局
关联使用变换后的几何，字段来源仍保存原件坐标；不把关联坐标写成原件定位。

逐字段复用 `Fact` 和 `FactRevision`，以 `representation=FIELD` 与旧摘录 `EXCERPT`
区分。字段保存 `clinical_report`、`field_key`、`entity_key`、`schema_version`，
不可变 `automatic_content` 同时包含类型化 `value`、`raw_value`、显示文字和明确的
变换记录。`FactSourceFragment` 保存每一处原文、原始偏移、证据及坐标；模型校验同一
原件、页、版本、证据块和报告范围。人工补录记录实际作者、所选原件页和核对原文，
不得伪造 OCR 块、字符偏移或坐标。

无 OCR 时可按显式页范围人工建立报告。它仍绑定原件生命周期和当时的解析状态；首次
OCR、解析启用变化、删除或恢复均会使既有确认需要重新核对。

## 多报告边界与候选生成

自动分段要求明确报告标题；同页并列报告使用几何栏位分离。拆开的标题片段可在同一
物理行恢复识别，来源仍分别保留。历史叙述中提到报告标题不产生独立报告。跨页合并
要求明确续页、相同检查号和相邻页，缺乏锚点的页不推定归属。

照片边缘的邻页窄条不能仅按横向顺序拼入正文。同页同时有明确的所见和结论标签时，
完全位于两个标签左侧、触及图像边缘且没有独立报告标题的窄列保留为未归属文字。
这不是固定比例裁边；缺少锚点、未贴图边或跨入正文范围的文字仍保留。原 OCR 不删除，
报告记为范围受限，报告和字段核对页提示查看完整原件，必要时人工重划范围或补录。

混合原件中的病历、检验页和没有可证明边界的页保留在未分段数量和限制中，不从评测
清单删去。`ClinicalExtraction` 单独记录提取状态、版本、报告和字段数、未分段页数及
限制；临床提取失败保留原件和既有检验/摘录，不宣称结构化完成。

字段提取仅引用边界内明确文字。正常器官或管径、否定病灶、影像叠字及上下文不明的
尺寸不替代局灶异常测量。自动候选均需人工对照原件；尺寸保留原数值和单位，不自动
进行疗效评价或诊断。

## 核对与失效

字段支持确认、更正、暂缓、排除、撤回确认和撤销上次操作；补录建立单独候选，仍需
核对。确认与更正必须声明已经对照原件，提交当前修订号和来源身份。更正只改变当前
有效内容，自动候选、原文、变换原因和既有修订保留。

来源身份包括原件、生命周期、活动解析的 ID 与启用时刻、报告边界和 OCR 来源。重新
解析、切回旧版本、删除恢复不能自动复活旧确认；撤销也不能恢复旧来源的确认状态。
父报告整体排除为每条字段追加修订并立即使导出失效。撤销整体操作要求字段集合及
每个最新修订均与该操作一致；有后续单字段核对或补录时拒绝覆盖。

人工替换边界后，新范围候选全部重新核对。撤销替换须确认新报告未发生核对、补录或
范围修改，并为新报告及其全部字段保留排除审计。已确认的同一字段存在不同值时，
详情、速查和导出均保留多条并标出冲突，不用字典键覆盖其中一条。

## 读写接口与权限

所有 HTTP 入口传入实际 `request.user`，按统一
`authorize_patient(patient, actor, capability, lock=…)` 授权。服务写入使用事务，锁序
遵循 Patient → UploadBatch → Document → 领域记录；来源与修订冲突返回可刷新重试的
冲突响应。查看者没有写权限，跨患者、已撤销成员和删除原件均不得继续访问。

| 接口 | 用途 |
| --- | --- |
| `facts:reports`，`/facts/documents/<document_id>/reports/` | 列出当前/历史报告，按活动版本请求提取，按显式页范围建立人工报告 |
| `facts:report`，`/facts/reports/<report_id>/` | 逐字段、原文与范围修订详情；排除、撤销、人工替换范围及补录 |
| `facts:detail`，`/facts/<fact_id>/` | 类型化字段核对、原件查看及完整字段修订历史 |
| `review_reports(patient, actor=…)` | 患者范围的当前报告读模型，保留冲突列表 |
| `request_clinical_extraction(…, expected_version=…)` | 对活动 OCR 版本幂等提取；仅失败运行可重试 |
| `create_manual_report(…, spans, expected_lifecycle_revision, expected_version_id)` | 实际作者和显式来源范围 |
| `add_manual_clinical_field(…, expected_report_source)` | 受类型校验的人工字段候选 |
| `replace_report_boundary` / `revise_report` | 父报告与逐字段一致的范围审计 |
| `revise_fact(…, actor, expected_revision, expected_source)` | 当前来源下的逐字段核对 |

GET 的无显式患者范围只按审核过的固定资源映射定位，再实时授权；POST 不按资源回推
患者。原件继续使用 Document 查看器接口；响应生成后复查访问资格，防止渲染期间撤权
仍返回内容。搜索包含当前有效字段内容，不用已更正的旧值替代当前结果。

## 导出兼容与共享契约

`build_snapshot` / `assert_snapshot_current` 保持原签名。全部报告、字段来源和修订进入
共同材料指纹；字段、报告、版本或生命周期变化令旧快照及生成任务失效。生成期间
发生变更时，发布前再次核验，不能留下可下载的旧制品。

JSON 模式由 `1.0` 扩展至 `1.1`，保留旧键并增加：

- `clinical_reports`：报告身份、原件/版本关联、边界、状态和修订。
- `clinical_fields`：Fact UUID、`report_id`、字段和实体键、类型化内容、状态、修订及冲突。
- `clinical_field_sources`：独立来源 ID、`fact_id`、`report_id`、原件/页/证据和原始片段。

CSV 增加三个同名关系表，旧 `facts.csv` 列保持不变。ZIP 同时携带 JSON、CSV 和用户
选择的其他部分。`read_structured_data` 可读取 `1.0` JSON，并将新增数组补为空；它是
格式读取兼容层，不是将导出重新导入数据库的功能。

可按 `report_ids` 和 `clinical_field_ids`（Fact UUID）进一步选择已经核对的字段。
存在报告或字段细选时，旧摘录和检验默认不附带，只纳入另外明确选择的 `fact_ids`
和 `observation_ids`；空值同样表示未选择。整份资料导出保留原有全量默认行为。
速查只使用可用确认，冲突值同时显示。

字段细选的 `content` 只投影类型化有效值、显示文字和限制，并以
`source_context_omitted=true` 说明不含完整核对上下文；完整 `raw_value` 和变换审计留在
授权核对页或用户明确选择的整份报告导出中。字段来源保留身份、页和原件坐标，整句
`raw_text` 留空、原上下文的字符区间留空、父报告 `spans` 留空，不把同句其他字段正文
带出。报告/字段选择不会裁剪完整 PDF 或图片；选择完整原件时界面明确提示其仍包含
整份文件，制品保持原字节与原始校验和。

分享层必须在授权后再次按资料、报告、字段及显示章节投影。字段 `category=IMAGING`
映射影像章节；`routing_kind` 仅为报告路由。安全显示使用自动转义的
`clinical_fields[].content.text`；精细分享不得直接呈现完整报告 spans、原文上下文或
原件 URL，不能把选中一字段等同于整份原件授权。

分享表单明确提交 `report_ids` 或 `clinical_field_ids`，选择项只来自实际操作者有权读取的
可用确认。后台仍校验它们属于所选原件和报告，不能把无效、撤销或跨患者的字段选择
退回整份资料分享。报告细选同样移除 `raw_value`、变换原片段和未选正文；完整上下文
仍可在档案核对页查看。字段撤销、父报告排除、解析切换或报告范围变化后，旧分享
资格失效并清除快照。精细分享不能选择完整原件来源或下载。

`ClinicalReport` 使用独立审计资源类型 `clinical_report`，以报告的真实原件关联定位
患者；访问定位不赋予权限。报告读取、提取请求、人工报告/字段补录和报告修订记录
实际操作者及真实患者，审计只保存动作、身份哈希和结果，不写入医疗正文。

## 验收及评测口径

自动字段和原摘录分别评分：新 `FIELD` 评测不改旧 `EXCERPT` 金标准、分母、错配或
未判断范围。影像固定范围为先看原件、后冻结标注的 8 文件、8 报告、35 个报告内实体，
105 个明确字段和 32 个原文未提供字段；缺失、失败、未分段和额外候选全部保留。
精确匹配要求字段值、报告边界和原始来源，不通过跨病灶交换预测取较好分数。

逐字段来源校核使用冻结标注中既有的精确定位或完整原文依据，不能用同页的有效来源
标记代替，也不能借另一条位置字段证明尺寸来源。位置原词、尺寸完整原文及必要历史
上下文必须在该字段自身证据中；不能证明时单列 `source_unverified`，它属于严格错配
的子集，不另加分母，也不表示该医学值已经判错。`value_correct`、`value_mismatched`
同时保留用于区分值匹配和来源证明。没有精确机器定位的原件标注保持原状，不为了
预测补造坐标。评分规则修订必须保留旧报告，用同一规则对初始和最终留存预测重算。

合成验收覆盖拆标题/并列报告/续页/混合资料、原始 Unicode 偏移、日期精度、尺寸轴和
时间角色、核对全部动作、父子修订冲突、解析与删除失效、实际作者、跨患者和撤权、
原件几何、搜索速查导出及旧格式读取。真实结果和人工检查代价由独立验证记录保留，
开发集成绩不作为外部泛化准确率。
