## 一、背景、目标与范围

当前系统能够拦截完全相同的文件，并对相似图片提供提示；检验对比表按文件、日期和医院分列。同一份报告的重拍图片、分段截图或续页可能形成多个独立来源，导致重复指标和重复列。

本次优化建立从上传校验、报告身份判断、结果展示去重到趋势与输出的一致规则，同时保留原始证据。

成功标准：

1. 相同文件继续沿用现有拦截规则。
2. 不同图片只有在证据充分时才自动归并为同一报告。
3. 有效检验报告必须具备采样日期和时分。
4. 对比表按采样日期和医院合列，指标按行。
5. 同列内同一指标、相同结果和单位只显示一条，即使来自不同报告或不同采样时刻。
6. 独有指标、不同结果、冲突和来源不丢失。
7. 趋势主图显示当日同院最后一次采样结果，其他结果可查看。
8. 报告归并可撤销；原图及来源可追溯。

适用范围包括新上传和历史检验资料，以及检验对比表、报告详情、趋势、导出和分享。

采样时间有效性规则仅适用于检验报告。影像、病理、处方等资料继续沿用原有规则。本期不增加医学推断，不根据结果数值猜测指标名称或采样时间。

## 二、核心定义与业务规则

### 2.1 三类操作分别处理

| 操作 | 含义 | 数据影响 |
| --- | --- | --- |
| 文件去重 | 判断文件内容是否完全相同 | 沿用现有拦截，不创建重复原件 |
| 报告归并 | 判断不同图片是否属于同一份检验报告 | 建立可撤销的报告关联，保留全部已接纳原图 |
| 展示折叠 | 将符合条件的相同结果显示为一条 | 不删除来源结果，不减少真实报告或采样次数 |

展示折叠不能作为“属于同一报告”的证据。报告归并被撤销后，只要结果仍满足展示折叠条件，表格中仍可显示为一条，但来源应恢复为各自独立报告。

### 2.2 上传有效性

**UP-01：完全相同文件。**\
继续按当前患者范围内的 SHA-256 规则拦截，提示已存在并允许查看原资料。不得跨患者共享去重结果。

**UP-02：完整采样时间。**\
检验报告必须具备有原件依据的采样日期和时分。仅有日期不满足要求；上传时间、报告时间、打印时间、文件名时间均不得替代采样时间。原件提供秒时保留原精度，不人为补充缺失精度。

**UP-03：缺失时间拒收。**\
无法获得完整采样时间的新增检验报告视为无效：

- 明确提示缺失的是日期、时分，还是未能可靠识别。
- 不进入正式档案、有效结果、趋势、导出或分享。
- 只允许进行完成有效性判断所需的临时识别，不继续正式解析和指标处理。
- 清除该次上传的临时原图、识别内容和提取结果；清理失败时隔离并重试，不得因此进入正式资料。
- 可保留不含原图、识别正文和医疗结果的必要操作状态及拒收原因码。

提示应表述为“未能识别到完整采样时间”，不能未经确认就断言原件没有时间。用户可重新上传包含完整表头的清晰图片，本期不提供脱离原件的手填时间接纳。

**UP-04：续页与截图。**\
图片本身没有时间，但同批图片中存在完整时间时，只有通过可靠报告号、医院和页间关联证据确认属于同一报告，且不存在日期、时间或结果冲突，才允许关联取得时间。

不得因为同批上传、图片相邻、版式相似或指标重叠而借用其他图片的时间。批量判断应等待相关图片完成校验，避免先到的续页被提前拒收。

**UP-05：缺失与冲突区别处理。**\
完整时间存在但有识别冲突的资料保留为待核对，不按缺失时间直接清除。有争议的归属或结果不得自动归并，也不得进入主趋势线。

**UP-06：批量部分成功。**\
每个可辨识报告单元分别判断。某一报告拒收不影响其他有效报告；但有效报告的时间不得用于救济无法证明关联的其他图片。

同一张图片或同一 PDF 页面同时包含有效和无效报告时，按用户实施阶段确认：保留承载有效报告的共享原图；无效报告单元不做正式提取、不进入结果，并明确提示。原图仍按原有权限控制。全部报告单元均拒收的上传继续执行 UP-03 的临时原图与识别内容清理。

同一个 PDF 的不同页面分别承载有效和无效报告时，同样保留完整原 PDF，不删除或重组页面；无效报告不做正式提取、不进入结果，并逐项提示。此规则由用户在实施阶段明确确认。

### 2.3 报告身份与归并

**MG-01：自动归并条件。**\
自动归并必须同时满足：

- 属于同一患者。
- 报告号及检测医院具有可靠来源依据并一致。
- 采样日期一致，已识别的采样时刻相容。
- 不存在报告身份、患者归属或指标识别冲突。
- 重叠结果不存在数值、单位、结果类型等冲突。

符合 UP-04 的续页或截图可使用有证据的报告级时间关联。

**MG-02：不得单独作为归并依据。**\
同日同院、相同结果、图片相似、相同文件名、上传顺序、相近上传时间均不足以自动归并。报告号缺失时，不自动认定为同一报告。

**MG-03：证据不足。**\
已具备完整采样时间但身份依据不足的报告独立保留。存在疑似关联时提示核对，允许用户对照原图确认“同一报告”或“不同报告”；人工决定应记录依据。

**MG-04：冲突处理。**\
报告号不同不得自动归并；报告号一致但时间、患者信息或重叠结果冲突时，保留全部来源并提示核对，不选取其中一份覆盖另一份。

**MG-05：归并内容。**\
归并后呈现报告包含的全部原图和有效指标。重叠结果按展示规则折叠，独有结果补齐。不得因归并删除图片、原始识别结果或人工修订历史。

**MG-06：撤销与重判。**\
用户可查看归并依据并撤销关联，恢复原报告关系。人工判定不同或撤销自动归并后，不得因相同证据再次立即自动归并；证据发生变化时重新提示核对。

### 2.4 结果折叠规则

**DD-01：折叠范围。**\
仅在同一患者、同一采样日期、同一医院、同一已确认指标内折叠。

同名但不同标本、计数与百分比、尚未确认映射的候选指标，不视为同一指标。

**DD-02：相同结果。**\
结果类型、结果值和单位必须一致：

- 数值只允许不改变含义的格式规范化，例如 `5.0` 与 `5.00`。
- 不设置近似误差范围，不因四舍五入后相同而折叠。
- `<5` 与 `5` 不同；不同比较符不同。
- 单位只允许已有明确等价写法规范化，不通过单位换算制造相同结果。
- 定性结果不通过未确认的同义词推断合并。
- 缺失或不可靠单位、指标身份不明确、结果识别冲突的记录不自动折叠。

**DD-03：跨报告、跨采样时刻。**\
满足条件时，即使报告不同或采样时刻不同，也只显示一条结果；展开后保留各次采样时间、报告和图片来源。

折叠不把多次真实检测变为一次检测，也不修改原始采样次数。

**DD-04：不同结果。**\
同一指标的不同结果分别保留，不取平均、不默认覆盖。不同采样时刻的变化不自动标成识别冲突；同一报告、同一次采样中的相互矛盾结果应提示核对。

**DD-05：参考信息差异。**\
数值和单位一致，但参考范围或高低标记不同，仍折叠数值，标注“参考信息有差异”。详情逐来源显示范围和标记，不给出统一高低结论。

**DD-06：指标误识别。**\
“前白蛋白误识别为白蛋白”等疑点单独列为指标身份待核对，不参与自动归并或结果折叠。核对界面同时展示原名称、标准指标、数值、单位及原图位置。

更正后重新计算归属与折叠关系。不得只因数值看起来合理就自动改名。

## 三、界面、趋势与输出要求

### 3.1 上传交互

上传状态应区分：

`上传中 → 有效性识别 → 已接纳／待核对／拒收`

接纳后再执行正式解析与报告关联判断。相同文件直接返回现有去重结果。

每张图片或报告单元显示明确结论，批量上传提供成功、待核对和拒收数量。相似图片提示、报告归并提示和无效报告提示不能混为同一种“重复”提示。

### 3.2 检验对比表

- 列按采样日期和医院组织，行按已确认指标组织，沿用现有指标分类和排序。
- 同日同院不同报告共用一列；同院不同日或同日不同院分别成列。
- 一个格内可有多条不同结果；相同结果显示一次，并提供来源数量和展开入口。
- 展开后可查看各次采样时间、报告号、来源图片、参考信息和核对状态。
- “查看报告”入口能够列出该列关联的所有报告，不再假设一列只有一个文件。
- 报告数、原图数和折叠后结果数分别计算，不混用。
- 医院缺失或归属冲突时显示待核对来源组，不把多个“医院未识别”当成同一家医院合列。
- 日期存在冲突时不强行归入某日，保留待核对入口。
- 展开与来源查看支持手机、键盘和触屏，不依赖鼠标悬停。

### 3.3 趋势

**TR-01：最新采样优先。**\
在同日同院的同一可比指标序列中，主图显示采样时间最晚的有效结果；更早结果保留在当日详情。不同医院及既有不可比序列不混为一条趋势。

**TR-02：折叠点。**\
相同结果折叠为一个展示结果，列出全部采样时间和来源。判断“最后一次”时使用该组真实来源中的最新采样时刻，而非上传时间或代表记录的创建时间。

**TR-03：不能可靠选最新。**\
时间识别冲突，或最新同一时刻存在不同结果时，该日显示待核对提示，争议结果不进入主趋势线，全部结果保留在详情。不得退回选择较早结果并将其标成最新。

**TR-04：计算边界。**\
趋势主图及其相邻点变化摘要使用同一组最新有效点，继续遵守既有单位、方法、标本和质量可比性要求。

展示折叠不提高数据可信度。原始采样次数、历史事实及其他既有统计不得因折叠减少；各统计应明确口径。

### 3.4 导出和分享

- 检验结果明细采用与对比表一致的合列、折叠和冲突规则。
- 不同结果全部保留；“仅显示最后一次”只适用于主趋势图，不删除明细中的早期结果。
- 相同结果附全部允许输出的采样时间和来源；静态文件通过明细或附表呈现，不能依赖交互展开。
- 参考信息差异、指标待核对、时间冲突均明确标注。
- 分享与选定导出必须先执行权限及选择范围过滤，再计算折叠、最新结果和来源数量。
- 不得通过折叠组带出未授权报告、图片、时间、结果或来源数量。
- 原图下载沿用已有授权规则；输出中的来源说明不自动授予原图访问权限。

## 四、数据、接口、历史资料与兼容要求

### 4.1 必要的数据与接口能力

新增或扩展下列能力，不以删除原始数据实现去重：

| 能力 | 最小要求 |
| --- | --- |
| 上传有效性结果 | 接纳、拒收、待核对状态；原因；涉及的上传项或报告单元 |
| 报告身份依据 | 报告号、医院、采样时间、精度、来源位置和核对状态 |
| 报告关联 | 关联图片或报告单元、自动或人工决定、依据、版本及撤销记录 |
| 折叠结果 | 指标身份、值、单位、全部来源、采样时间及参考差异 |
| 核对操作 | 查看依据、确认同报告、判定不同、更正字段、撤销归并 |

现有观察值来源和修订链应复用。报告级医院、采样时间及身份更正必须有原件依据并保留修订记录，不能只改展示标签。

上传接口保持现有文件级去重语义，增加明确的有效性结果；不能将拒收伪装成普通解析失败，也不能把待核对返回为已完成归并。

### 4.2 生命周期一致性

- 重试、重复请求或并发上传不得创建重复关联和重复核对决定。
- 人工核对及撤销应进行版本检查，旧页面不能覆盖更新的决定。
- 重新识别、切换解析版本或修订字段后重新计算有效视图，不覆盖原始证据和人工历史。
- 同一原件曾按原图人工核对完整采样时间，但后续重新识别未能识别完整时间时，按用户实施阶段确认：按本次识别排除该报告的有效结果，不使用旧人工时间恢复本次结果；保留原件、历史修订记录及原件核对入口。趋势、导出和分享同步排除该报告的当前结果。
- 新证据与已确认报告关系冲突时暂停自动归并并提示核对。
- 删除或撤销访问某个来源后，各视图和输出不再计入该来源；其他有效来源及其结果继续保留。
- 来源恢复后按当前规则重新计算，不机械恢复失效关系。
- 一个文件含多份报告时按有证据的报告单元处理，不把文件天然视为单一报告。

### 4.3 历史资料

新规则适用于历史检验资料，但不自动重跑全部原图识别。

- 利用已有有效证据重新生成合列和折叠视图。
- 缺少完整采样时间的历史报告保留原图、档案和历史记录，标记不满足接纳条件，不纳入有效结果、趋势、导出和分享。
- 有完整时间但存在冲突的历史资料进入待核对。
- 只有日期的旧字段不能直接升级为完整采样时间；其他日期类型不能冒充采样日期。
- 历史报告归并同样遵循严格证据规则，不通过批量迁移猜测报告关系。
- 历史资料可通过原图核对或后续明确触发的重新识别补齐依据，再恢复参与有效视图。

### 4.4 文档兼容

本规格调整[检验对比产品优化方案](2026-09-14-lab-comparison-optimization.md)中“同日同院不同报告保留独立列”的规则，并补充趋势、导出、分享和上传接纳约束；其他未冲突的质量、权限、来源与可比性规则继续有效。

这是部分需求调整，不将整份旧规格标为失效，也不改写旧功能的验证事实。新增行为已在独立功能分支完成本地验收。相关多指标比较依据见[多指标对照与个人变化设计](2026-09-08-personal-trend-comparison.md)。

## 五、验收与交付标准

### 5.1 功能验收矩阵

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 同一患者重复上传相同文件 | 沿用现有拦截，不新增原件或结果 |
| AC-02 | 不同患者上传相同文件 | 各自处理，不泄露对方资料存在性 |
| AC-03 | 同一报告重新拍摄，身份依据完整一致 | 自动归并，保留两张原图，相同结果折叠 |
| AC-04 | 同一报告截图部分重叠 | 重叠结果显示一次，独有指标全部补齐 |
| AC-05 | 无时间续页可严格关联同批主报告 | 接纳并标明时间来源；不受上传顺序影响 |
| AC-06 | 无时间截图无法证明属于其他报告 | 拒收并清理临时原图与识别结果 |
| AC-07 | 只有采样日期，没有时分 | 新资料拒收；历史资料保留但排除有效视图 |
| AC-08 | 只有报告时间或上传时间 | 不替代采样时间，按缺失处理 |
| AC-09 | 批量中既有有效报告又有无效报告 | 有效报告正常处理，无效报告独立拒收 |
| AC-10 | 同日同院不同报告，相同指标值和单位 | 一列、一条展示结果，全部来源保留 |
| AC-11 | 同日同院不同采样时刻，结果相同 | 折叠为一条，展开能看到全部采样时刻 |
| AC-12 | 同日同院不同采样时刻，结果不同 | 表格保留全部值，趋势主图选最后一次 |
| AC-13 | 最新同一采样时刻存在不同值 | 保留待核对，不任选一个进入主趋势线 |
| AC-14 | 完整采样时间存在识别冲突 | 保留待核对，不自动归并或确定最新 |
| AC-15 | 同值但单位不同，或 `<5` 与 `5` | 不折叠，不自动换算 |
| AC-16 | `5.0` 与 `5.00`，其他条件一致 | 可折叠，原始写法可追溯 |
| AC-17 | 同值同单位，参考范围或高低标记不同 | 数值折叠，差异提示可见，无统一高低结论 |
| AC-18 | 前白蛋白与白蛋白疑似混淆 | 独立标记核对，不自动折叠或改名 |
| AC-19 | 报告号缺失，但日期医院和结果相同 | 不自动归并报告；满足条件的结果仍可展示折叠 |
| AC-20 | 医院缺失、不同医院或不同采样日期 | 不错误合列，不借用邻近来源信息 |
| AC-21 | 撤销归并、修订时间或切换解析版本 | 关系与各视图同步更新，原图及修订历史不丢失 |
| AC-22 | 删除折叠组中的一个来源 | 来源数量更新，其余来源和结果继续可用 |
| AC-23 | 导出与分享折叠结果 | 结果、采样时间、参考差异和授权来源完整 |
| AC-24 | 分享只授权折叠组的部分来源 | 不输出或泄露未授权来源，包括计数和最新时间 |
| AC-25 | 并发上传、操作重试和旧页面提交 | 无重复关系，过期决定不能覆盖新决定 |
| AC-26 | 非检验资料没有采样时间 | 不受本次检验拒收规则影响 |

### 5.2 验证方法

1. 单元测试验证时间有效性、报告身份、指标身份、数值及单位相等规则。
2. 集成测试验证临时接收、拒收清理、批量关联、归并撤销、修订与权限过滤。
3. 浏览器测试验证上传提示、同日同院合列、多来源展开、冲突核对和移动端操作。
4. 使用有明确预期的重拍、重叠截图、不同报告及冲突样例，逐项核对原图数、来源数、独有指标和不同结果，证明没有丢失或误合并。
5. 检查趋势与导出分享的结果口径一致，并证明视觉折叠未减少原始采样事实。
6. 执行现有相关回归和文档治理校验。

没有具体误识别样例的原图及识别链路证据时，不声称已定位或修复该样例的识别根因。
