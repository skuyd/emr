# 肿瘤个人病案与病情轨迹系统 V1 系统设计

> 本设计落实《第一版产品需求文档-PRD-v1.0.md》。用户已授权由实现方完成技术决策，不再要求用户选择技术方案。

## 1. 目标与完成定义

交付一个可在桌面浏览器使用的单账号、单患者个人健康档案系统。用户能够通过手机号验证码登录，批量上传图片或 PDF，可靠保存原件，后台自动完成 OCR、文档分类、日期与机构识别、检验指标抽取，并通过病案列表、全文搜索、详情、原件定位和实验趋势重新找到资料。

V1 完成必须同时满足：

1. PRD AC-00 至 AC-22 均有自动化或可重复的人工验证证据；
2. 上传成功的原件均可重新打开；
3. 账号隔离测试不存在跨账号读取；
4. 解析失败不会删除或阻塞原件；
5. 删除操作覆盖业务数据、索引、缩略图和对象存储，并有可观测的后台删除状态；
6. 从工作区 `示例/` 中提取并人工可读地固化至少 125 个检验指标词条；
7. Chrome、Edge、Safari 支持范围内的核心流程可执行；
8. 产品不输出诊断、风险、疗效或处置建议。

## 2. 方案选择

### 2.1 采用方案：Python 模块化单体加独立后台任务

- Django 5.2 LTS 提供页面、会话、权限、管理后台、数据库迁移和 API；
- Celery 5.6 与 Redis 处理 OCR、解析、索引、通知和删除任务；
- PostgreSQL 18 保存业务数据，并使用 `pg_trgm` 与 GIN 索引实现本阶段搜索；
- S3 兼容私有对象存储保存原件、缩略图和解析中间产物；本地开发使用 MinIO；
- PaddleOCR 3.x 作为默认本地 OCR 适配器，保留合规云 OCR 适配接口；
- pypdf 负责 PDF 结构与安全检查，pypdfium2/PDFium 负责页面渲染、文本和坐标读取，Pillow/pillow-heif 处理图片与 HEIC；发布包同时保留 PDFium 的第三方许可证声明；
- 服务端渲染页面配合少量原生 JavaScript，PDF.js 负责 PDF 查看，ECharts 负责实验趋势。

该方案把账户、文件、解析和检索放在同一数据事务边界内，减少首版分布式一致性问题，同时让耗时解析独立扩容。

### 2.2 未采用方案

- Next.js 前端加 Python API：交互开发灵活，但首版需要维护两套类型、鉴权和部署链路；当前收益不足以抵消复杂度。
- 多微服务：独立扩展能力强，但会提前引入服务发现、跨服务事务和多套监控，不符合封闭试用阶段。

## 3. 仓库结构

```text
config/                 Django 配置、URL、Celery 与环境校验
apps/
  accounts/             手机号账号、验证码、会话、同意记录
  patients/             单患者空间和称呼
  documents/            上传、原件、页面、去重、状态机和删除
  processing/           OCR、分类、日期/机构识别、解析版本与证据
  labs/                 指标字典、字段抽取和实验趋势
  search/               搜索文档构建、查询、片段和索引维护
  notifications/        站内任务提醒与可选 Web Push
  feedback/             识别不准确和产品意见
  analytics/            去敏事件和运行指标
  operations/           配额、任务重跑、版本切换和安全审计
templates/              P00-P08 页面模板
static/                 样式、页面脚本、PDF.js、图表和图标
tests/                  跨模块、端到端、安全、性能与 PRD 验收测试
tools/sample_dictionary/ 样本提取、候选归并和字典生成工具
deploy/                 Docker、反向代理、备份和运行说明
```

每个 Django 应用只暴露 `services.py` 中的用例接口；视图不得直接修改其他应用的模型。后台任务调用相同服务接口，避免 Web 与 Worker 产生两套规则。

## 4. 运行架构

```text
浏览器
  -> HTTPS 反向代理
     -> Django Web/ASGI
        -> PostgreSQL
        -> 私有对象存储
        -> Redis -> Celery Worker -> OCR/解析器
        -> Web Push 服务（仅用户授权后）
```

对象下载不暴露永久地址。Django 每次校验账号与患者归属后，返回 5 分钟有效的签名地址；登出、注销或文档删除后不再签发。

## 5. 核心数据模型

所有主键使用 UUID，时间统一以 UTC 存储、按 Asia/Shanghai 展示。

- `Account`：手机号密文/哈希、状态、最后登录时间；
- `OtpChallenge`：用途、手机号哈希、验证码哈希、到期时间、失败次数和发送信息；
- `ConsentRecord`：同意类型、文本版本、时间、IP 摘要和撤回时间；
- `Patient`：账号、一条患者记录、称呼；数据库唯一约束保证一账号一患者；
- `UploadBatch`：批次、文件/页数/大小统计和汇总状态；
- `Document`：患者、原文件名、格式、大小、页数、SHA-256、感知哈希、文档类型、候选日期、机构、处理状态、上传时间和删除状态；
- `DocumentPage`：页码、图片/文本层对象键、宽高和方向；
- `ProcessingRun`：文档、解析版本、尝试次数、阶段、开始/结束时间、错误码和是否为当前生效版本；
- `OcrBlock`：页面、文本、坐标、多边形、OCR 置信度和顺序；
- `ExtractedField`：PRD 7.3 的全部字段、抽取置信度、映射置信度和生效版本；
- `LabDictionaryEntry`：本地稳定编码、标准中文名、类别、能力等级和字典版本；
- `LabAlias`：词条、原始别名、常见 OCR 错写、单位形式和来源样本；
- `SearchDocument`：文档级标准化检索文本和版本；
- `Notification`：站内通知、已读状态、不得包含医疗内容；
- `Feedback`：类型、文档/字段关联、可选说明，不复制完整 OCR；
- `AuditEvent`：访问、删除、重试、版本切换等安全事件，只存标识和动作；
- `DeletionJob`：删除范围、各存储层状态、尝试次数和完成时间；
- `AnalyticsEvent`：PRD 允许的去敏事件属性。

原件对象不可覆盖。新的 OCR 或解析写入新 `ProcessingRun`，事务成功后切换当前版本，旧版本保留到账号删除。

## 6. 登录与同意默认规则

- 仅接受中国大陆 `+86` 手机号；数据库不保存明文验证码；
- 验证码 6 位、5 分钟有效，同一挑战最多错误 5 次；
- 同一手机号 60 秒内不得重发，1 小时最多 5 次，24 小时最多 15 次；同一 IP 1 小时最多 30 次；
- 触发阈值后要求图形验证或暂时阻断；本地开发使用固定验证码 `123456`，生产环境启动时若仍启用固定验证码则拒绝启动；
- 会话闲置 24 小时过期，最长 7 天；登出立即销毁当前会话；注销销毁全部会话；
- 第一版不提供手机号换绑。原手机号不可用时由受限运营流程核验，不允许客服直接读取病案内容；
- 隐私政策、敏感个人信息和上传授权分别记录版本；任何必需文本升级后重新同意；
- 未完成三项同意不得创建患者或上传。

短信通过 `SmsProvider` 接口发送。本地使用控制台适配器，生产通过环境配置选择经过合规确认的供应商。

## 7. 上传、文件安全与去重

### 7.1 限额

- 每批最多 20 个文件、60 页；
- 图片每个不超过 20 MB，PDF 每个不超过 100 MB；
- JPEG/JPG、PNG、HEIC、PDF；
- 封闭试用默认每账号最多 300 份文档、1,000 页和 2 GiB 原件；达到任一配额后停止新增上传，仍允许查看、搜索和删除；
- 配额为数据库配置，调整不改变流程。

### 7.2 流程

1. 浏览器预检扩展名、大小和批次数；
2. 服务端创建待上传记录并签发分片上传信息；
3. 文件上传到隔离临时区；
4. 服务端重新识别 MIME、校验 PDF/图片可读性、页数、尺寸、文件头和恶意内容；
5. 计算 SHA-256；仅在当前患者范围判断“完全相同”，禁止通过跨账号去重结果泄露存在性；
6. 校验通过后原子移动到私有原件区并创建文档；此时才返回“资料已保存”；
7. 生成解析任务，浏览器可离开；
8. 相似度只在患者内通过感知哈希计算，命中只提示，不阻止上传。

加密 PDF、无法读取的 PDF、超大像素图片、扩展名与内容不符和恶意文件均作为上传失败，不创建病案文档。断点续传按文件分片恢复；浏览器无法恢复已失效的本地文件权限时明确要求重新选择该文件。

## 8. 状态机与后台处理

公开状态严格使用 PRD 状态。内部阶段为：

`QUEUED -> PREPARING -> OCR -> CLASSIFYING -> EXTRACTING -> INDEXING -> SUCCEEDED`

错误分为：

- `NO_STRUCTURED_RESULT`：OCR 或结构化内容不足，公开为“仅原件”；
- `RETRYABLE_ERROR`：供应商超时、网络或临时资源不足，公开为“处理失败”；
- `PERMANENT_PROCESSING_ERROR`：文件已安全保存但解析器无法处理，公开为“处理失败”。

自动重试最多 3 次，间隔 1、5、30 分钟；每次执行以文档 UUID、解析版本和任务类型组成幂等键。Worker 使用数据库行锁确认状态，重复消息不得生成重复字段。处理 15 分钟无心跳视为失联，由巡检任务重新排队。用户手工重试创建新的 `ProcessingRun`，不覆盖旧数据。

在数据库事务内完成字段、当前解析版本和搜索版本切换，保证详情和搜索不会读取半套结果。

## 9. OCR、文档识别与 125 项指标字典

### 9.1 文本获取

- PDF 优先提取可信文本层和字符坐标；文本层缺失、乱码或覆盖不足则逐页渲染后 OCR；
- 图片执行 EXIF 方向修正、版面方向检测和保守增强；原件不修改；
- OCR 保存文字、页码、坐标和置信度，供搜索与证据定位；
- OCR 适配器统一返回 `OcrPage`，本地 PaddleOCR 和将来的云供应商不得改变上层数据结构。

### 9.2 样本字典生成

`tools/sample_dictionary` 对 `示例/` 执行以下可重复流程：

1. 提取 PDF 文本层并 OCR 图片页；
2. 识别表格行中的项目名称、缩写、结果、单位和参考范围；
3. 生成带来源文件与页码的候选词条；
4. 使用 Unicode NFKC、空白、全半角和常见 OCR 错写规则归一化；
5. 合并同义词但保留全部原始名称；
6. 输出 `lab-indicators.v1.json`、人类可审阅的 Markdown 清单和样本覆盖报告；
7. 若唯一规范项少于 125，只能继续从样本中的其他检验报告提取，不得虚构医学词条；
8. 每个规范项使用本地编码 `PHR-LAB-0001` 起顺序编号，可选外部标准编码为空，避免错误声称 LOINC 映射。

字典发布内容固定版本和 SHA-256。重新解析记录字典版本，已有版本不被原地修改。

### 9.3 结构化准入

- 原始名称、结果关系必须由同表格行、明确键值对或可复核版面关系支持；
- OCR/关系综合置信度低于 0.80 时只保留 OCR；
- 标准名称映射置信度低于 0.90 时保留原始字段但不展示标准名；
- 趋势映射置信度必须不低于 0.95，并满足 PRD P07 的日期、单位、方法和数值条件；
- `未检出、阳性、阴性、溶血、拒收、未报告` 等保留原文和结果类型，不转成 0；
- 带 `<`、`>` 的结果保留比较符号，不进入趋势；
- 不根据参考范围生成严重度或医学提示。

## 10. 文档类型、日期和机构

- 类型限定为 PRD 7.1 的八类；分类不确定时优先 `UNKNOWN`，有可读内容但不匹配时为 `OTHER`；
- 日期保存全部候选、标签、来源页、精度和置信度；用户日期按 PRD 7.2 的优先级选取；冲突且最高候选差距不足 0.10 时显示“日期未识别”；
- 不完整日期只按原精度保存，不补造月或日；
- 机构保留原文，规范化名称仅作候选；V1 不做跨机构合并推断。

## 11. 搜索

每个文档生成一条去格式化、NFKC 归一化的 `SearchDocument`，内容包含 OCR、原始文件名、类型、机构、日期、指标原始/标准名称、原始值和单位。

- 默认每页 20 条，最大查询长度 100 个可见字符；
- 排序：完全匹配标准指标名，其次元数据完全匹配，其次指标/OCR 片段相似度，最后文档日期与上传时间；
- `pg_trgm` GIN 索引支持包含和错字相似搜索，短于 2 个字符只做安全前缀/包含查询；
- 所有查询首先限定 `patient_id`，数据库查询和对象访问都不得先取数据再在应用层过滤；
- 命中片段只截取原文前后字符并转义 HTML，不生成摘要或医学解释；
- 删除和解析版本切换在事务提交后触发索引更新；每日一致性任务可从源数据重建并比对索引。

## 12. 页面与视觉

采用现有“明晰”方案的固定左侧导航和任务效率，结合“暖笺”的低压力颜色与文案，形成温和但不幼态的专业界面。核心信息使用系统无衬线字体，页面标题可使用克制的中文衬线字体。

- P00-P08 均按 PRD 页面清单实现；
- 1280×720 起无横向滚动；窄于 1024px 显示电脑访问提示；
- 首页上传为唯一最高强调按钮；
- 详情默认左右双栏，字段点击定位 PDF 页码/图片区域；
- 状态同时使用文字、图标与颜色；
- 所有核心控件支持键盘，焦点可见，点击区域不小于 PRD 要求；
- 任何自动结果附近显示“自动识别结果可能不准确，请以原始报告为准”；
- 页面和通知不得出现 PRD 8.3 禁用文案。

## 13. 原件查看和证据定位

- PDF.js 查看 PDF，图片查看器支持缩放、拖动、旋转和全屏；
- `SourceEvidence` 以页面原始宽高下的归一化坐标保存，显示时按当前缩放换算；
- 有坐标时高亮，无坐标时只跳页；
- 前后端同时校验文档归属；文件对象键不进入页面源代码和日志；
- 返回详情页时用 History State 保存滚动位置；
- 不提供下载、分享和离线缓存；Service Worker 明确排除原件响应缓存。

## 14. 实验趋势

趋势查询只读取当前解析版本且满足：同一规范指标至少两条普通数值、日期精确到日、单位完全相同、方法相同，或同机构且无方法冲突。冲突组分开显示且不连线。

图表不计算变化率、不着色异常、不补点。每个点展示原始值、单位、日期、机构，并可返回来源。所有趋势页固定显示实验性声明。

## 15. 通知、反馈和埋点

- 站内通知默认开启；Web Push 仅在用户点击开关后请求权限；拒绝后不再次自动弹窗；
- 通知载荷只含任务 UUID 和通用文案，服务端点击后再鉴权取详情；
- “识别不准确”只记录文档、可选字段类别和当前解析版本，不要求正确答案；
- 埋点严格按 PRD 10.2 白名单，属性使用显式序列化器，未知字段拒绝写入；
- 搜索词、文件名、OCR、指标名值、手机号和患者称呼不得进入分析或错误日志。

## 16. 删除、保留和备份

- 单份删除二次确认后立即从业务查询、搜索和签名 URL 服务中不可见；
- 后台删除页面、OCR、字段、索引、缩略图和原件对象，正常目标 24 小时内完成；失败持续重试并进入运营告警；
- 账号注销立即禁用账号、撤销所有会话与 Push 订阅，并创建覆盖全部患者数据的删除任务；
- 安全审计事件删除直接身份关联，只保留不可逆账号摘要、动作、结果和法定必要期限；
- 加密备份每日生成、保留 30 天；删除对象可能在备份中保留至自然过期，恢复流程必须重放删除墓碑，避免恢复已删除资料；
- 活跃账号数据保留至用户删除或封闭试用结束后的明确通知期限；试用结束默认给予 30 天删除窗口，之后执行全量删除；
- 第一版不提供用户恢复。

## 17. 安全与内部运营

- HTTPS、Secure/HttpOnly/SameSite Cookie、CSRF、CSP、HSTS 和上传内容嗅探默认开启；
- 对象存储、数据库和备份使用平台加密，密钥与代码分离；
- 敏感配置只来自环境或密钥服务，启动时校验生产必需项；
- Django 管理后台只允许受限网络访问，管理员采用独立账号、最小权限和 TOTP；
- 管理员默认看不到原件与 OCR；必须通过带原因、限时授权的支持流程访问，并记录审计；
- 提供任务重跑、解析版本切换、字典发布、配额调整、删除状态和告警查看；
- 跨账号对象 ID、搜索、签名 URL、缓存和后台任务均有自动化越权测试；
- 外部 OCR 适配器必须显式配置“禁止训练、留存期限、处理地域”，未配置时生产环境拒绝启用。

## 18. 性能、可靠性和可观测性

验收环境固定为 4 vCPU/8 GiB Web、4 vCPU/16 GiB CPU Worker、PostgreSQL 4 vCPU/8 GiB、对象存储同地域；测试网络下行 50 Mbps、上行 20 Mbps、往返时延不高于 50 ms。

- 100 个同时在线账号、10 个并发上传批次下验证首页和病案首屏；
- 单患者 300 文档、每文档平均 3 页、每页 2,000 OCR 字符作为搜索基准；
- P95 指标采用 PRD 11.1；60 页批次至少一个文档在 5 分钟内产生结果；
- Web 服务月度可用性目标 99.5%；
- 数据库每日全量加持续日志备份，生产 RPO 15 分钟、RTO 4 小时；每月执行恢复演练；
- 指标包括上传成功率、队列长度、阶段耗时、重试率、原件打开失败、索引差异、删除积压和外部供应商错误；
- 告警不得携带医疗文本或文件名。

## 19. 测试策略

所有行为变更遵循测试先行：先写会因缺少行为而失败的测试，再写最小实现。

- 单元测试：字段解析、日期选择、状态机、配额、权限和禁用文案；
- 数据库集成测试：唯一约束、事务切换、索引隔离、删除级联和幂等任务；
- 文件契约测试：格式、超限、损坏、加密、重复和对象存储失败；
- 样本回归：对 `示例/` 生成固定清单、页数、候选指标和来源证据快照；
- 端到端测试：P00-P08、关闭标签后继续处理、搜索、定位、趋势、反馈和删除；
- 安全测试：两个账号穷举页面/API/对象访问，期望零泄露；
- 隐私测试：扫描日志、埋点、通知和缓存，不得出现样本医疗文本；
- 浏览器测试：Chrome、Edge、Safari 支持范围与 1280×720、1440×900；
- 性能测试：按第 18 节固定环境和数据集报告 P50/P95/P99；
- PRD 追踪矩阵：每项 MUST、AC-00 至 AC-22 和测试场景 1-26 都链接到测试或人工验证记录。

## 20. 交付顺序

1. 工程基础、环境校验、领域状态机和安全基线；
2. 手机号登录、同意和单患者建档；
3. 批量上传、原件存储、去重、配额和任务状态；
4. PDF/图片处理、OCR、样本字典和版本化解析；
5. 病案列表、搜索、详情、原件查看与证据定位；
6. 实验趋势、反馈、站内通知和 Web Push；
7. 单份删除、账号注销、运营后台、埋点和监控；
8. 全量验收、安全、性能、浏览器和封闭试用发布包。

每一阶段都必须产生可运行的纵向功能和测试证据，不以仅存在页面或空接口作为完成。

## 21. 规格自审

- 不存在占位内容或留给用户的技术选择；
- MUST、页面、状态、数据、隐私、性能和验收均有对应实现位置；
- SHOULD 中的相似提示、反馈、趋势和浏览器通知全部实现，不再利用裁剪条款跳过；
- 第一版明确不实现下载、分享、离线、多患者、诊断建议和删除恢复；
- 架构保持单体业务边界，只有耗时任务独立运行，不存在不必要的微服务拆分。
