# 健康趋势总览设计

日期：2026-09-02
状态：已确认，待实施

## 背景与目标

当前桌面端“健康趋势”和移动端“趋势”都跳到 `/records/`，而已有趋势详情只能通过 `/trends/<standard_code>/` 打开。一级导航因此没有独立目的地，用户会把它理解成配置错误。

本次新增患者范围内的健康趋势总览，让一级导航、总览和已有指标详情形成完整路径：

`健康趋势导航 -> /trends/ 总览 -> /trends/<standard_code>/ 详情 -> 来源原件`

## 页面与交互

- 新增 `GET /trends/`，页面标题和一级标题均使用“健康趋势”。
- 桌面端“健康趋势”和移动端“趋势”统一指向 `/trends/`。
- `/trends/` 与 `/trends/<standard_code>/` 均只高亮趋势导航；档案及资料详情继续只高亮健康档案。
- 总览只列出符合既有保守趋势规则的标准指标，不显示只有一个可比较点或完全不可比较的指标。
- 每张指标卡展示标准名称、最新一条可比较记录的原始值、原始单位（缺失时明确说明）、观察日期和可比较记录次数。
- 卡片的“查看趋势”进入既有指标详情。
- 指标详情的返回入口改为“返回趋势总览”。
- 无可用指标时显示：“暂时没有可生成趋势的指标”和“同一指标至少需要两个可比较记录”，并提供“查看健康档案”“上传新资料”两个入口。

## 数据规则

- 总览与详情必须复用同一套趋势资格与分组逻辑，不能出现总览可见但详情 404，或详情可见但总览缺失。
- 查询始终按当前认证账号的患者空间过滤，并排除已删除文档、非活动解析版本及既有规则判定为不可比较的数据。
- 同一标准代码只显示一张卡；最新记录按观察日期、记录创建时间和主键确定。
- 指标按最新观察日期倒序排列；同日以标准名称和标准代码稳定排序。
- “可比较记录次数”只统计实际进入合格趋势序列的数据点。
- 总览数据选择器使用一次候选观察查询，不按指标发起额外查询。
- 不新增数据库字段或迁移。

## 医疗与隐私边界

- 保留原始数值精度和原始单位，不做单位换算、不补点、不计算百分比变化。
- 不输出“改善”“恶化”“正常”“异常”等诊断、治疗或疗效判断。
- 所有页面继续使用私密、禁止缓存的敏感 HTML 响应保护。
- 不新增产品分析事件；已有 `trend_opened` 只在具体趋势详情打开时记录。

## 可访问性与响应式

- 页面只有一个 `h1`，指标使用语义化列表与卡片标题。
- 日期使用带 `datetime` 的 `time` 元素。
- 所有主要操作具备可见键盘焦点和至少 44px 触控高度。
- 390px、768px、1440px 下无页面级横向溢出；卡片在窄屏改为单列。
- 强制颜色模式仍保留边框和焦点可辨识性。

## 验收标准

1. 点击任一端的趋势导航都会进入 `/trends/`，不再进入健康档案。
2. 有合格趋势时只显示当前患者的合格指标，并能进入对应详情。
3. 无合格趋势时能理解形成趋势所需条件并继续查看档案或上传资料。
4. 总览和详情资格一致，原始值与单位保持不变，页面没有医疗判断。
5. 相关 Django、可访问性、导航和浏览器验证通过。
